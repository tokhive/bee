# Bee OpenAI 账号完整交付规格

Status: needs-info
日期：2026-11-09（Asia/Shanghai）

本文是完整交付的统一规格草案，不是实施授权。已确认的产品行为不重新讨论；剩余工程方案及参数集中在文末，关闭后才将整体验收票标为 ready-for-agent。发布到本地 Markdown 跟踪器，不创建远程 issue。

## 问题陈述（Problem Statement）

用户已经逐项确认账号页业务场景，并认可连续步骤与完成反馈的 HTML，但正式应用尚不能完整实现登录取链、安全重登、原操作结果核对及遗留状态恢复。零散接口、静态样本和页面确认被混用，难以判断真正完成了什么。目标是一次完成这些缺口，让每个必要动作有真实反馈、确定结果或安全可执行的下一步。

## 解决方案（Solution）

沿用已有准备保护、接单选择、普通登录和账号核验能力，补齐 Hive、Bee 原生层与正式 UI 的完整链路。用同一交付清单收敛，不把已有实现重新建设；最终每个已确认场景都有对应的真实行为和验收证据。纯样式调整不阻塞接口工作，业务操作、确认条件和结果变化才触发规格复核。

页面以最新已认可的主预览为依据，旧 draft 仅供对比。227 个预览入口对应 108 个业务索引，不是 227 个新功能；HTML 认可不等于接口或正式应用验收。

## 用户故事（User Stories）

1. 作为接入用户，我希望 Bee 识别本机官方账号，以便确认要使用的身份。
2. 作为首次用户，我希望确无历史接单选择时被告知准备完成后默认允许接单，以便理解接入影响。
3. 作为已有用户，我希望接入保留最新暂停／允许选择，以免被旧操作覆盖。
4. 作为用户，我希望历史选择查询失败被明确展示，以免被误当作首次使用。
5. 作为用户，我希望准备期间不接新任务、已有任务可继续完成，以便安全接入。
6. 作为用户，我希望准备失败后继续原流程，以免重复确认接入。
7. 作为用户，我希望 Bee 启动官方登录并提供本次有效链接，以便完成授权。
8. 作为用户，我希望打开浏览器失败后可再次打开同一登录，以免产生重复进程。
9. 作为用户，我希望未取得链接时有有限等待和安全恢复路径，以免一直卡住。
10. 作为用户，我希望真实登录完成后自动核验身份，以免把打开浏览器当成登录成功。
11. 作为用户，我希望核验失败能重新核验，以免无必要地重新登录。
12. 作为用户，我希望取消反馈准确区分受理、清理中和取消完成，以免误以为后台已停止。
13. 作为用户，我希望一次点击重新登录能够安全结束旧登录并启动新登录，以免手工串联操作。
14. 作为用户，我希望新登录启动边界的取消作用于当前登录，以免遗留进程。
15. 作为用户，我希望进度未知时仅查询原操作，以免重复登录。
16. 作为用户，我希望记录损坏或进程归属不明时仍有具体可执行的恢复说明，以免只看到永久禁用按钮。
17. 作为用户，我希望主动重新登录即使仍为原账号也保持暂停，以便自行恢复接单。
18. 作为用户，我希望只有成功读取到不同身份才提示换号，以免把 token 刷新或读取失败误当换号。
19. 作为用户，我希望核对新旧账号并明确确认后才更换，以免未经同意使用新账号。
20. 作为用户，我希望换号结果未知时保留原操作与目标信息，以免误报成功或重复更换。
21. 作为用户，我希望暂停／恢复结果丢失后能查清该次操作，以免只凭当前快照猜测。
22. 作为用户，我希望后来做出的接单选择不被迟到旧请求覆盖，以便保持控制权。
23. 作为用户，我希望额度耗尽期间仍能改变接单选择，以便额度恢复后按选择执行。
24. 作为用户，我希望正常刷新、重连和权限修复保留接单选择，以免被自动解除暂停。
25. 作为用户，我希望替换设备或丢失本地记录后能从 Bee 发起恢复，以免准备保护永久残留。
26. 作为用户，我希望涉及替换旧设备或失效旧操作时被告知影响并确认，以免无意中改变其他设备状态。
27. 作为用户，我希望凭证读取设置有保存／取消、保存失败保留输入，以便修复而不重复填写。
28. 作为用户，我希望保存后读取和核验确实成功才显示修复完成，以免把保存回执当成业务成功。
29. 作为用户，我希望步骤保留流程来源与已完成部分，以便失败重试后仍知道进展。
30. 作为用户，我希望成功反馈停留至点击完成，而完成不改变接单选择，以便看清结果。
31. 作为用户，我希望普通暂停、额度等待和重连没有多余步骤或祝贺页，以便聚焦当前状态。
32. 作为用户，我希望详情只补充真实证据、信息和设置，以免重复主页面。
33. 作为用户，我希望查询失败有限重试，长期等待有明确出口，以免无限转圈。
34. 作为验收者，我希望预览、受控测试和真实联调分别记录，以便判断哪些能力真正可用。

## 实施决策（Implementation Decisions）

### 沿用的技术与边界

沿用 React 19、TypeScript 7、Tauri 2／Rust、Go 1.27.3 及现有 Hive 服务与数据库事务机制。桌面工具链沿用 Node 24；具体依赖版本服从仓库锁定版本，不随本任务升级。沿用 Playwright、Go 标准测试与现有 Rust 原生集成设施。不引入新框架、消息队列、工作流引擎或进度平台。

本会话只在 bee-desktop-ui worktree 写规格。Hive 变更列为跨仓交付依赖；实际实施前定位并核实对应源码、测试和授权工作区，不因此授权修改 Hive 主工作区。既有其他会话修改保持不动。

### 已有能力复用

- 接入准备采用独立供给保护，不将用户选择先改成暂停再恢复。现有 Bee 实现有测试；Hive 配套交付记录仍须结合真实源码和部署核实。
- 复用普通启动、查询、取消登录及账号读取／核验入口。
- 保留既有原操作标识、账号版本、实例归属与严格跨层解码，不以页面阶段代替业务状态。
- 当前部分刷新入口会触发维护动作；原操作的只读结果核对必须验证其实际副作用，不能按名称认定安全。

### Hive 的目标流程

1. 对接单写操作提供可持久核对的操作身份与结果；重复同一操作不产生第二次副作用，异参数冲突明确拒绝。
2. 结果丢失后返回该次操作状态，而非仅返回当前 paused。新旧操作的排序和原子准入必须保证迟到旧写不能覆盖后来选择。
3. 查询准备保护返回真实归属和恢复所需证据。可由原设备继续时沿原操作恢复，不新建竞争保护。
4. 原设备已失效或原记录丢失时，先判断恢复资格；涉及替换／失效旧操作时由 Bee 告知影响并取得用户确认。
5. Hive 在同一受保护的事务边界核实权限、当前版本及恢复资格，并使旧归属不能继续影响恢复后的状态；不能先解除保护再核验。
6. 新 Bee 完成当前账号、授权、连接和同步核验，Hive 才结束保护，按用户最新接单选择决定是否派单。已有任务的处理遵守既有收尾规则。
7. 无法证明安全则保留保护并返回具体阻塞及可执行条件。不依赖保护超时自动释放，不默认要求管理员介入，也不建立通用接管平台。
8. 如果现有返回不能区分无历史与明确允许，增加最小判别信息；不建历史审计产品。查询失败不返回“无历史”。

具体恢复资格、旧归属失效证据和写入排序协议尚须技术核实，不能把以上要求直接解释为某种未经证明的接管算法。

### Bee 登录与恢复的目标流程

启动官方进程 → 同进程持续、有界读取并校验链接 → 安全打开 → 等待真实官方结果 → 核验身份 → 继续原接入／修复流程。

- 实现已定义的进度、安全打开、复合重新登录及其状态／取消能力，覆盖 Go、bridge、Rust 注册、生产 client、严格解码和 capability；旧客户端兼容按既有扩展约定处理。
- 链接绑定当前受管登录，不接受 UI 传入任意 URL／命令；取消、超时或失效后撤销链接。打开回执不代表授权成功。
- 重新登录先安全结束旧流程，确认停止且准入允许才启动新流程。停止失败和归属不明保留真实阻塞；重试不能靠删除记录绕过。
- 取消受理不等于清理完成。复合操作转入新登录的提交边界必须明确，随后取消准确路由到新登录。
- 原操作／进程记录缺失时，区分可重新取得证据和不可恢复记录丢失。前者核实后继续；后者给出真实可执行的隔离或清理路径，不能误杀外部进程或宣称已经安全。
- Hive 不能证明本机进程已退出；Bee 不能擅自解除 Hive 准备保护，两条恢复流程各自提供证据。
- 主动重登及确认换号保持暂停；普通刷新、重启、重连和读取修复保留最新选择。不同身份须另行明确确认，失败不等于换号。

### 查询、轮询与写操作

- 安全查询遇临时错误：首次后最多重试三次，共最多四次；成功立即结束本轮，权限／参数错误不重试。
- 查询成功但操作仍在进行属于轮询，另设有限等待上限。到上限不将业务改判失败，也不重新提交写操作。
- 自动核对运行期间不添加重复手动刷新；停止后显示原因和对应手动核对或安全恢复入口，继续指向原操作。
- 暂停写的有限重试只在明确未生效、且不可能覆盖后来意图时允许；恢复请求未知不能盲重放。修复条件不等于原请求成功，也不自动重放。
- 间隔、退避、各类等待上限和暂停写重试次数尚待确定；不能将查询的三次上限套用到写操作。

### 设置与正式 UI

- 读取设置明确保存／取消，定义真正的持久保存成功回执；保存失败保留输入，成功后自动读取并核验。打开设置不等于检测或修复。
- 沿用主预览的连续步骤：首次四步、直接接入两步、换号三步；重登／读取修复按实际路径追加准备。
- UI 保留当前流程来源和可信已完成阶段，失败只突出实际失败节点，重试不抹掉前序证据；数字圆圈保留数字，完成绿色、失败红色、当前突出、未来灰色。
- 仅显示可信阶段，无细分证据时只展示正在准备。不新增虚构百分比、倒计时或完整遥测系统。
- 成功反馈在原卡片保留至点击完成。完成只收起反馈，不发送接入、准备、换号或接单写请求；允许且条件满足时不等待点击才接单。
- 恢复接单不再作为成功流程最后一步；完成后普通暂停卡片提供恢复。额度与接单选择独立。
- 完成提示生命周期已确认：同一次 App 运行中，切到其他页面再返回仍保留尚未点击“完成”的成功提示；退出并重新打开 Bee 后直接展示真实当前状态，不恢复旧成功提示。期间出现新故障、账号变化或换号待确认时，立即展示新状态，不让旧成功提示覆盖。提示的保留或收起不改变账号、暂停／允许选择和额度。
- 普通暂停／恢复、额度等待、自动重连、状态更新与独立结果核对不增加完成祝贺页；RE-12 进度未知仍保留既定登录步骤。
- 主状态唯一，错误同因去重、独立条件保留；折叠内容只补充有效证据。详情页不复制完整步骤、接单按钮和额度区。
- 补齐 Q1 新恢复路径、查询重试耗尽及轮询到上限的预览页面和转换；不以当前 HTML 的“出口待补”页面作为最终交付。

## 测试决策（Testing Decisions）

以可观察行为和安全结果为断言，不按内部函数逐个镜像测试。优先复用最高的已有边界，不为了单一超大端到端测试改造系统。

- 主跨层边界：真实 Rust bridge → 生产 Go transport／服务 → 受控 Hive。沿用已有原生自动服务集成测试，补登录扩展而非声称旧测试已覆盖。
- 登录：沿用真实 authorizer 与受控 OS 子进程，验证迟到输出、输出分段、无链接、打开失败、超时、清理失败、取消竞态、重启和外部进程不受影响。
- Hive：用真实数据库事务测试结果丢失、同操作重放、异参冲突、旧写晚到、新选择优先、恢复资格失效、旧设备重连不能解除新保护。
- UI：正式 React 页面与受控原生响应验证流程、按钮、保存输入、旧结果丢弃、数字步骤、完成无业务写、暂停与额度不被完成改变。
- 时间：受控时钟验证四次查询上限、不可重试错误、轮询超时及停止后的入口；测试不能靠真实长时间睡眠。
- 真实联调：实际官方登录、实际桌面应用和配套 Hive 环境独立验收，部署与迁移兼容须核实；未经执行不得标为通过。生产部署需独立授权。
- HTML 认可、受控自动测试、真实业务验收分别记账；纯样式变化不阻塞接口正确性测试。

## 范围之外（Out of Scope）

Claude 或其他平台新功能、收益资金、新总接单开关、通用管理／接管平台、完整操作历史产品、全量进度遥测、框架升级、重写已实现接入保护。发布规格不修改正式代码、mock、HTML，不创建真实登录或业务写入，不合并或部署。
