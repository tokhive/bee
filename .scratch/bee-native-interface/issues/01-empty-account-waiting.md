# 01: 无账号时自动进入等待接入

**What to build:** 已配对且没有接入账号的 Bee 打开后，由原生生命周期自动准备并维护设备连接，用户在真实前端看到正常的“等待接入”及可用的登录、接入入口，无需点击“开始贡献”。等待接入不等于服务故障、可接单或已经接入账号；候选登录不会因此被自动选定。复用已有设备在线维护能力，先交付零账号这一条完整路径，账号接入后的自动维护、旧版停止意图迁移及完整退出流程分别由后续票据交付。

**Blocked by:** None (can start immediately).

**Status:** implemented

**Evidence:** [实施验证记录](../implementation-validation.md)。受控实现已可供 02 使用；真实前端经 Tauri/Go 到受控 Hive 的组合验收由 11 汇总，未声称生产 Hive 或真实官方登录验收。

- [ ] 在有效配对、可读的当前设备账号状态、零个已接入账号且没有未决操作的起点打开应用，原生生命周期自动进入可持续的等待接入流程；不再因“没有账号选择”报告启动失败。页面加载、切页、重复挂载或隐藏 WebView 均不是维持该流程的必要条件。
- [ ] 设备在线时仍不创建平台转发目标、不发布账号授权、不解除任何平台的暂停接单；本机发现候选登录也不自动接入或换号。未配对、设备身份被拒绝或绑定待恢复时保留原有明确处理入口，不自动配对或替换设备身份。
- [ ] 类型化公开快照足以区分服务准备中、正常等待接入、连接恢复中以及实际阻塞；真实前端使用当前事实展示对应状态和下一步，不将设备在线、管理进程就绪或命令受理等同于可接单，也不依赖 mock 专用标志伪造完成。
- [ ] 初始化受理与最终等待状态分开核对；重复初始化不会创建并行设备连接或后台工作。结果未知时保留原操作并核对其最终结果，不能由前端自动重放写操作；旧实例、旧绑定、旧修订或过期观测不能覆盖当前状态。
- [ ] 零账号不成为清空异常状态的理由：未决账号操作、不可读或损坏的持久化数据、无法证明已停止的旧会话及不明归属均保留证据并阻止相关自动动作。已有明确停止意图在迁移规则交付前不被覆盖，不据“等待接入”推导新的接单许可。
- [ ] 连接临时中断后按现有恢复约束继续等待，身份、权限或完整性错误则呈现本次具体阻塞及实际可用的处理入口；过期数据显示待核对。修复后能从原等待流程继续，不要求重新配对，也不把断线期间的旧成功状态当成当前事实。
- [ ] 等待阶段收到明确退出或后台所有者终止请求后，自有设备连接和工作能够被取消、等待结束并交付真实清理结果；迟到的初始化或连接回调不能在终止后重新启动工作，也不能清理其他实例留下且本实例无法证明归属的会话。
- [ ] 补充覆盖以上路径的原生行为、公开契约与前端连续验证：至少包含正常零账号打开、连接中断恢复、重复初始化、结果未知、旧结果晚到、未决或损坏状态及等待期间退出。记录真实前端经 Tauri／Go 到受控 Hive 的验证证据；mock 结果与真实原生链路结果分开报告，未连接真实 Hive 的验证不声称通过生产接单验收。
