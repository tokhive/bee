# 02: 接入账号后自动维护，平台保持暂停接单

**What to build:** 用户明确接入账号后，Bee 自动准备目标平台的授权维护和请求转发，并在账户页显示真实准备状态；准备完成仍保持暂停接单，由用户明确恢复。接入第二个平台时，已经运行的平台继续服务。

**Blocked by:** 01 — 无账号时自动进入等待接入。

**Status:** implemented

**Evidence:** [实施验证记录](../implementation-validation.md)。7 项原生受控行为和扩大 race 回归通过；正常入口切换及正式 WebView 组合验收仍由 11 完成。

- [ ] OpenAI 与 Claude 都能从候选核验、明确确认接入，连续进入自动准备；本机已有登录不会自动变成已接入。
- [ ] 确认操作明确目标身份、使用订阅额度和接单选择。暂停影响同一 Hive 用户的目标平台，不能描述成仅本窗口或仅此设备的开关。
- [ ] 接入后由原生生命周期启动目标平台维护，无需页面再发开始贡献；页面受理反馈、准备过程与最终可用事实分开呈现。
- [ ] 核验身份与来源后，本机转发先就绪，再发布当前连接的可用授权；授权发布与账号变化、连接代次切换的竞争由真实层验证，不能仅靠 UI 最终读回证明安全。
- [ ] 自动准备不解除暂停；用户明确恢复后，只在最新接单条件满足时显示可接单，其他独立阻碍继续可见。
- [ ] 接入第二个平台不会重启、覆盖或暂停另一平台；一个平台准备失败不抹掉另一平台的正常事实。
- [ ] 来源变化、旧修订、结果未知或重复点击不导致再次接入或覆盖新状态；未知写入核对原结果，失败保留输入及可执行的下一步。
- [ ] 公开快照与动作约束、跨语言严格解码、共享前端及 mock 一起同步；通过原生受控流程验证正常接入、准备失败、迟到回执和恢复后继续，分别记录模拟与真实结果。
