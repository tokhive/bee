# 03: 重启、重连与后台刷新保留接单选择

**What to build:** 用户重新打开 Bee、经历普通断线或同账号凭据后台刷新后，服务自动核验并恢复，平台沿用 Hive 当前确认的接单选择；服务恢复不替用户改变暂停接单的决定。

**Blocked by:** 02 — 接入账号后自动维护，平台保持暂停接单。

**Status:** implemented

**原生进度（2026-11-05）：** Go 实现及真实受控 HTTP／WS／转发时序测试已完成；详细证据见 [03／09 原生验证记录](../validation/03-09-native.md)。本票页面与跨层契约已整合，正式系统验收仍保留。

- [ ] 对已核验且具备可恢复证据的账号，正常重新打开或断线重连后自动准备服务；原暂停平台继续暂停，原允许平台仅在真实条件满足后可接单。
- [ ] 普通启动与重连不执行会覆盖用户意图的成对临时暂停／自动恢复；采用 Hive 当前确认状态，不能用旧本地快照覆盖其他设备或当前会话中的新选择。
- [ ] 同一账号的后台凭据刷新保持接单选择；发现不同身份只能进入账号变更待确认，不自动换号或解除暂停。
- [ ] 新连接重新核验来源、身份与授权，本机转发就绪后才发布该连接的可用授权，不复用旧连接授权证明。
- [ ] 恢复期间发生的最新明确暂停优先于旧恢复、后台同步或迟到回包；用真实时序测试证明不会重新开放新任务。
- [ ] 损坏状态、未决操作、归属冲突和不明旧进程阻止未经证明的恢复，页面给出对应状态及核对入口；不清空证据来制造成功。
- [ ] 页面离开或关窗不决定服务存活；实例、账号、绑定、网络及修订变化后，旧回执不能覆盖新状态，过期事实不呈现为可接单。
- [ ] 同步公开状态、Client 解码及 mock，并分别验证两平台不同暂停组合、断线重连、同身份刷新、响应丢失和最新暂停竞争；旧版停止意图的转换由 09 单独处理。
