# 04: 主动登录只维护目标平台

**What to build:** 用户从目标账号发起官方登录，无需先全局停止服务。Bee 在确认目标平台暂停后隔离其维护并完成登录，再核对真实来源；另一平台继续运行。原账号恢复维护后仍暂停，不同账号须明确确认换号。

**Blocked by:** 02 — 接入账号后自动维护，平台保持暂停接单。

**Status:** implemented

- [ ] OpenAI 与 Claude 均可从已运行状态发起受控官方登录；确认中说明同一 Hive 用户的目标平台将暂停、登录后需手动恢复，以及官方授权变化可能影响已有请求。
- [ ] 已参与供给的目标平台先得到 Hive 暂停确认，再停止其授权维护并关闭新转发入口，随后才启动登录；暂停或隔离结果未知时不越过前置，不重放写入。
- [ ] 未接入且没有既有供给的平台首次登录仅产生候选，不自动接入，不为首次登录修改无关平台状态。
- [ ] 登录期间禁止目标平台恢复接单及并行换号；另一平台的连接、维护、接单选择和反馈保持独立。已有流不主动切断，也不承诺排空或不受官方登录影响。
- [ ] 成功、失败、取消或超时后都重新核对真实来源；进程退出、取消回执或回到 App 的信号不能证明身份未变或登录成功。
- [ ] 同一已选身份且来源有效时恢复该平台维护，但保持暂停接单；不同身份进入明确换号确认，确认后仍暂停；来源不可读或身份未确认时保持不可接单并给出恢复入口。
- [ ] 恢复维护先准备本机转发，再发布当前连接授权；新暂停、来源修订和实例变更优先于迟到结果，旧登录不能覆盖新候选或另一平台事实。
- [ ] 同步操作阶段、平台范围、可用动作及失败证据的严格契约，并通过真实受控登录替身和前端连续流程验证成功、失败、取消、异号确认及结果未知；不将取消或失败后的可用状态重新标为登录成功。

## 本轮实施记录

平台登录隔离及 journal 持久化已实现；跨平台丢更新和完成证据落盘前解隔离已修复并有真实故障回归。完整证据与未验收边界见[实施验证](../implementation-validation.md)。本状态表示代码及受控验证完成，不表示上述真实环境验收清单全部通过。
