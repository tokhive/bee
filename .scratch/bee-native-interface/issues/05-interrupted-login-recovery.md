# 05: 登录中断后恢复原维护流程

**What to build:** 用户在主动登录期间退出 Bee 或遭遇崩溃后，下次打开能够看见并核对原维护过程。Bee 根据真实来源恢复维护或保留待确认状态，不重复登录、不自动换号，也不解除目标平台暂停。

**Blocked by:** 03 — 重启、重连与后台刷新保留接单选择；04 — 主动登录只维护目标平台。

**Status:** ready-for-agent

- [ ] 暂停确认、维护隔离、登录执行及来源核对各阶段的必要恢复证据可跨进程重启保留；不能只依赖页面内存或登录子进程仍存在。
- [ ] 重新打开先核对原过程和真实来源，不自动再次启动官方登录，不重放未确认的暂停或账号操作。
- [ ] 核验为原账号且来源有效时恢复对应维护，仍保持暂停接单；不同身份等待明确确认，来源不可读或归属不明则保持受阻并提供有效入口。
- [ ] 原操作结果与当前账号可用状态分开记录；一次只读核验不能将原失败、取消或未知登录改写成成功。
- [ ] 另一平台按自己的有效恢复证据继续运行；目标平台的未决维护不覆盖其成功结果，也不能借此跳过共享归属保护。
- [ ] 损坏记录、保存失败、旧实例回包或上下文变化不会清除未决证据、误认干净会话或解除暂停；失败显示本次环节、原因和可核对事实。
- [ ] 公开恢复阶段、操作归属、允许动作与严格解码贯通到列表及详情；在真实进程重启的受控测试中逐阶段中断，验证恢复完成、保留阻塞及用户继续操作，不用同会话 mock 重启代替持久化证据。
