# 09: 升级时保留旧版停止意图

**What to build:** 旧版明确停止贡献的用户升级后不会静默开始接单；兼容处理及中断恢复有可核对结果。用户仍能按平台明确选择恢复，旧版存储不能成为绕过归属、未决操作或暂停选择的理由。

**Blocked by:** 03 — 重启、重连与后台刷新保留接单选择。

**Status:** implemented

**原生进度（2026-11-05）：** Go v3 持久迁移、一次性暂停转换、unknown 只查询及 `Start([])` 继续核对已实现；真实进程 SIGKILL、HTTP 响应丢失、原子替换失败和保护边界已有验证。详细证据见 [03／09 原生验证记录](../validation/03-09-native.md)。Rust／TS／页面严格契约和受控集成已同步，正式系统验收仍保留。

## 已确认的兼容规则（2026-11-05）

用户已确认：旧版记录为 `running=false` 且存在已选账号时，统一先保持这些平台暂停，自动维护账号，等用户逐平台明确恢复接单。旧记录不能区分主动停止与从未启动，两类均按此规则处理。暂停作用于同一 Hive 用户的目标平台；只处理当前已核验身份的已选平台，不处理其他历史 scope 或未选择平台。

迁移仅执行一次，持久保留旧记录、进行中和已完成证据。Hive 暂停确认前不发布可用授权；未知写入只核对原结果。迁移不清理脏会话、未决账号操作或归属保护，也不能在后续启动重新暂停用户已经恢复的平台。03 的实现依赖已满足。

**外部前置：** 已解除，采用上述用户确认规则；03 的实现依赖仍保留。

- [ ] 先明确旧记录能够证明什么，覆盖从未启动、明确停止、正常退出与证据不足的情况；不能把所有非运行值都解释为允许接单。
- [ ] 在身份、选择、旧意图和必要远端结果得到核对前，不开放旧停止范围内的供给；若采用平台暂停转换，必须获得可信确认，不能仅保存本地意图就放行。
- [ ] 转换不新增另一个日常总开关，不自动接入候选或确认换号；平台暂停仍使用同一 Hive 用户的既有平台级语义。
- [ ] 转换结果未确认、网络中断或进程重启时保留原证据并继续核对原过程；不会重复覆盖后来作出的暂停／恢复选择。
- [ ] 损坏存储、无法证明归属或未决账号操作保持受阻，不删除保护标记、不假装已迁移或生成干净会话。
- [ ] 页面能区分兼容处理中、结果待确认、受阻及处理完成，给出对应动作；完成后仍由用户明确恢复需要恢复的平台。
- [x] 所选规则已由用户确认并记录，旧状态识别与转换前置已解除；implemented 不代表真实系统验收全部完成。
- [ ] 随后同步持久状态、公开契约、严格解码、前端及模拟数据，以真实旧状态样本和重启／写入中断测试完成本票验收。
