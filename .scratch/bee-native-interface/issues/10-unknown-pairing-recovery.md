# 10: 设备创建结果未知时提供恢复闭环

**What to build:** 配对创建已经尝试、但 Bee 未取得原配对凭据而进入 `creation_unknown` 时，用户能通过经过确认的人工或协议恢复步骤继续原设备连接／重新绑定流程。界面能够说明已知事实、外部处理所需信息和处理后的继续入口；Bee 核验恢复证据、设备身份及归属后才宣布完成，跨重启保留原事务及失败证据。当前仅有阻塞提示、控制台核对和诊断导出，不构成恢复闭环。

**Blocked by:** None (no ticket dependencies).

**Status:** needs-info

**外部前置：** Hive／人工恢复方式及其证据契约尚未明确。该前置解决前不能开始实现，不因没有其他票据依赖而视为可立即领取。

## 外部待决问题

- 原创建响应与配对 token 均不可得时，如何将本机保存的创建尝试唯一关联到 Hive 原事务；由谁提供关联证明，如何区分未创建、已创建、已批准、已兑换及已过期？现有 Hive 仅保存 token 摘要，不能直接查回原 token。
- 谁有权发起和确认恢复，Bee 如何核验其授权及其与当前 Hive、本机凭据和原事务的关系；归属改变时如何保留用户明确确认？
- 人工处理或协议处理具体允许什么动作、返回什么可验证证据；如何在不重放原创建／兑换、不采用任意 token、不删除原事务绕过保护的前提下继续？
- 什么事实足以证明恢复成功、原事务已终结或可以安全进入后续步骤；处理失败、结果未知、证据过期及跨重启时分别如何继续？
- 上述方式是否需要 Hive 新增协议、持久化字段或管理能力；若需要，由哪个上游工作交付并验证，再解除本票外部前置？本票不预选任何新上游协议。

## 验收标准

- [ ] 实现前记录并确认上述待决问题的答案、外部交付及可验证的成功条件；只有证据和授权契约明确后，才将本票改为 `ready-for-agent`。
- [ ] 创建响应丢失或原 token 保存失败后，公开状态和正式设备页面一致呈现创建结果未知，说明已确认的创建尝试与缺失事实，并给出实际可用的外部处理及返回继续入口；不把“已导出诊断”或“已联系管理员”显示为恢复完成。
- [ ] 原创建尝试、操作标识、Hive／绑定上下文和具体失败证据跨进程重启保持可核对；读取、刷新页面、外部处理后继续及重复点击都不会重放原创建或兑换请求。
- [ ] 只接受已确认恢复方式提供的有效证据；拒绝来源不明的 token、错误 Hive、无关原事务、无权确认及已失效证据，保留原记录和当前配置，并反馈具体受阻原因及可用下一步。
- [ ] 原事务尚未获得权威结论时持续保留未知状态；本机时间经过、查不到记录、网络失败或人工口头判断均不能单独证明远端未提交或已过期，不能据此开放重新创建。
- [ ] 有效恢复证据到达后，Bee 核验设备真实身份与归属，并继续必要的归属确认及本机保存；绑定上下文变化或旧结果晚到时拒绝覆盖当前配置，保存失败仍能从原事务继续。
- [ ] 完成状态只在所需远端事实、归属确认与本机保存均已核验后出现；重新绑定不继承旧设备的账号选择或运行意图，不因恢复操作开放平台接单。
- [ ] 以受控 Hive 证明创建响应丢失、token 保存失败、外部处理失败／未知／成功、错误证据、恢复期间重启及本机保存失败的连续路径，核对实际请求次数、原事务和绑定结果；另记录正式页面到真实 Hive／人工处理的恢复闭环证据，明确区分 mock、受控集成和真实验收。
