# 11: 接通真实入口并验收自动服务主流程

**What to build:** 将已经逐票打通的原生能力接到正常桌面入口，使用户可以在真实 App 中连续完成接入、自动维护、暂停恢复、主动登录、换号与重启。主流程以可追溯的真实证据验收，明确模拟、受控集成和真实系统的结论边界。

**Blocked by:** 03 — 重启、重连与后台刷新保留接单选择；05 — 登录中断后恢复原维护流程；07 — 应用网络配置后受控恢复服务；08 — 更新安装复用可靠退出流程；09 — 升级时保留旧版停止意图。

**Status:** ready-for-agent

- [ ] 依赖票已经分别完成各自纵向交付与验证，本票不以入口切换补齐未完成的核心行为；09 未明确并完成前不将自动服务直接开放给旧停止状态用户。
- [ ] 正常入口从真实原生状态决定等待、准备、运行和受阻，取消日常开始／停止贡献入口，保留服务问题的对应恢复动作；不用 mock 标志或前端定时器管理真实生命周期。
- [ ] 在同一真实会话连续完成已有配对设备的官方登录／候选核验、明确接入、自动准备、保持暂停、恢复接单及再次暂停；以 Hive 与实际受控请求证据证明接单效果。
- [ ] 双平台运行时验证目标平台主动重登、异号确认、失败／取消核对、来源修复及登录中断恢复，另一平台保持自己的事实与选择。
- [ ] 验证重连、正常重新打开、同身份后台刷新、旧停止状态升级，以及期间的新暂停；检查未决结果不会重复提交，旧回执不覆盖新状态。
- [ ] 验证关窗找回、明确退出、网络应用及退出安装，随后在有效恢复条件下保留平台选择；失败、结果未知及恢复后继续都有实际证据。
- [ ] 列表／详情共用当前事实，原因折叠与去重、读取来源定位、输入保留、键盘／焦点、中英文和窄窗在真实接口下仍有效；历史成功或过期报告不替代当前状态。
- [ ] 记录候选包、源码版本、Hive／官方客户端与系统环境，并分列契约／mock、Go／Rust 受控集成、真实 App／系统的通过与缺口；设备创建未知无 token 的完整恢复仍由 10 独立验收，不在本票中宣称通过。
