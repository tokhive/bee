# 接入准备期间的供给保护

普通首次接入、同账号重新接入期间，Hive 临时阻止该用户、该平台的新任务。准备完成只解除本次保护，始终保留最新的 `paused` 用户选择；无记录仍沿用 Hive 的 `false` 默认。本次不决定新的产品默认。主动重新登录、确认换号仍走原有明确暂停流程。

沿用 Go、net/http、PostgreSQL 和现有桌面状态文件，不新增依赖或 UI。验证边界为现有供给 HTTP 接口、真实 PostgreSQL 调度准入、Bee 接入与自动维护公开接口。

## 内部协议

复用 `GET/PUT /api/bee/platforms/{platform}`。普通 `paused` 请求和响应不变。准备请求为 `PUT {"preparation":{"id":"48位小写十六进制","action":"begin","account_fingerprint":"SHA256"}}`；完成使用同一 ID 和指纹、`action=complete`，另带当前 `lease`、`account_generation`、`credential_revision`。不得与 `paused` 混用。

只读核对使用 `GET ?preparation_id=<原ID>`，准备请求返回 `{preparation:{id,state},supply:{platform,paused,ready,reasons}}`；state 为 `absent/active/completed/cancelled`。查询不解除保护。普通供给投影在保护期间使用已有 `authorization_unavailable`，`paused` 始终只表达用户选择。

现有“清除本地选择”使用同 ID、指纹和 `action=cancel` 结束尚未注册账号的保护，不带同步回执。Hive 在事务内核对账号仍未注册、无待确认换号后才返回 `cancelled`；已注册账号只能完成同步，不能用取消绕过准备。完成、取消的 ID 均保留，迟到请求不能重新开启或解除下一轮保护。

例外衔接：用户明确确认换号时，既有 `/account/confirm` 在同一事务内确认 `paused=true`、结束旧准备记录并切换账号、使旧授权失效。此时保护由手动暂停继续承担；旧确认请求的重放不会结束后来新建的保护。

Hive 持久保存操作 ID、设备、平台、指纹和完成标记；同 ID 重放不重新开始，异参数冲突，一个用户/平台最多一个活动保护。开始/结束与最终调度准入锁住同一供给控制行；完成须核验当前连接、已上传授权和账号版本。没有超时自动解除。

Bee 在发送前保存操作 ID，接入选择保存后将 ID 一起持久化，由自动维护在完成来源、账号、连接及同步回执核对后结束保护。“选择已保存”不等于“准备完成”；来源失效时保存的选择仍可供恢复，但不会解除保护。停止同步 worker 不代表在途流已经结束，同账号重新选择期间保留既有转发能力，由 Hive 阻止新准入。

失败和响应丢失沿原 ID 查询/幂等重试；重启从原选择继续维护。每次新连接在上传授权前核对保护，上一轮已结束才持久化新 ID，未结束则恢复原 ID。同账号重新选择可沿用活动保护修正来源。旧版未决 `paused=true` 操作保持旧核对规则，不自动解释成临时保护。

尚未注册账号时，重新选择另一身份先按上述限制安全取消原保护，再建立新保护，保留原终态记录；已注册账号仍必须明确确认换号。

## 兼容与限制

先部署 Hive（含迁移 067），再部署 Bee。现有普通供给请求、前端 DTO 与 mock 无需更改；新 Bee 遇到不支持准备协议的旧 Hive 会保留未决操作并停止接入，不退回到无保护上传。旧状态缺少可选 `preparation_id` 时继续可读；旧 Bee 的严格状态读取器会拒绝含新字段的文件，降级不可直接删除该字段或未决记录。

网络、来源或同步失败时，恢复真实条件后由原操作继续核对；冲突须核对原设备、账号和版本，不能靠无限重试解决。保护不自动过期；原设备被替换或本地原始记录遗失时，本次没有新增跨设备接管/管理员解除接口，须保留 Hive 记录并诊断，不能用重启或删除状态绕过。首次无历史的产品默认仍待产品决策。

## 验证矩阵

- 原选择为接单/暂停、期间改为接单/暂停、无历史默认。
- 活动保护期间手动恢复不能绕过；只阻止新任务，已有流继续。
- 同 ID 并发、重复请求、参数冲突、迟到完成不得解除下一次保护。
- 错误设备/平台/用户、错误连接/账号/版本不能完成。
- Hive/Bee 重启、开始/完成响应丢失、准备失败后原 ID 恢复。

本文件记录已批准规则的实现边界；真实能力以代码和通过的验证为准，不以静态样本代替。
