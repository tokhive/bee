## 可复现的真实环境验收步骤（未执行）

前置：明确授权使用的 Hive 测试环境、OpenAI／Claude 测试账号和受控请求范围；优先使用独立系统测试用户和专用官方目录。记录 App／Bee 版本、OS、架构和两官方客户端版本，不将 token、授权 URL、邮箱或原始凭据写进报告。修改官方登录前获得账号使用者同意。

1. 首次打开：设备配对完成后，确认本机未运行、未自动检测官方来源。分别检测已有登录，检查候选来源与身份；确认接入后重新打开，应保留选择但不自行贡献。
2. 官方登录：在两个平台分别由 Bee 打开官方登录，实际完成官方页面；核验结果只成为候选。各做一次取消，确认本次子进程回收、已有外部官方客户端仍运行；核对自定义目录／默认存储的实际落点。
3. 贡献：明确选择允许恢复的平台并开始；记录真实 Hive 握手、账号／代次核对和可接单状态。按授权范围发送一个可识别的受控请求，证明经本 Bee 到达上游；一个平台故障时另一平台仍可工作。
4. 暂停与换号：暂停后确认 Hive 不接新单；修改官方来源为另一个获准测试账号，明确确认换号。核对代次和新身份，并确认成功后仍暂停；再次明确恢复才可接单。
5. 恢复与失败：断网再恢复；在测试设备上验证凭证撤销和重复连接占用不会自动抢占。普通退出后重新打开按原意图核验恢复，手动暂停保持；明确停止后重开保持停止，异常终止后不得自动贡献。
6. 退出保护：停止和退出时说明可能中断任务；核对本 App 的 worker／子进程已回收及配置锁释放，外部 Bee 仍存活。操作前后核对 CLI 配置及未授权来源未改变，公开诊断无秘密。

未具备前置环境时保留 T4 真实登录和 T8 真实闭环两个复选框，不自动使用个人账号补齐证据。Windows／Linux 及其余目标组合的原生官方来源和发布验证继续由 S3 汇总。
