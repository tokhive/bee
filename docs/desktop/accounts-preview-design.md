## 会话合并基线

用户已要求将[分叉会话 2](codex://threads/01a1a9aa-3c05-73b3-81db-6acb17d7b300)的新增结论合入[主会话 1](codex://threads/01a1a60a-62f8-7d71-a9b3-b4c0ebc93699)，后续在主会话继续。本节承接两边已确认的要求；合并不代表批准待评审的视觉或预览页实施，也不涉及 Git 合并。

- **账号呈现**：每账号只突出一条主状态；原因默认折叠，同因去重，独立条件保留。权限不足与手动暂停分别解除，修复权限不自动解除暂停。
- **按任务展示步骤**：首次接入和故障恢复中，有先后依赖才展示当前必要步骤；根据实际状态跳过或切换，完成后隐藏。可接单、单纯暂停、自动重连、额度等待和结果核对不常驻完整步骤条。步骤不替代业务状态机；可接单仍需当前可信事实证明。
- **当前动作易操作**：用户接受步骤数字可点击或旁边有对应按钮；自动阶段只展示进度，后续步骤不能跳过，接入与换号仍须确认。
- **换号与修复语义**：成功读取的可用候选身份与已接入身份不同，才属于发现不同账号；token 刷新、文件修改时间变化和读取失败本身不代表换号。保留原账号，明确确认后才更换。暂停和本机运行情况是当前事实，不能列为换号原因。“打开读取设置”只定位读取方式和目录，打开详情不等于检测、授权或修复完成。
- **自动运行目标**：Bee 运行时自动维护已明确接入的账号，不再要求用户手动开始／停止贡献。接入、主动重新登录和确认换号后保持暂停；正常重连、重启及同身份后台刷新保留接单选择。早期手动启停的步骤和截图仅为历史依据。产品目标与当前原生实现、mock 验证范围分别核对，不能互相替代。

以下为分叉当时的历史状态；后续三场景认可范围见本文末尾记录，其他旧候选不因此获得认可。分叉中的视觉结论须区分状态：用户已否定整块卡片式可点击步骤；`html-clickable-steps-*` 截图不是后续视觉基线。最新候选采用轻量水平步骤线和相邻独立操作按钮，去掉金色外框、大片底色与拥挤说明，**尚未获得用户视觉认可**。候选与历史记录见[账户页评审记录](evidence/2026-11-04-account-ui-review/README.md)、[当前 HTML](evidence/2026-11-04-account-ui-review/accounts-preview.html)和[完整 HTML 历史索引](evidence/2026-11-04-account-ui-review/history/README.md)；原型检查通过不等于正式 React 或真实业务验收通过。

## 已确认

- 先定预览页设计，再修改页面。
- 评审范围是 AI 账号页。
- 以 AI 账号完整场景列表作为评审入口，便于直接选择要看的页面状态。
- 三个验收项目不能替代完整场景列表。用户不应为了查看某个场景，先理解并组合外部事件参数。
- 场景入口沿用顶部下拉列表，按接入、接单、授权问题、变更与恢复分组。
- 选择场景后，页面按钮仍可操作；由页面操作触发的登录等结果由场景预设并演示，不要求用户配置外部事件。
- 正常场景和异常场景都在列表中。异常起点停留供评审；想看正常页面时，直接选择对应正常场景。不增加“演示恢复”按钮，也不按定时器自动离开所选异常场景。
- 切换场景加载该场景的预设起点；这用于比较页面状态，不等同于验证原场景的数据经过恢复流程。连续恢复中的暂停保留等规则另由自动化验证。
- 预览区保留场景下拉、外观、窗口尺寸、重置场景，以及一句“当前看什么、预期是什么”的说明。去掉长教程和验收进度；正式账户页面放在下方。Q5 示意图中的“演示恢复”按上述讨论移除。

## 三场景步骤预览（已认可，已纳入主预览）

用户确认：首次使用／接入、故障恢复等有先后依赖时，展示随事实调整的必要步骤；自动阶段只显示进度，完成后隐藏。可接单、普通暂停不常驻步骤。本轮不再讨论是否采用步骤展示。

[打开三场景候选](evidence/2026-11-04-account-ui-review/accounts-steps-prototype.html)，使用顶部场景列表比较：

- 首次接入：登录 → 确认接入 → 自动准备 → 恢复接单。
- 故障恢复：以授权过期且已暂停为例，重新登录 → 自动核验 → 手动恢复接单；原因默认折叠。
- 可接单：没有步骤条；暂停和恢复也不重新显示步骤。

已认可轻量步骤线与独立操作按钮的三场景呈现。官方登录结果在用户发起操作后由预设自动承接，页面不设置外部结果按钮。三场景用于比较呈现，未替代完整场景清单。验证范围为独立 HTML 原型；正式页面与真实登录不包含在本轮。完整留版见[历史索引](evidence/2026-11-04-account-ui-review/history/README.md)。


## 当前文本评审基线（2026-11-05）

本节是后续场景讨论与未来 HTML 更新的依据。每次用户确认后及时更新对应结论，不等全部讨论结束再补记；有变更则更新本节，避免把已被替代的说法继续当作方案。文本确认、HTML 更新与真实实现验证分别记录。

### 确认进度与执行边界

- 已确认文本流程：主动重新登录；发现不同账号并确认换号；读取权限不足（原先允许接单／原先暂停两种情况）；授权过期但未手动暂停接单。细节见下文。
- 已确认通用呈现：同一下拉按类别、流程、子场景组织；各可见状态及弹窗可直接选择并停留；操作时连续推进并同步标示当前位置；重置回到最后直接选择的起点。故障时只突出当前必要修复要素。规则正文见本 worktree 的 HTML 预览规范。
- 已认可主预览仍只有首次接入、授权过期且暂停后的恢复、可接单三个场景。draft 已有重新登录与换号的局部模拟，但尚未同步本轮确认的新文案、子场景入口和故障布局；不能将整份 draft 标为已认可。
- 授权过期但未手动暂停接单：用户已明确同意该场景文本呈现与流程，尚未同步 HTML。
- 后续参考场景：额度耗尽、断线自动重连、换号结果待核对、报告过期待核对。已有登录待接入、刚接入暂停、普通暂停可从已认可流程到达，独立入口仍待补齐。旧版 13 项与此前助手建议均不是全部已确认需求；登录失败、服务准备失败等仍只是待核对建议。
- 本阶段每轮只做一个场景的文本线框与简短流程，不修改 HTML、正式前端或 mock。全部讨论完成后先汇总结论，等用户明确要求再更新 HTML。真实登录读取、暂停生效、换号持久化与恢复条件尚未据此验收。

### 主动重新登录：流程已确认

指用户在 Bee 账号详情中主动点击“重新登录”，调用官方客户端登录；账号正常时也可以使用，返回身份可能仍是原账号。后台 token 刷新、正常重连及重启不属于主动重新登录。

```text
AI 账号
OpenAI · 账号 A
● 可接单                    [暂停接单] [详情 →]

账号详情
当前账号  A
● 可接单
[暂停接单]
[重新登录]（次要操作）
▸ 凭证读取方式
```

```text
重新登录 → 确认弹窗：将暂停此平台接单，登录后仍暂停
  ├─ 取消 → 返回详情，不改变接单选择
  └─ 开始官方登录 → 等待官方登录… [取消登录]
      → 自动核验身份
          ├─ 仍是 A → 已暂停 → [恢复接单] → 可接单，步骤隐藏
          └─ 发现 B → 保留 A → 等待核对并明确确认换号
```

开始登录后再取消不自动恢复接单；读取失败不等于发现不同账号。“返回不同账号”仅描述预览预设结果，产品按钮只叫“重新登录”。同身份结果也必须能作为子场景直接查看。

### 发现不同账号：流程与最终文案已确认

前提是成功读取到可用候选身份 B，且确实不同于已接入的 A。既可能来自主动重新登录，也可能来自自动读取；文件时间或 token 变化、读取失败均不能单独作为换号依据。

```text
AI 账号
OpenAI · 已接入账号 A
⚠ 发现不同账号
① 核对账号 ─ ② 确认换号 ─ ③ 自动准备 ─ ④ 恢复接单
[核对账号变更]                         [详情 →]
▸ 换号说明

账号详情
已接入账号       A
发现新账号       B

确认换号前，Bee 保留已接入账号 A。
[确认换号]
```

最终文案用“核对账号变更”替代“查看新旧账号”；身份字段使用“已接入账号／发现新账号”，省去“原读取目录／该目录现读到”等目录信息。B 是候选身份，确认前不替换 A。

```text
核对账号变更 → 展示 A、B 对比 → 确认换号 → 二次确认 A → B
  ├─ 取消或关闭详情 → 保留 A
  └─ 确认更换 → 自动准备 B → B 已就绪，保持暂停
      → [恢复接单] → 可接单，步骤隐藏
```

运行与接单情况是独立事实，不作为换号原因。错误／阻塞呈现统一按已确认的聚焦规则，不堆叠无助于处理的额度占位信息。

### 读取权限不足：页面与暂停保留规则已确认

```text
AI 账号
OpenAI                              [详情 →]
已接入账号 A

⚠ 无法读取登录文件：系统拒绝访问
① 修复读取 ─ ② 自动核验
[打开读取设置]
▸ 查看错误详情
```

页面只突出“打开读取设置”；“暂停接单”移入账号详情，不显示“额度尚未核对”、额度或套餐等无助于修复的信息。折叠详情保留读取位置和实际系统错误证据，同因去重。原账号 A 保留，读取失败不代表登出或换号。

```text
打开读取设置 → 展开读取目录与存储方式（仍未修复）
  → 用户修正目录或系统权限 → 实际读取成功 → 自动核验
      ├─ 仍是 A → 按原有接单选择继续
      ├─ 发现 B → [核对账号变更] → 明确确认后才换号
      └─ 仍被拒绝 → 保留具体错误与修复入口
```

用户明确确认：原先暂停就仍暂停，原先允许接单就在修复、核验通过且其他条件满足后继续接单。修复权限本身不改变接单选择；修复期间用户主动改变选择时保留其最新选择。若转入主动重新登录或确认换号，则适用这些动作完成后保持暂停的既定规则。

原先已经暂停时，沿用同一故障布局，步骤显示为：

```text
① 修复读取 ─ ② 自动核验 ─ ③ 恢复接单
[打开读取设置]

修复与核验完成 → 已暂停 → [恢复接单] → 可接单，步骤隐藏
```

暂停是独立条件，不列为权限错误的原因；故障未解除时不提前突出“恢复接单”按钮。所有阶段均按子场景规则提供独立评审入口。


### 授权过期但未手动暂停接单：页面与流程已确认

```text
AI 账号
OpenAI                              [详情 →]
已接入账号 A

⚠ 授权已过期
① 重新登录 ─ ② 自动核验 ─ ③ 恢复接单
[重新登录]
▸ 查看错误详情
```

```text
重新登录 → 确认弹窗
  ├─ 取消 → 保留授权过期状态，不改变原接单选择
  └─ 开始官方登录 → 暂停接单 → 等待登录 → 自动核验
      ├─ 仍是 A → 保持暂停 → [恢复接单] → 可接单，步骤隐藏
      └─ 发现 B → [核对账号变更] → 明确确认换号
          → 自动准备 → 保持暂停 → [恢复接单]
```

仅检测到授权过期不等于用户主动暂停；授权故障本身阻止接单。用户确认开始官方登录后，适用主动重新登录保持暂停的规则，即使原先允许接单也不自动恢复。各状态与弹窗按子场景规则提供直接查看入口。用户已明确同意本场景；HTML 与真实实现状态不因此改变。
