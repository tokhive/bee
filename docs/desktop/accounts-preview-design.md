## 连续流程新版确认（2026-11-09，当前基线）

用户已认可 flow-comparison.html 新版并要求落盘。该版已纳入 [唯一主预览](../preview/index.html?scene=intake-candidate-allowed)，[新版对比页](../preview/flow-comparison.html) 与 [旧版](../preview/draft.html) 继续保留。以下规则替代此前“其余流程先测试再决定”“主预览暂未合入”及相关旧步骤描述；旧章节和逐项 HTML 缺失记录作为当时的评审历史，不代表当前覆盖状态。当前预览有 227 个直接入口，对应原 108 个业务索引条目；HTML 认可不等于正式代码或真实接口验收。

| 流程 | 连续步骤 | 完成反馈 |
| --- | --- | --- |
| 首次登录与接入 | 登录 → 核验账号 → 确认接入 → 准备接单 | 账号接入成功；沿用已认可的首次完成态 |
| 已登录账号直接接入 | 确认接入 → 准备接单 | 账号接入成功 |
| 重新登录／授权过期恢复 | 重新登录 → 核验账号；需要准备时追加准备接单，并保留到完成 | 重新登录成功／账号授权已恢复；明确接单仍暂停 |
| 凭证读取修复 | 修复读取 → 核验账号；需要准备时追加准备接单，并保留到完成 | 账号读取已修复；保存设置本身不代表修复完成 |
| 确认换号 | 核对账号 → 确认换号 → 准备接单 | 已更换为账号 B，接单保持暂停；确认生效前保留 A |

步骤位于身份下方，状态和按钮区预留空间。失败只标记失败节点，重试保留前序进度和流程来源；实际需要新增准备阶段时展示，不为未知进度虚构节点。准备成功后节点全绿，完成反馈在原卡片停留至用户点击“完成”，不新增全屏祝贺页。

“完成”仅收起步骤和提示，进入普通账号卡片，不改变身份、暂停选择或额度，不重新提交接入／准备。暂停时普通卡片提供“恢复接单”，恢复操作不再列为完成流程的最后一步。允许接单且条件满足时，不等待用户点击“完成”才接单；额度不足时明确等待额度恢复。读取修复保留原接单选择；主动重新登录和确认换号仍保持暂停，不能因完成反馈自动恢复。

超时后的安全重登先显示“正在结束上次登录”，确认结束后启动新登录；取消中、已取消、结果未知仍遵守既有规则，不显示成功完成态。普通暂停／恢复、额度等待、自动重连、状态更新与独立结果核对不套用这次完成确认。

### 官方登录：静态模拟与正式行为的边界

当前 HTML 由固定延时模拟官方授权完成，因此未点击“打开登录页面”也可能自动进入核验。这只是预览演示，不是正式产品的跳过登录规则。正式产品必须依据真实官方登录结果再核验账号，不能以延时或浏览器已打开判定成功。若官方客户端已自动打开浏览器，打开按钮用于补开；实际是否具备自动打开能力尚待源码与集成核验。已有会话可以很快完成，但仍需真实结果与身份核验。此次认可不宣称这些接口能力已经实现。

## 首次登录连续流程与完成确认（2026-11-09，已认可）

用户已认可 [首次登录草稿](../preview/draft.html?scene=onboarding) 的本次效果；[完整冻结版](../preview/history/20261109-180232-first-login-completion/draft.html?scene=first-success) 为本轮依据。认可范围仅为首次登录到接入准备及完成确认，不代表整份草稿、其他流程或真实业务验收通过。本轮仅落盘文档，主预览暂未合入这次改动；用户先测试当前场景，再决定其他流程是否调整。

### 连续呈现

- 同一 OpenAI 卡片内保持“① 登录 → ② 核验账号 → ③ 确认接入 → ④ 准备接单”。核验成功后保留前两步绿色完成记录，不重新编号为两步接入流程。
- 步骤位于账号身份下方、状态说明上方，状态与按钮区预留空间，减少推进时的跳动。数字始终保留，沿用既有完成／当前／失败／未开始颜色。
- 核验成功显示“已识别账号 A，请确认是否接入”；用户仍须明确确认接入。接入与准备中的失败重试保留当前流程来源；失败不显示成功结果。取消与未知结果继续遵守各自既定规则，不伪装成完成。

### 完成态与接单状态分离

准备成功后不立即收起步骤；四个数字节点全部变绿，在原卡片显示“账号接入成功！”和一个“完成”按钮，不新增全屏页、弹窗或撒花动画，不自动跳走。

| 实际条件 | 完成态说明 | 点击“完成”之后 |
| --- | --- | --- |
| 允许接单且条件满足 | 账号已接入，可以接单了。 | 普通可接单卡片，提供暂停接单 |
| 用户已暂停 | 账号已接入，接单保持暂停。 | 普通暂停卡片，提供恢复接单 |
| 允许接单但额度不足 | 账号已接入，等待额度恢复后接单。 | 普通额度等待卡片 |

“完成”只表示用户看完结果：收起步骤和成功提示，展示普通账号卡片；不重新接入、不重新准备、不更改接单选择，也不是第二次接单授权。允许接单且条件满足时不等待此按钮才生效；暂停和额度阻塞也不会因点击而解除。若同时暂停与额度不足，完成态优先说明保持暂停，普通卡片继续展示额度条件。

首次流程始终四步，不增加第五步“恢复接单”。恢复接单属于完成后普通卡片的独立操作；之后暂停／恢复不重新弹出首次成功提示。该规则是此前“准备完成后隐藏步骤”及“暂停时补恢复步骤”的首次登录专项例外，其他流程暂沿用原规则。

```text
登录 → 核验 → 确认接入 → 准备接单
                            ├─ 失败 → 保留步骤与具体原因 → 重试
                            └─ 成功 → 四步全绿＋接入成功＋实际接单条件
                                      → [完成] → 普通账号卡片
```

直接选择完成态应停留；重置回最后直接选择的起点。切场景取消旧模拟，主题／尺寸切换保留当前状态。完成态提供允许接单、暂停、额度等待三个直接入口。只验证静态 HTML，真实接单、持久化与后台恢复边界不据此认定完成。

## 会话合并基线

用户已要求将[分叉会话 2](codex://threads/01a1a9aa-3c05-73b3-81db-6acb17d7b300)的新增结论合入[主会话 1](codex://threads/01a1a60a-62f8-7d71-a9b3-b4c0ebc93699)，后续在主会话继续。本节承接两边已确认的要求；合并不代表批准待评审的视觉或预览页实施，也不涉及 Git 合并。

- **账号呈现**：每账号只突出一条主状态；原因默认折叠，同因去重，独立条件保留。权限不足与手动暂停分别解除，修复权限不自动解除暂停。
- **按任务展示步骤**：首次接入和故障恢复中，有先后依赖才展示当前必要步骤；根据实际状态跳过或切换，完成后隐藏；首次登录按上文专项规则停留至点击“完成”。可接单、单纯暂停、自动重连、额度等待和结果核对不常驻完整步骤条。步骤不替代业务状态机；可接单仍需当前可信事实证明。
- **当前动作易操作**：用户接受步骤数字可点击或旁边有对应按钮；自动阶段只展示进度，后续步骤不能跳过，接入与换号仍须确认。
- **换号与修复语义**：成功读取的可用候选身份与已接入身份不同，才属于发现不同账号；token 刷新、文件修改时间变化和读取失败本身不代表换号。保留原账号，明确确认后才更换。暂停和本机运行情况是当前事实，不能列为换号原因。“打开读取设置”只定位读取方式和目录，打开详情不等于检测、授权或修复完成。
- **自动运行目标**：Bee 运行时自动维护已明确接入的账号，不再要求用户手动开始／停止贡献。接入保留原有接单选择；主动重新登录和确认换号后保持暂停；正常重连、重启及同身份后台刷新保留接单选择。早期手动启停的步骤和截图仅为历史依据。产品目标与当前原生实现、mock 验证范围分别核对，不能互相替代。

以下为分叉当时的历史状态；后续三场景及额度等待认可范围见本文对应记录，其他旧候选不因此获得认可。分叉中的视觉结论须区分状态：用户已否定整块卡片式可点击步骤；`html-clickable-steps-*` 截图不是后续视觉基线。最新候选采用轻量水平步骤线和相邻独立操作按钮，去掉金色外框、大片底色与拥挤说明，**尚未获得用户视觉认可**。候选与历史记录见[账户页评审记录](evidence/2026-11-04-account-ui-review/README.md)、[当前 HTML](evidence/2026-11-04-account-ui-review/accounts-preview.html)和[完整 HTML 历史索引](evidence/2026-11-04-account-ui-review/history/README.md)；原型检查通过不等于正式 React 或真实业务验收通过。

当前 worktree 的通用规则见 [HTML 预览规范](../standard/html-preview.md)；具体账号场景及确认结论在本文维护。HTML 修改前归档、交付时留版，冻结完整依赖，只追加历史并维护时间、来源、评审状态；截图不能代替 HTML。规则正文在 [Bee AGENTS.md](../../../../bee/AGENTS.md)，worktree 通过自身 AGENTS.md 引用，不在项目根目录另建副本。

## 已确认

- 先定预览页设计，再修改页面。
- 评审范围是 AI 账号页。
- 以 AI 账号完整场景列表作为评审入口，便于直接选择要看的页面状态。
- 三个验收项目不能替代完整场景列表。用户不应为了查看某个场景，先理解并组合外部事件参数。
- 场景入口沿用顶部下拉列表，按接入、接单、授权问题、变更与恢复分组。
- 选择场景后，页面按钮仍可操作；由页面操作触发的登录等结果由场景预设并演示，不要求用户配置外部事件。
- 正常场景和异常场景都在列表中。异常起点停留供评审；想看正常页面时，直接选择对应正常场景。不增加“演示恢复”按钮，也不按定时器自动离开所选异常场景。
- 切换场景加载该场景的预设起点；这用于比较页面状态，不等同于验证原场景的数据经过恢复流程。连续恢复中的暂停保留等规则另由自动化验证。
- 预览区保留场景下拉、外观、窗口尺寸、重置场景，以及一句“当前看什么、预期是什么”的说明。去掉长教程和验收进度；正式账户页面放在下方。Q5 示意图中的“演示恢复”按上述讨论移除。

- 实施时不能仅增加场景名称：现有授权和额度故障有按固定场景标识持续添加的逻辑，场景内操作后需要由当前模拟事实决定状态；“换号结果待核对”需要初始化可核对的未决操作。依据：`desktop/tests/fixtures/bee-preview/scenarios.mjs`、`fixture.mjs`、`desktop/tests/fixtures/native-accounts.mjs`。

## 三场景步骤预览（已认可，已纳入主预览）

本节记录既有 HTML：其中“接入后统一暂停”的行为已被下方最新文本规则替代，HTML 尚未同步，不再作为接入状态规则的依据。

## 当前文本评审基线（更新于 2026-11-09）

本节是后续场景讨论与未来 HTML 更新的依据。按用户最新要求，逐项确认先保留在对话中，用户明确要求落盘时再统一更新本节并提交；有变更则更新对应结论，避免把已被替代的说法继续当作方案。文本确认、HTML 更新与真实实现验证分别记录。

### 确认进度与执行边界

- 已确认文本流程：主动重新登录；发现不同账号并确认换号；读取权限不足（原先允许接单／原先暂停两种情况）；授权过期但未手动暂停接单；断线自动重连；换号结果待核对；账号状态信息已过期、正在更新。已登录官方客户端待接入 Bee、刚接入且准备就绪后保留接单选择、普通暂停、未找到官方客户端的安装指引也已确认。额度等待的文本及 HTML 均已确认。细节见下文。
