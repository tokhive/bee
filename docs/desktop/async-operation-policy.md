# 桌面异步操作与重试规范

更新：2026-11-09（Asia/Shanghai）。本文件记录已确认的桌面通用行为；规范落盘不代表现有代码已实现或通过业务验收。

## 查询失败的自动重试

### 适用范围

适用于桌面应用中的查询类操作，例如读取账号状态、刷新登录进度、查询原操作结果。只有确认可安全重复的查询才适用；不能仅凭接口名称含“查询”或“刷新”认定没有副作用。

登录、接入、换号、暂停／恢复接单等写操作不适用本规则。查询结果未知也不构成重新提交原写操作的授权。

### 次数与停止条件

- 一次查询因临时错误失败后，最多自动重试 **3 次**。
- 重试次数不包含首次请求，因此同一轮最多执行 **4 次请求**：首次请求 → 重试 1 → 重试 2 → 重试 3。
- 查询成功即结束本轮失败重试，不必用满次数。
- 权限不足、参数错误等明确不可重试的问题，不自动重试，直接提供对应处理入口。
- 达到上限后停止本轮自动重试，显示本次失败原因，并提供与业务对应的手动刷新入口，例如“刷新登录进度”。不能换一个内部计数器继续无限重试。

### 与进度轮询的区别

- 查询成功，但返回“仍在进行中”或“结果尚未确定”，属于进度轮询，不计为查询失败，不消耗失败重试次数。
- 进度轮询必须另设等待上限，不能因每次查询都成功就无限等待。
- 查询失败不等于被查询的登录、接入或换号已经失败；仍应查询原操作，不能自动创建新的业务操作。

### 待确定与实现边界

本次已确认的是失败重试上限及上述行为边界。以下参数尚未确定，不得将任意数值写成已确认规则：

- 自动重试间隔及退避方式。
- 不同异步操作的轮询间隔、等待上限及达到上限后的具体恢复路径。

既有模块的实现与旧文档需要在相应任务中对齐本规范；本次未修改代码、HTML、mock 或现有场景文档，也未验证真实重试行为。
