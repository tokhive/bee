# 旧会话安全结束与恢复补充

用户于 2026-11-11 要求继续实施真实旧会话的恢复闭环。本补充落实原启动恢复规格的旧工作线程与 Hive 归属证明，不改变账号、设备绑定或接单选择。

## 实现边界

沿用 Go、Rust/Tauri、React、私有原子文件和现有 Hive PostgreSQL，不新增服务或依赖。Bee 改动仅在当前 worktree；Hive 配套实现保存为可审阅补丁；用户后续确认在独立分支 `fix/runtime-session-retirement` 正式集成并完成隔离跨进程验收。Hive 主工作区未修改，不部署，不执行真实账号恢复。

## 处理方式

1. 本机管理进程持有设备独占锁，确认当前没有工作线程、账号写操作、设备恢复或未决登录维护。该检查只证明本机不会再产生旧请求，不能代替 Hive 证明。
2. 在任何远端写前保存恢复 ID、设备绑定摘要、原运行意图、完整账号范围摘要、原 run 和原保护记录。回执丢失后查询同一 ID，参数不能变化。
3. Hive 在设备请求入口隔离旧代请求，等待已经获准的写操作返回；保存新代与原恢复 ID，停止旧连接并核对未结束任务。未结束、未知或数据库失败均不签发结束证明。
4. 在设备隔离下核对原准备 ID、账号指纹及归属，结束对应准备保护，保留原终态；其他设备或未知准备保护继续阻塞。暂停状态不写入。
5. Bee 只有取得与原请求完全匹配的持久证明，才保存新会话代并受控接管保护记录。旧记录保留为证据；正常启动、停止、升级原有校验继续生效。
6. 旧 Hive 未提供该协议时明确说明需要 Hive 配套升级。没有有效恢复动作时不展示无效的“核对结果”循环；本地诊断仍可导出。

Hive 当前连接与调度由单个 Market 进程拥有；配套补丁的请求隔离与其部署模型一致。持久会话代在 Hive 重启后仍拒绝迟到的旧请求。不能将补丁在隔离环境通过等同于已部署或真实账号已恢复。

## 风险与验证矩阵

| 场景 | 要求 |
| --- | --- |
| 旧写先获准、恢复随后到达 | 恢复等待旧写完成，迟到写不能覆盖新代 |
| 旧请求在恢复后到达、Hive 重启 | 旧代和无代写均拒绝 |
| 原恢复回执丢失、进程重启 | 查同一 ID；不换 ID 绕过未知结果 |
| 同 ID 换参数、新 ID 抢占未决恢复 | 拒绝并保留原证据 |
| 旧连接或远端任务未结束 | 保持阻塞，不发结束证明 |
| 准备 ID 不同、账号指纹不同、归属不同 | 保留保护并阻塞 |
| 一个账号暂停、另一个允许 | 恢复全过程没有暂停写，回读保持选择 |
| 本地文件任一步保存失败或中途崩溃 | 保留原引用，不无证据写 clean，不启动贡献 |
| 原意图停止、新停止、退出／升级竞争 | 不启动贡献，不放宽写屏障 |
| Hive 无协议或返回损坏数据 | 具体阻塞原因，诊断可用，无虚假重试成功 |

## 实际验证与限制

风险回归先记录客户端接口缺失的编译失败；Hive 最初的依赖缺失不能算有效行为红测试。后续准备冲突证据测试实际失败，暴露公共错误码白名单漏项，补齐后通过。未编造完整 TDD 证明。

Go 完整竞态测试、最终恢复风险测试与 vet 通过；Rust 303 单测与 76 合约通过，原生窗口类 4 项仍 ignored；原生界面模拟 IPC 全组 73 项通过，最终受影响分支 7 项通过；Hive 真实 PostgreSQL／HTTP 集成 4 场景通过。最终开发包构建、ad-hoc 签名检查通过，未启动真实账号。

Hive 补丁已在独立分支实际集成，共享 wire 独立提交并更新 gitlink；真实 Rust → Go sidecar → Hive HTTP → PostgreSQL 的五场景，加四个 Hive 集成回归通过，证据见[联调摘要](../evidence/2026-11-11-startup-recovery/native-hive-integration.txt)。配套文件见[配套实现](../integrations/hive-session-retirement/README.md)。证明先保存，新 epoch、旧 scope、guard、completed 分阶段落盘；中断后沿原 proof 恢复，不能无证明写 clean。Rust 使用持久绑定摘要关联旧未知记录，缺少摘要的历史未知记录仍阻塞；退役不改写原操作未知结果。

原生窗口、真实部署及真实账号恢复仍未验收；单设备单 Market 前提、旧 Bee 降级不兼容与证据边界见[验收记录](../evidence/2026-11-11-startup-recovery/README.md)。
