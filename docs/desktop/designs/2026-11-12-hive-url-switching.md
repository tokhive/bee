# 按 URL 切换 Hive

状态：2026-11-12 用户确认完整设计，并指定按 implement-spec 直接实施，不另写实施计划。包含 Q1–Q10、技术栈、迁移边界、2 秒／60 秒观察参数及验收矩阵。规格已批准不表示当前 App 已支持切换。日期：2026-11-12（Asia/Shanghai）。

## 1. 目标与已确认决策

支持 A → B → A。每个 Hive 保留自己的设备绑定、账号选择及相关操作记录，切回时重新核验原绑定。一个 App 同时只在一个 Hive 贡献。

| 决策 | 已确认行为 |
| --- | --- |
| 环境边界 | 本阶段按 URL 区分，见 [ADR](../../adr/0001-hive-url-scope.md)；不新增 Hive 实例身份 |
| Q1 | 停止 A 接收新任务，等待已接任务完成，再切换；等待期间可取消 |
| Q2 | 切换成功前明确失败，保留 A；若 A 已断开，核验后恢复原连接和暂停／允许选择 |
| Q3 | 无法证明 A 的旧任务或未决操作已安全结束时阻止切换；有可靠干净停用证据时不一律要求 A 在线 |
| Q4 | 本轮仅等待与取消，不提供强制中断；等待过久不自动终止任务 |
| Q5 | 崩溃或重启后自动核对并继续原切换；结果未知不重放写操作，明确失败按 Q2 返回 A |
| Q6 | 先完成 B 的配对及身份核验，期间 A 正常运行；准备 B 不接入 AI 账号、不开始贡献 |
| Q7 | 统一主机名大小写、默认端口和末尾斜杠；不同主机名／非默认端口独立；历史冲突保留并提示 |
| Q8 | 在概览设备区提供“切换 Hive”，使用紧凑的已保存地址列表与添加入口，进度留在同一区域 |
| Q9 | 主动退出时提供继续等待／取消切换并退出；取消后走现有退出流程，说明退出可能中断任务；取消未知不宣称成功 |
| Q10 | B 的身份与连接核验通过后可以完成切换；账号未接入、登录或额度问题在 B 内处理，成功后的断线走 B 的正常恢复 |

“任务完成”包括 Hive 已准入的执行、仍可能在上游运行的未知终止及未完成结算，沿用 Hive 现有执行预算和结算规则。不能以本机流数量为零替代。

接入账号、主动重新登录和换号沿用 [账号准备规则](../account-preparation-supply.md) 与 [术语表](../../../GLOSSARY.md)。切换不自动接入新账号，也不改变用户的暂停／允许接单选择。读取不到最新选择时，不推定允许接单。

## 2. 当前事实与方案选择

当前 DesktopDevice 拒绝修改已绑定 URL。设备配置、运行保护、设备恢复、当前会话退役和 Rust 启动恢复均为单份；账号和登录维护文件只有部分记录已经按 URL／用户／设备隔离。

Go 正式桌面入口没有选择配置目录的参数，获取设备锁后不允许更换路径；Rust 重连复用固定启动参数。device_status 可能保存身份和推进配对，Restore 会预约运行保护，二者不能作为无副作用的历史列表读取接口。

Hive 已有设备级最终准入锁与执行／结算查询基础，但没有可取消的独立停止派单协议。设备替换最终撤销旧设备，runtime retirement 会立即关闭旧连接，都不能原样代替本需求。

| 方案 | 完整性 | 业务复杂度 | 实现复杂度 | 结论 |
| --- | --- | --- | --- | --- |
| 只保存多套凭证，切换时覆盖当前文件 | 恢复记录、锁、进程和启动日志仍可能串用 | 表面简单，隐含错误恢复规则 | 低，但不正确 | 不采用 |
| 每个 URL 独立绑定目录，单个切换协调器管理进程交接 | 覆盖记录归属、准备 B、往返及重启恢复 | 一个当前 Hive、一笔切换 | 中等，复用现有单绑定核心 | 推荐 |
| 一个常驻核心同时容纳所有 Hive 的运行对象 | 可以完整覆盖 | 需要多套生命周期和写入准入 | 高，需广泛改写单绑定假设 | 本轮不采用 |

推荐方案使用现有私有文件、进程监管和 PostgreSQL，不引入新服务或任务框架。单个后台只拥有一个绑定目录，避免运行中替换其路径。

## 3. URL 判定与历史兼容

URL 比较由核心统一执行，Go／Rust／TypeScript 使用同一组输入、输出和拒绝样本。

- 仅接受服务 origin：远程 HTTPS；HTTP 仍仅允许标准回环地址。拒绝用户名密码、非根路径、查询参数和片段。
- 协议、主机名按统一大小写规则处理；去掉 HTTPS 的 443、HTTP 的 80 及根路径末尾 `/`。
- `https://HIVE.example:443/` 与 `https://hive.example` 是同一键。
- `localhost` 与 `127.0.0.1`、不同域名、不同非默认端口分别保存。不通过 DNS、重定向或地址解析结果自动合并。
- 其他既有合法主机形式继续由共享契约明确处理；本轮不额外推定 Unicode 域名与其编码别名、不同 IPv6 写法等价。
- 规范化键负责查找绑定，不能直接覆盖历史事务中的原始 origin、作用域摘要或证明内容。旧记录保留原上下文，新增记录使用规范化地址。
- 多条历史记录归一化后冲突时，不按时间覆盖或拼接凭证。保留原记录及当前有效绑定，对冲突项禁用切换并给出明确冲突信息；在未决操作核对完之前不允许合并或删除。

同一 URL 换数据库仍属于同一地址范围。`invalid_device_credential` 表示当前服务不接受凭证，`device_replaced` 才是明确撤销证据。需要重绑时使用受控恢复，新设备不继承旧设备的已接入状态。没有被保存的旧凭证不能从账号记录或哈希还原。

不同 URL 可能实际指向同一个服务；按 URL 的方案不能识别这一点。B 网页配对若要求替换既有设备，影响由该网页明确确认，不能承诺这种别名场景下 A 的绑定始终有效。每个关键阶段仍重新核验绑定，不向 B 发送 A 的凭证来试探是否同一服务。

## 4. 本地数据与进程归属

### 4.1 存储边界

新增受保护的绑定目录索引，保存版本、规范化 URL 到内部 profile ID 的映射、当前 profile、修订号和迁移状态。索引不复制设备凭证。profile ID 由核心生成，前端只能选择已登记 ID 或提交待校验 URL，不能指定文件路径。

每个 profile 的私有目录成套保存设备配置、账号文件及旧版本备份、登录维护记录、运行 guard、配对／凭证恢复记录、会话退役记录、Rust 启动恢复记录及其历史证据。所有密钥文件沿用 0600、拒绝符号链接、原子替换和目录同步规则。

另设一份 App 级切换记录，保存操作 ID、A/B profile 与绑定版本、准备／停止派单／连接阶段、远端原请求标识及回执、取消／退出意图和当前提交状态。已完成记录只归档，不复写成新操作。

语言、外观、通知和开机启动偏好仍属 App。代理按绑定范围隔离；全局通知投递去重仍保留，但通知携带来源 profile，切换后不得把 A 的通知解释成 B 的问题或自动切回 A。

官方登录文件和钥匙串由 Codex／Claude Code 管理，不复制到 Hive 绑定目录。两个 Hive 可以选择同一个来源；在 B 登录可能改变 A 的来源，切回必须重新核验账号身份和凭证版本。

现有历史账号作用域和登录维护容量校验继续按 profile 执行。达到原有上限时明确阻止新增，保留全部未决证据；本轮不新增自动删除历史绑定或远端设备的规则。

### 4.2 单运行对象与目标准备

Rust 协调器拥有 App 级独占锁，同时最多管理一个当前后台和一个目标准备后台。两个后台分别固定自己的 profile 路径、进程实例和设备锁。

目标准备后台在 Go 核心层限制能力：只允许本地上下文检查、身份／能力核验、用户已发起的配对／凭证恢复、相应原事务核对，以及协调器为安全激活指定的设备屏障操作；禁止运行恢复、账号接入、授权上传、官方登录、供给维护和任务连接。Rust 也使用对应白名单，不能只靠界面隐藏按钮。

目标的私有文件可以因已授权配对而变化，但不替换当前 profile，不应用其网络偏好到 A，不向当前账号视图发布目标快照。目标预检读取已保存的 guard／未决记录时不自动执行旧写操作；不满足目标恢复条件则在停止 A 之前阻塞。

交接前确认 A 的 owned worker、IPC 写入、登录进程及连接已按对应协议安全结束，保存必要回执，停止并确认其管理进程退出。切换专用停止原因保留原运行意图，抑制自动重新连接；服务器封存回执持久保存前，不将原会话保护最终标成可恢复。目标准备后台也正常退出后，以固定 B 路径启动受协调器控制的正常后台。不能强杀不属于本 App 的进程或靠锁超时冒充退出。

切换涉及全局协调器、profile、后台实例、绑定版本四层上下文。旧实例的成功、错误、配对结果和通知不能覆盖当前 profile。普通页面命令仍只路由到当前 Hive；切换操作用独立接口和快照公开 A/B 进度。

## 5. Hive 停止派单协议

新增独立的设备级停止派单能力，工作名称为 device-drain。它不撤销设备凭证、不修改用户平台 paused，也不把目标 Hive 地址传给源 Hive。

提供只读的版本能力查询，以及按设备和原操作 ID 的 begin、status、seal、release 操作。具体路由和严格 DTO 在共享协议任务中固化；能力查询不能写数据，不能通过尝试写入来猜支持情况。身份接口成功不代表支持此协议。

| 动作／状态 | 必须保证的行为 |
| --- | --- |
| begin → draining | 在与最终调度准入相同的设备锁下持久关闭新准入，保留当前连接和已接任务；屏障提交前已准入的执行纳入核对 |
| status | 返回原操作、当前阶段及执行／未知终止／未结算事实；没有可靠计数时不伪造进度 |
| ready 观察 | 已无未完成工作，但新准入屏障继续保持；这只是允许封存的条件，不能解除屏障 |
| seal → sealed | 再次核验无未完成工作、隔离旧代写入并确认旧连接注销，持久保存该操作的封存回执；屏障仍保持 |
| release → released | 按当前阶段和绑定核验解除本次屏障；取消等待或重新激活使用对应条件，不能解除别的操作 |

协议覆盖以下要求：

- 调度最终准入必须读取新屏障；仅关闭 Bee 写接口或停止本机维护不足以停止新任务。
- seal 才允许推进运行 epoch；必须显式关闭并确认旧连接，因为已存在 WebSocket 不会逐帧重新验证 epoch。封存之前让原执行和结算自然结束。
- 每个设备只有一个有效屏障。操作 ID 和各动作请求在发送前持久化；同 ID 同参数返回原结果，异参数冲突。迟到 begin／release 不得重新开启已终结操作或影响下一次屏障。
- 新屏障与既有设备替换、运行退役必须串行核对；冲突时拒绝新操作并保留原归属。重新激活须核验预期 epoch、当前连接 lease 和原操作，不能结束其他进程拥有的连接或屏障。
- release 与 begin／seal 并发时在服务端串行判定。取消一个尚未到达的 begin 需要持久终结标记，防止迟到请求重新关闭准入；已 sealed 则不能恢复旧 epoch，必须用新代重新连接。
- 回执固定记录本操作的设备、用户、原上下文、封存后 epoch 与完成事实，和当前设备状态分开返回。后续操作不能改变旧回执的含义，也不能把历史完成事实当成当前在线状态。
- 屏障不因超时、进程退出或配对过期自动解除。重启只核对原操作；未知响应不通过换 ID 绕过。旧无 epoch 客户端在推进后不能重新进入；普通身份 GET 仍按其自身鉴权规则工作。
- 使用现有设备注册单一 Market owner 的部署前提；数据库准入屏障必须持久化。不能把当前进程内的互斥锁宣称为多实例分布式协调。

返回 A 或激活 B 时，也要避免“连接尚未验证就开始接单”：目标启动前须持有该目标的停止派单屏障，优先续用上次切出的原屏障。连接与最新用户选择核验通过并提交当前 Hive 后，才解除对应屏障。准备和用户暂停等其他保护独立生效，解除切换屏障不等于平台必然可接单。

## 6. 切换顺序与提交边界

1. 保存切换意图，固定 A/B 与绑定版本。拒绝第二笔冲突切换；重复点击返回原操作。
2. 准备 B：使用已有凭证核验，首次地址由用户配对；检查版本能力、目标本地记录、绑定及网络配置。A 继续运行，目标不贡献。
3. B 准备成功后，重新核对两边绑定版本，冻结 A 的新增账号／登录写操作并核对已在途操作。用原 ID 在 A 建立停止派单屏障，保留任务处理和结算所需能力。用户暂停选择仍以最新结果为准，恢复接单不能绕过切换屏障。
4. 等待 A 的任务完成。停止派单不改 paused；网站此时对用户选择的修改仍然有效。取消须保存意图并核对服务端解除结果。
5. Hive 确认可以封存后，完成 A 的本机停止、服务器 seal、回执落盘、管理进程退出和恢复记录收尾。部分保存失败沿原记录继续，不能只清 guard。
6. 在 B 的屏障下启动目标后台，完成设备、网络和连接核验；不能要求所有 AI 账号正常才允许切换。
7. 原子提交绑定目录索引中的当前 profile=B，并记录该切换 ID。此点是切换成功的持久边界；重启按索引和原 journal 修复展示。提交前 B 不能接单。
8. 显示已切换到 B，按原记录解除 B 的切换屏障并恢复正常维护。账号问题、解除屏障结果未知或后续断线在 B 内处理，不自动回到 A。

连接核验须独立于账号维护：即使 B 尚未接入账号，也能建立并验证设备连接。屏障解除前不上传账号授权、不启动供给维护，不能借用必须先准备账号才返回成功的现有启动结果作为切换成功证据。

索引和 journal 不是一个文件事务：先持久化准备提交的阶段及证据，再原子替换索引，最后补记终态。索引需携带操作 ID／修订号，重启能区分“尚未提交”和“已提交但未补记”，不得仅凭界面最后显示的地址决定归属。索引写入本身结果未知时，先核对实际持久状态，不能盲目回退。

在提交前明确失败，先停止并确认 B 不可能开始贡献，保留 B 已发生的配对／绑定及其子事务，然后恢复 A。恢复 A 也先核验当前身份、最新 paused 和连接；无法恢复则显示“A 已保留，连接仍需处理”，不能宣称已恢复。结果未知先核对，不能直接按失败回退。

成功后用户要求返回 A 是一笔新的 B → A 切换，保留前次成功事实。

## 7. 取消、退出与离线

取消仅撤销本次切换意图，不撤销已经完成的 B 设备配对。B 已确认的绑定继续保存供下次使用；创建／兑换未决的子事务必须保留原凭证和查询入口，不能用“切换已取消”掩盖远端结果未知。

等待 A 完成时取消，释放对应屏障后按最新选择继续 A。若 A 已 sealed，回到 A 需要新代连接和解除屏障，不能复活旧连接。取消与成功提交并发由协调器串行决定；已经提交 B 时不改写为取消成功，可另发 B → A。

关闭面板或切换页面不取消操作。主动退出按 Q9 提供继续等待／取消切换并退出；退出意图持久化。取消响应未知时，不新建切换或声称取消完成；退出过程仍执行既有 owned worker 清理，下一次启动先核对原取消，而不是自动继续去 B。App 意外崩溃且没有取消意图时按 Q5 继续原切换。

A 离线时，“可靠干净停用证据”必须包含：匹配当前绑定和原运行代的已持久封存回执、对应本机 worker 已退出、无未决操作／在途 IPC、且此后没有重新连接、解除屏障或写入尝试。只看到 clean 文件、PID 不存在、没有本机流或设备锁可用都不足以证明。

旧版 Hive 不支持新能力时，不能以暂停两个平台、伪造设备替换或立即退役代替等待。存在上述完整旧证据才可离线离开，否则提示升级／核对原 Hive；目标 B 的安全激活能力不满足时，在停止 A 前阻塞。

查询失败沿用[异步操作规范](../async-operation-policy.md)：首次失败后最多自动重试 3 次，不可重试的鉴权／参数错误立即停下。停止自动查询不终止任务、不解除屏障、不释放操作占位；重启不清空原查询预算。

已确认参数：状态查询每 2 秒一次，一轮自动观察最长 60 秒；仍未完成则保持等待，说明当前事实并提供“继续等待”。用户继续后开启下一轮观察，原操作 ID 不变。失败重试沿用当前统一查询调度器。此观察上限限制查询，不是业务任务截止时间。

## 8. 旧数据迁移与升级

迁移在旧设备锁和 App 锁保护下进行，先确认没有运行中的旧管理进程。脏会话可以原样迁入，但仍保持原来的恢复阻塞，不能为迁移改写成 clean；损坏记录保留证据。保存带摘要的私有原件备份和迁移进度，再写临时目标目录并校验，最后提交目录索引。崩溃继续原迁移，不重复拆分或清空记录。

当前有效绑定成为第一个 profile。原始 origin、哈希和事务证据保持可验证；旧账号／登录文件可能含多个历史 scope，不能把它们全部当成当前 URL，也不能无凭证地生成可连接的历史绑定。保留完整旧证据，只有能确认归属的数据才作为该 profile 的活动数据；归属不明的旧操作维持阻塞并可查看诊断。

迁移后旧入口必须明确拒绝旧程序继续使用根目录配置；原件保存在私有归档，不能留下一个可被旧 Bee 独立启动的旧配置副本。持有旧锁期间先验证新目录，再持久写入旧入口拒绝标记，之后才公开新索引；任一阶段中断均由迁移记录恢复。新程序识别迁移标记并继续恢复，不能把升级降级当作删除保护的途径。降级需专门迁移，不自动把新结构压回单绑定。

代理记录按经过核验的旧绑定上下文迁移；外观等全局偏好不复制。历史 URL 冲突保留证据并局部阻塞对应项；不能为了显示新列表让整个可用当前绑定丢失。

部署顺序：先共享协议与 Hive 数据迁移／服务能力，再发布 Bee。Hive 新增持久操作与屏障数据，沿用现有设备锁、最终准入和执行／结算查询；实际迁移编号在实施时按分支现状分配。旧 Bee 普通行为保留，但不能绕过新屏障或已推进 epoch。

## 9. 用户界面

概览设备摘要旁新增“切换 Hive”。紧凑列表显示规范化地址、已核验归属／上次归属、当前标记和添加入口；不自动遍历所有服务器触发配对或维护。

进度在原设备区单层展示，例如准备 B、等待 A 的任务完成、正在连接 B、正在恢复 A。只展示实际阶段及可信计数；未知结果明确写“结果待核对”，不估算百分比。详情一次展开，主动作按真实状态显示核对、继续等待或取消。

选择目标前说明切换会保留各自账号选择；已有允许接单的平台在切换成功并满足条件后可能接单。首次 B 没有已接入账号时，切换成功后引导接入，不自动沿用 A 的账号。

取消、超时和失败保留输入及原操作。弹层支持键盘、可见焦点与关闭后焦点回归；关闭列表不等于取消后台切换。沿用当前样式、暗色及窄窗口布局，正式实现和主预览同步；预览按现有规范留档。

## 11. 验收矩阵与完成标准

| 场景 | 必须证明 |
| --- | --- |
| A → B → A，两个既有绑定 | 使用各自凭证、选择、代理和恢复上下文，切回重新核验 |
| 首次 B，配对失败／取消／兑换未知 | A 准备期间继续运行；B 子事务不丢失、不重复兑换 |
| 同时到达的派单与 begin | 屏障之前的任务被纳入等待，之后的最终准入被拒绝 |
| 运行、未知上游执行、未结算 | 正确等待且不提前封存；真实数据库和任务状态验证 |
| 等待期间取消、暂停选择变化 | 只解除本次屏障，保留最新用户选择 |
| begin／seal／release 响应丢失、取消并发 | 查原操作；迟到请求不复活终态或影响下一轮 |
| seal 后本地保存失败、索引提交前后崩溃 | 原证据续写；当前 Hive 唯一；B 提交前无接单 |
| B 未成功、已成功后的账号故障／断线 | 前者明确失败安全返回 A；后者留在 B 正常处理 |
| 主动退出、意外崩溃、查询预算耗尽 | 分别保留取消／继续意图；未知状态不重放或自动清除 |
| A 离线、有／无封存证据、旧 Hive | 正确判断证据与能力，不用本机 clean 冒充远端证明 |
| URL 等价、地址别名、同 URL 数据库重建 | 不重复建立等价项，不跨凭证试探，不混淆拒绝与撤销 |
| 迁移中断、旧程序启动、历史 URL 冲突 | 旧证据保留、可恢复迁移、旧写入被阻止、不静默覆盖 |
| 官方来源在另一 Hive 改变 | 不把异号来源自动当成原账号接入 |
| 旧后台响应、旧通知、重复点击、第二实例 | 不污染当前界面，不产生第二笔切换或第二个贡献后台 |

验证包括 Go／Rust／TS 契约与故障注入、真实 PostgreSQL 并发准入、两个隔离 Hive 的往返集成，以及原生 App 的正常／失败／重启流程和主预览一致性。模拟样本不能替代真实任务完成及结算证据。未经授权不拿用户真实账号强制中断或替换设备。

已确认设计范围：Q1–Q10 的落实、profile 与协调器方案、Hive 新协议及部署依赖、迁移边界、2 秒／60 秒观察参数和上述验收矩阵。实现与验证进度记录在任务跟踪器，不能以规格批准代替验收。
