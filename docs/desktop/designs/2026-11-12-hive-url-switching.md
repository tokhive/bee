# 按 URL 切换 Hive

状态：讨论中。用户于 2026-11-12 调用 grill-with-docs，要求补齐 A → B → A 切换能力；尚未完成设计确认，未开始实现。

## 已确认边界

- 本阶段以 Hive URL 区分环境，见 [ADR](../../adr/0001-hive-url-scope.md)。
- 支持 A → B → A；各 URL 保留独立绑定，首次连接 B 需要配对，切回 A 时核验原绑定。
- 同一 URL 更换数据库仍落入凭证核验及恢复流程；invalid_device_credential 只说明当前 Hive 不接受凭证，不能据此宣称旧凭证已撤销。
- 切换时先停止 A 接收新任务，等待已接任务完成后再切换；等待期间允许取消。（Q1 已确认）
- 切换 B 失败时保留 A 为当前 Hive；若 A 已断开，重新核验后恢复连接和原暂停／允许接单选择，并明确提示切换失败。（Q2 已确认）
- 无法证明 A 的旧任务或未决操作已安全结束时阻止切换，保留记录并说明原因；已有可靠的干净停用证据时，不一律要求 A 在线。（Q3 已确认）
- 本轮只提供继续等待和取消切换，不增加强制中断入口；等待过久不自动终止任务。（Q4 已确认，细化 Q1）
- 切换期间崩溃或重启后，自动核对并继续原切换；明确失败按 Q2 返回 A，结果未知只核对而不重放写操作。（Q5 已确认）
- 先准备 B 的绑定并核验身份，期间 A 正常运行；B 准备完成后才停止 A 的新任务准入，等待已有任务结束并切换。准备 B 不接入 AI 账号、不开始贡献。（Q6 已确认）

## 沿用的领域规则

- 接入账号保留用户最新暂停／允许接单选择；确无历史选择时默认允许。以当前 GLOSSARY.md 和 account-preparation-supply.md 为准。
- 不同 Hive 的设备绑定与账号选择独立，不能因切换把 A 的凭证或已接入状态用于 B。
- URL 等价规则、切换结果未知及中断后的处理仍需完成设计，不能由上述目标推定实现已具备。

## 当前实现事实

- DesktopDevice.operate 拒绝将已绑定地址直接改成其他地址，目前没有正式切换入口。
- bee-desktop.json 只保存当前绑定；设备恢复成功会替换该绑定，恢复记录中的旧绑定摘要不能还原旧凭证。
- 账号记录按 URL、用户 ID、设备 ID 分隔，但这不足以提供完整的绑定往返切换。
- 当前设备身份协议没有 Hive 实例标识。
- 设备绑定、运行保护、设备配对／恢复、当前会话退役以及 Rust 启动恢复记录目前均为单份；账号与登录维护文件中的部分记录已有作用域隔离。设计必须覆盖全部记录的归属与中断恢复，不能仅给设备配置增加 URL 列表。
- 现有 Stop 会取消并等待本机工作退出，不保证已接业务任务全部完成。Hive 调度已有设备级准入锁和未完成执行／结算判断，但没有独立的可取消排空协议。
- 设备替换的 draining 会等待旧任务，但最终撤销旧设备，不适合作为 Hive 切换；runtime retirement 会立即取消旧连接且不能取消退役，不能保证在途任务持续完成。Q1 需要 Hive/Bee 共享协议及 Hive 准入状态的配套扩展，旧 Hive 的兼容行为须明确。
- A、B 可以引用同一个本机官方登录来源。在 B 重新登录可能改变 A 的来源；切回 A 必须重新核验账号身份，不能仅凭保存的选择宣称原账号可用。
- 现有账号作用域上限为 16，登录维护记录上限为 32；历史绑定保留与上限行为需在设计中明确。
- 正式概览设备区已有设备名称、归属和 Hive 地址，当前没有切换按钮；正式设置页没有历史 Hive 列表。旧演示页的切换按钮仅操作模拟状态。
- Go 已保存地址契约保留主机大小写、显式默认端口及部分 IPv6／Unicode 形式；代理偏好使用的 URL 规则不同。统一地址时需覆盖 Go／Rust／TypeScript 与历史记录迁移，不能只在前端变换字符串。

事实入口：agent/desktop_device.go、agent/desktop_account_persistence.go、agent/desktop_login_journal.go、agent/desktop_runtime.go、agent/desktop_session_retirement.go、desktop/src-tauri/src/startup_recovery.rs。

## 决策树与待确认项

- 环境边界：URL（已确认）。
  - Q7 待回答：推荐统一主机大小写、默认端口和末尾斜杠；不同主机名／非默认端口独立，localhost 与 127.0.0.1 不自动合并。历史冲突保留并提示。
  - 各环境的数据边界与旧配置迁移：单份记录已识别，隔离与迁移规则待设计。
- 切换过程：停止新任务准入，等待已接任务完成，可取消（Q1 已确认）。
  - 如何实现当前连接的停止准入、证明任务完成及取消恢复：已确认需要 Hive 配套协议；具体设计待完成。
  - 本轮仅继续等待／取消切换，不提供强制中断；不因等待过久自动终止任务（Q4 已确认）。
  - 先准备 B 的绑定并核验身份，期间 A 正常运行；B 准备完成后才等待 A 的任务结束并切换，准备 B 不接入账号或贡献（Q6 已确认）。
- 切换失败：保留 A 为当前 Hive；若已经断开则核验后恢复原状态，提示 B 切换失败（Q2 已确认）。
  - 无法证明 A 的任务及未决操作已安全结束时阻止切换；已有可靠干净停用证据则不一律要求 A 在线（Q3 已确认）。
  - 崩溃／重启后自动核对并继续原切换，明确失败按 Q2 返回 A，结果未知只核对而不重放写入（Q5 已确认）。
  - Q9 待回答：推荐主动退出时提供继续等待／取消切换并退出；取消后走现有退出流程并提示任务可能中断，取消结果未知则保留待核对状态。
- Q8 待回答：推荐概览设备区增加“切换 Hive”，用紧凑列表展示已保存的地址、归属和当前 Hive，提供添加地址；配对／切换进度留在同一区域。
- 目标 Hive 的状态恢复、凭证失效处理及首次配对未决：结合上述选择细化。

## 验收场景草稿
