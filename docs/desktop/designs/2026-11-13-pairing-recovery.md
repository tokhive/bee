# 设备配对的结果核对与安全重配

状态：2026-11-16 已批准 8 点重绑方向、Q9 网页受限恢复授权及 Q11 到期/取消后的停单规则；最小技术契约待审，未实施，不包含强制中断任务。已确认选择来自[讨论记录及后续范围反馈](2026-11-13-pairing-recovery-discussion.md)；下述跨端协议仍为提案，不另写实施计划。

## 最新批准范围

以[2026-11-16 批准的 8 点方向](2026-11-13-pairing-recovery-discussion.md#2026-11-16批准的-8-点重绑方向)为当前范围。本轮补充下文“无旧凭证的最小恢复契约”，仍为待审设计；Q11 的取消与到期后接单行为已确认。后半部旧接口、表结构和协议保留为参考提案，不因方向获批就全部进入实施。旧排空/退出记录、遗留 running 和缺证据的未结算任务可能持续阻塞；重绑总等待上限未获证明，不承诺网页登录后立即完成重绑。

## 要解决的问题

Hive 已创建配对，但 Bee 没收到可接受的回包，就可能丢失查询原配对所需的凭据。重启仍读取同一笔未知记录，无法继续，也不能安全地再创建。当前本机旧记录正属于这个场景，见[部署证据](../evidence/2026-11-13-local-deployment/README.md)。

本轮同时处理旧记录和未来故障，覆盖首次配对、凭据失效后的重新绑定，以及切换 Hive 时准备目标 Hive。配对继续使用网页确认归属和替换设备；完成配对不自动接入 AI 账号或开始贡献。

| 场景 | 现在 | 修改后 |
| --- | --- | --- |
| 未来创建回包丢失或校验失败 | 可能丢失配对凭据，停在创建未知 | 发送前已保存原申请，自动核对并继续同一笔配对 |
| 当前旧记录没有配对凭据 | 只能保留阻塞，管理员核查不能变成 App 回执 | 用原设备秘密核对；用户发起重新配对后，Hive 安全结束旧申请，再生成新码 |
| 旧配对其实已完成绑定 | 后续过期可能掩盖成功 | 恢复原成功事实，并另查设备当前是否仍有效 |
| 重新配对中崩溃 | 缺少完整跨端恢复路径 | 按原意图核对已做到哪一步，再安全续办 |
| Hive 离线或证据矛盾 | 缺少明确恢复动作 | 显示本次原因；离线可继续核对，矛盾记录交管理员 |
| 核对长时间无结果 | 容易持续等待 | 每轮最多 60 秒，停止后显示状态和“继续核对” |

## 核心边界

后续讨论收窄建议范围：绑定有效且 Bee 能正常连接时，无需重新绑定，本轮不增加主动重置正常绑定的功能。配对结果未知先核对，已成功则恢复；无法继续的配对安全结束后重配；凭证失效或确实无法恢复时才重新绑定。网络、地址和版本故障须处理对应原因。

**已纳入、尚未实现的场景**：Hive 仍认为绑定有效，但 Bee 的设备凭证丢失或损坏，实际无法连接。先尝试恢复；确实无法恢复时，通过 Hive 网页确认旧设备，再按下文最小恢复契约处理阻塞并替换。原秘密核对协议只适用于仍持有原秘密的分支，不承担秘密丢失的鉴权。完整技术设计仍待确认，不构成实施授权。

查询原申请、重放原申请、创建新申请是三种不同动作。新配对须来自用户明确意图；Q5 的一次“重新配对”可以授权先安全结束旧申请，再创建一笔新申请。

超时、一次查无记录、身份查询拒绝、本机到期倒计时和旧接口的单独 `410`，都不证明旧请求不会再生效。没有安全结束回执时，保留原 Hive、秘密、申请和证据，不通过删除文件、换地址或换秘密绕过。

每个 Hive 仍按已确认的 URL 归一化规则独立保存。恢复不改变当前 Hive，不推进另一个 profile；同一 URL 换库的识别限制仍按 [ADR 0001](../../adr/0001-hive-url-scope.md) 保留。

## 本地记录丢失或损坏的入口

Q10 已确认：本轮覆盖整个 Hive 本地记录丢失且可在网页确认原设备的情况。Q9 已于 2026-11-16 批准：网页登录并明确确认旧设备后，允许 Hive 服务端无需 Bee 旧凭证核对和处理该设备的恢复阻塞；权限限本次恢复，不含接单、普通账号修改或强制中断任务。

恢复检查须独立于正常配置加载：已登记 profile 目录缺失、配置不可解析、凭证字段损坏、恢复记录不可读时，App 仍能展示已确认的故障和恢复入口。区分文件不存在、内容损坏、权限/路径不安全；保留现存文件，不把读取失败当成从未配对，不自动删除或绕过文件安全检查。

先从已有受保护记录寻找可验证的原凭证。只有原 Hive、身份及操作上下文一致，且 Hive 接受该身份时，才能修复原配置；身份丢失而凭证可用时优先恢复身份。恢复原绑定不清空旧账号操作、运行记录或未决配对，也不自动开始贡献。Hive 没有原凭证明文可供下载。

无法恢复原凭证时，由用户确认 Hive 地址，经该 Hive 网页登录确认账户和原设备。Hive 当前每个用户只有一个有效设备，沿用网页展示确切设备 ID 并明确确认替换的方式；名称相同不构成身份依据。残存的可信原 Hive、owner、设备 ID 与网页结果矛盾时暂停核对，不能以新的网页选择覆盖旧证据。无任何旧身份信息时，网页确认确定恢复对象，但不能据此声称已恢复丢失的本地历史。

为恢复保存的新记录须使用独立受保护的暂存位置；不抢先覆盖旧文件或改变当前 Hive。可确定原 profile 时关联原 profile；地址或索引归属不能唯一确定时继续核对。完整本地记录丢失不会豁免 Hive 侧的任务、结算、竞争替换及旧操作检查；残存但无法核实的未决请求保持阻塞。其他 Hive 记录和官方 AI 客户端登录不受影响。

该入口与下文契约共同构成待审设计，不是现有代码已支持的声明。

## 无旧凭证的最小恢复契约（本轮待审）

只扩展现有配对、设备排空、运行退出和结算能力。不增加重置中心、通用历史恢复平台或独立后台服务。沿用下文已确认技术栈；新增的只是本次恢复授权、必要持久事实及替换专用处理，不在本轮确定所有 URL、表名和字段布局。

### 网页确认先建立受限授权

1. 用户在 Bee 发起“重新绑定 Hive”。Bee 先按前节尝试恢复原凭证；失败原因确属凭证或记录故障时，在受保护的暂存位置保存本次申请标识、新凭证及核对所需秘密，再发送申请。首次配对和有原秘密的旧申请仍走各自核对分支。
2. 用户登录 Hive 网页，确认页面显示的确切旧设备及本次申请。Hive 服务端从登录会话取得 owner，核对旧设备、申请和候选新凭证的关联；不能由 Bee 自报 owner 或设备名替代。网页确认只授权本次恢复，不立即撤销旧设备。
3. **确认入口允许记录既存阻塞**。当前 `ConfirmPairing` 在存在 drain/pending retirement 时直接拒绝，必须在此增加受限恢复分支，保存本次授权及待核对的原操作关联；普通替换继续保留原保护。允许进入核对不等于忽略阻塞，不能仅把兑换接口改成网页登录鉴权。
4. Hive 在同一设备串行保护下保存授权和停止派新任务的事实，与最终派单检查共同生效。已经获准派发的任务纳入等待集合；以后新派单被拒绝。旧连接可继续完成已有任务，此时不为重绑断开连接，不启动会先断连接的旧退出 POST。
5. Bee 用本次申请的持有证明查询或请求推进，Hive 从已保存的网页授权解析对象和权限；这个证明不能调用普通设备、账号控制或接单接口。Hive 只保存秘密摘要。只读查询不推进恢复，推进请求按原编号和原参数幂等处理。

同一旧设备同时只能有一笔持有处理权的恢复。重复确认原申请返回原事实；另一申请、设备已被别人替换或身份矛盾时报告冲突，不自动转向后来设备。旧操作与恢复申请的关联须逐笔核对；“这都是该用户的数据”不足以证明可以结束它们。

### Hive 如何处理旧操作

Hive 以已保存的原请求和结果为依据，Bee 不必重新提交已经丢失的旧秘密、lease 或账号指纹。下表是新增受限处理分支的规则，不能以管理员或网页登录身份直接调用旧接口替代。

| 阻塞对象 | Hive 服务端的处理及结束条件 | 不能放行的情况 |
| --- | --- | --- |
| 排空处于 draining/ready | 保持停止新派单；核对全部已接收任务、终止未知及结算。条件成立后，记录替换专用的结束动作，隔离旧写入并确认旧连接退出；保留原请求与完成证据 | ready 只说明观测到无任务，不等于已 released；epoch、lease、任务计数与持久事实矛盾均保留阻塞 |
| 排空处于 sealing/sealed | sealing 按已接受动作及其 epoch 续办，不另造封存动作；sealed 验证原回执和旧连接退出事实。新增“由本次替换结束占用”的结果，不要求旧设备重新上线 | 不伪造普通 release 所要求的新在线 lease，不把替换结束写成“旧设备已重新启用”；原回执与当前事实矛盾转人工 |
| 运行退出处于 pending | 先核查任务及结算，再按 Hive 保存的原请求核对 pending/epoch、供给准备、设备归属和账号指纹，处理原操作允许结束的准备记录并记下 retired 结果 | 不直接重放现有先断连接的 POST；不清别的 pending，不进行普通账号修改；账号、准备记录或终态矛盾保留原阻塞 |
| 未完成配对 | 仅处理能可靠关联到本次恢复对象的原申请。已兑换保留成功并核对当前身份；未兑换且允许结束的申请保存不可再生效的关闭事实；本次新配对不能被一起关闭 | 同名设备、单次查无记录、配对过期均不能证明可以关闭；另一笔竞争恢复不自动取消；无法归属的 legacy 请求转人工 |

替换专用结束与普通恢复接单是不同结果。原 drain、退出、配对的请求和既有终态保持不变；新增关联结果说明它为何不再阻止这一次替换。旧检查不能全局改成忽略 drain/pending：只允许持有授权的恢复在核对精确原操作及结束证据后继续。无法解释的多个占用同时存在时按矛盾证据处理。

### 任务与结算：继续条件和人工边界

| Hive 查到的事实 | 如何继续 | 何时需要管理员 |
| --- | --- | --- |
| 任务仍在运行 | 保留连接及原任务，由既有执行路径记录结束；Hive 复查持久结果后继续 | 完成写入失败导致 running 残留且无可靠结果时转人工，不用年龄推断结束 |
| 已结束但终止未知 | 仅沿用现有针对特定终止未知记录的执行预算判定，并复查其他条件 | 不能把该预算套到 running/unsettled；实际配置及适用证据无法核实时仍说明未知 |
| unsettled 且有完整有效结算证据 | 由现有后台结算恢复处理；本次恢复读取其结果，结算成功后再判断是否可替换 | 临时错误继续既有恢复；持续错误可交管理员排查，不承诺固定完成时间 |
| 结算证据缺失、无效或互相矛盾 | 保留原任务、账目和阻塞，指出缺失或校验失败的证据 | 立即提供诊断摘要，不让用户反复点重试期待证据凭空出现 |
| 任务和结算均已满足，只有旧操作占用 | Hive 按上一表续办或结束原操作，记录结果 | 仅在原操作归属、账号或准备记录矛盾时转人工，不要求旧 Bee 重连 |

本轮不新增“按年龄清理 running”，也不把重启 Hive 作为用户恢复步骤。若后续要自动修复残留 running，必须另行证明执行已停止、结果与账务如何恢复，不能借本次授权直接写 failed/completed。

管理员接收的诊断包含 Hive、旧设备和恢复编号、阻塞操作/任务编号、最后核对时间、实际失败点及所需证据，不含秘密和配对码。管理员可以排查持久化错误、核对原始执行和结算材料；只有原规则可验证的证据恢复后，本次申请才继续。现有管理员结算接口同样拒绝无效证据；本轮不新增“管理员强制放行”按钮。始终拿不到证据时，重绑可能无法完成，需要另行决定人工修复方案。

### 旧连接、迟到请求与最终替换

停止新派单不等于立即隔离所有旧写入。第一阶段允许已有任务正常完成，禁止新增冲突的配对、排空、退出和账号控制操作；已受理控制写入须完成并重新读取其结果。第二阶段只有任务、结算和关联证据均满足后，才能隔离旧运行写入并处理旧连接。

复用现有设备行锁、runtime gate/epoch 和连接控制锁；在实际写入点重查设备有效性、本次授权及原操作归属，覆盖已经通过 HTTP 鉴权但尚未写入的请求。已有 pending 或封存动作拥有的 epoch 必须先按原记录续办，不能先换新 epoch 再把原操作视为无主记录。配对、排空、运行退出本身不都经过普通 RuntimeFence，须分别纳入检查，不能只换 epoch 或关闭 WebSocket。

旧连接处理必须指向保存并核实的旧设备/运行实例；发送 cancel 后等待对应 done，不能把发出取消当作退出。等待不得持有连接退出所需的 controlMu 或连接表锁；重启后复查持久屏障和当前注册事实，不能因内存连接表为空就跳过任务检查。记录若已证明原连接退出，后来却出现不符合屏障的连接，按完整性异常停止，不把它解释成正常重连。

最终沿用“撤销旧设备、创建新设备”的同一事务，复查旧设备仍是网页确认对象、任务/结算条件和精确旧操作结束证据，同时保存本次恢复与新旧设备、配对成功结果的关联。旧占用的解除与替换必须始终由持久停止派单保护覆盖，不能出现先放行旧设备、再提交替换的间隙。保留历史任务和账目；任何重放只能取得原结果，不得撤销后来设备。

### 中断续办、到期与取消

Hive 至少保存：本次申请及参数关联、网页确认的 owner/旧设备、关联旧操作、停止派单及旧写入隔离事实、已完成步骤和原兑换结果。Bee 至少保存：原 Hive、本次标识及持有证明、新凭证、用户意图和已验证结果。具体表结构与接口名尚未定稿；必要事实不能因省表省字段而丢失。

Bee 回包丢失、重启或保存配置失败后，先核对同一次申请；Hive 已替换成功时，Bee 只续存原结果并验证当前有效性，不重复替换。恢复暂存记录本身再次全部丢失时，也不能无凭据重放或凭设备名接管已有申请；须经网页登录核对原申请，无法证明关联则保留阻塞，不承诺找回全部历史。

Hive 的旧操作处理由已授权的推进请求执行，既有结算后台照常工作；本轮不增加全功能恢复调度平台。Bee 关闭后保留远端事实，下次启动先核对再续办。沿用 Q8 的观察轮与临时查询重试预算，60 秒仅限制一轮自动核对，不是任务、结算、授权或停止派单的到期时间。

**Q11 已确认的行为**：配对码过期、页面关闭和观察轮结束不自动解除已确认恢复的停止派单，也不丢弃原申请；用户主动取消停止后续替换，但不自动恢复旧设备接单，也不撤回已完成的旧操作处理。以后恢复接单仍须用户明确操作并通过原有检查，因此旧设备可能持续停单；本轮不扩展无旧凭证的接单权限。

相应技术提案：过期码不可再用于新授权，后续沿原已确认申请核对。Bee 先保存取消意图，Hive 持久接受后停止尚未接受的后续替换，保留已发送步骤的核对及已完成结果；取消尚未送达时不能显示为远端已取消。取消与兑换竞争时以同一串行保护下先提交的事实为准，已完成兑换不能显示为“未发生”。

### 本轮必须证明的边界

以下为将来实现的验收约束，尚未执行：配置/profile 损坏仍能进入；有可信原凭证则恢复原绑定；网页确认能接纳既存 drain/pending 而不放过冲突；旧设备始终离线仍可在证据齐全时完成替换；旧任务在等待阶段不被重绑断开；sealed 不要求新 lease；残留 running/缺失结算证据明确阻塞；配对码过期或取消不形成自动恢复派单的空窗；已鉴权迟到写入、连接注册、取消及竞争替换不会越过屏障；回包丢失/重启/保存失败只完成原兑换一次。

Bee 沿用现有恢复区域展示具体阻塞对象、原因、最后核对时间及有效下一步：任务或有效证据的结算仍在推进时可继续核对；证据缺失或矛盾时提供管理员诊断；原绑定成功但本地保存失败时说明续存原结果。停止观察后停止进行中动画，不显示虚假剩余时间。重绑成功不自动接入 AI 账号或开始贡献。

## 旧配对协议参考提案的地位

以下从“未来新配对”至原验收条件，保留原秘密仍在时的恢复思路和未来请求可靠性保障，均未整体批准。其秘密鉴权、普通 release、旧配对 TTL 和锁顺序不能直接承担上文的无旧凭证分支；完整契约还须按两条分支统一审查。尤其“关闭原申请”不得隐式撤销本次网页恢复授权或自动恢复接单。保留原结果、防迟到生效、发送前落盘等保障继续成立；不因保留参考文本就承诺所有旧接口、表和协议细节进入实施。

## 未来新配对：先记住原申请，再发送

1. Bee 使用系统安全随机源生成独立 `attempt_id`、配对 token 和用户码，与原 Hive、设备秘密、规范化设备名及原绑定版本一并私有持久保存。随机或保存失败则停止，不发送。
2. 新协议将 `attempt_id` 发给 Hive。每次真正生成新码使用新 attempt；查询、重启和原请求重放使用原 attempt 和原参数。现有恢复操作编号作为父意图编号保留，不再把它当作每次远端配对的编号。
3. Hive 在同一事务中记录原参数摘要、创建结果及配对行。相同 attempt、相同参数返回原创建回执；参数不同则明确冲突。创建回执中的受理时间、有效期和结果不可刷新，实时进度通过状态查询取得。
4. 创建回包丢失或格式不合要求时，Bee 保留本地已生成的 token/code，向固定的原 Hive 查询原 attempt。确认支持新协议且原用户意图仍有效时，可以补发原 attempt；同一观察轮最多补发一次，仍未知则继续查询或等用户继续核对。
5. 网页仍显示设备和账号，确认归属及要替换的设备。Hive 校验批准、旧设备任务和结算状态后才兑换；新协议的重复兑换返回原兑换回执，并可补做原连接退出，不重复撤销或创建任何设备。
6. Bee 核验当前设备身份和本地绑定上下文后保存配置。保存失败只续存原成功结果，不再次创建或兑换。

配对 token 沿用 `beep_` 加 32 字节随机数的 URL 安全编码；用户码沿用 5 字节随机数、8 字符的现有字母表和 `XXXX-XXXX` 展示格式。用户码先去连字符并转大写再取摘要，Hive 首次受理时决定有效期。

全库 token/code 唯一约束继续生效，包括历史配对。碰撞必须形成已提交、可查询的拒绝结果；同 attempt 不换参数重试。数据库提交结果不明仍是未知，不能伪造为已拒绝。碰撞后的新申请由用户明确发起。

## 旧记录：核对原秘密，再安全结束

Bee 已在旧创建前保存了 256 位设备秘密。恢复端点验证其格式，由服务端计算摘要关联原配对和设备；单独提供摘要不算证明。此认证只允许核对和结束本秘密对应的配对，不能冒充已批准设备，也不能替代网页登录。

升级后先自动只读核对旧记录；仍有配对 token 时可以继续原配对。没有 token 且尚未绑定时，显示“重新配对”入口。用户点击后，先持久保存重配意图和关闭请求编号，再请求 Hive 安全结束旧配对。

| Hive 核对到的事实 | 处理 |
| --- | --- |
| 已有匹配的有效设备 | 恢复该身份；同秘密遗留的其他未完成配对在安全关闭事务中结束，不再生成新码 |
| 从未完成绑定，尚有一笔或多笔旧配对 | 安全结束全部关联未完成旧配对；保存回执后创建新 attempt |
| 没查到配对，原创建仍可能迟到 | 写入持久关闭标记，保证后来到达的旧请求也被拒绝，才确认安全结束 |
| 曾完成绑定，之后设备又被替换或撤销 | 保存历史成功，展示当前已失效；由用户进入既有重新绑定流程，保留原运行与账号操作检查 |
| 绑定或归属证据矛盾 | 保留记录并阻塞，给管理员诊断摘要 |
| Hive 离线或返回不可验证 | 保留待核对状态，显示本次原因，提供继续核对 |

历史成功与设备当前有效性分开表示，不能用原成功回执声称撤销后的设备仍可连接。重新绑定保留原 owner 变化确认；已撤销设备的秘密因全库唯一约束，不能用于创建另一台设备。

“已成功但本机未保存，随后又撤销”需要新增恢复分支：将 Hive 已核对的历史身份、归属、原申请及撤销证据私有保存为“已核对、当前失效”的终态，归档原配对尝试，释放的仅是原配对槽位。历史身份作为重新绑定上下文保留，不冒充实时身份校验通过；本轮扩展重新绑定前置条件，使本机尚无活动身份时也能依据该证据进入确认。实际采用不同 owner 仍须原确认，旧 scope 的未决账号操作和运行保护仍须先处理。新绑定成功前保持不可运行。

## Hive 的持久保证

沿用 PostgreSQL，增加配对专用的持久作用域记录和尝试账本，并为现有配对保存关闭事实及兑换设备关联。保存原参数摘要、受理/拒绝回执、关闭回执、兑换结果及关联关系；服务器只存秘密摘要，不增加可解密 token/code 存储或密钥配置。

- **同一秘密串行处理**：以服务端计算的设备秘密摘要定位并锁定作用域。创建、网页确认、兑换、安全关闭都遵守相同锁序：作用域 → 配对/尝试记录 → 必要的旧设备锁和现有控制锁。按 token/code 先读到摘要后，取得共同锁还要重读验证；只读预查不构成最终许可。
- **新编号不绕过旧占位**：同一秘密最多一笔可推进的配对；换 attempt 也须先结束原未决申请。已有设备时恢复原身份，不能另建第二台设备。legacy 关闭仅作用于无编号历史申请，新协议关闭仅作用于匹配的原 attempt。
- **永久封住旧入口**：安全关闭旧申请时保存 `legacy_closed` 及原回执，阻止无编号创建及 legacy 配对继续确认/兑换。配对行须能区分 legacy 与新 attempt；新 attempt 仍通过共用网页确认，按自己的关闭状态校验。新 attempt 不清除此标记；首次创建也须确认旧申请已可安全收尾并封住无编号入口。存在未决旧配对时拒绝直接新建，引导核对或安全结束。
- **封住尚未到达的申请**：新协议关闭原 attempt 时，即使原创建还没到达也保存其终态。未曾受理创建时，后来到达的 begin 返回封闭拒绝；曾受理后关闭时，begin 重放仍保留原受理回执，并单独返回当前已关闭。两种情况都不能重新插入配对或兑换。
- **成功不能改成取消**：关闭与兑换在共同锁内决定先后。兑换已提交则保留成功并返回关联身份；关闭先提交则以后不能兑换。关闭未完成替换不得撤销或退役原设备。
- **所有读取理解关闭**：网页进度、竞争替换、候选供给、API 派单、设备排空和封存判断一致排除已关闭配对。原设备是否接单仍取决于暂停、其他屏障和正常条件。
- **跨秘密竞争照常保护**：同用户的另一台设备可能使用不同秘密；继续保留现有旧设备行锁、显式替换确认、任务与结算检查，不能拿新作用域锁替代。
- **证据不自动过期清理**：本轮保留最小操作账本、终态和关闭标记；配对码的有效期不等于恢复证据保留期。不设会让迟到请求重新生效的清理任务。

迁移不把缺少记录、过期或拒绝的旧身份强行补成失败。旧已兑换配对通过设备摘要及 owner 核对关联设备；关联矛盾保留原记录并阻塞，不能猜测补全。

兑换事务同时保存新设备 ID 和原被替换设备 ID。提交确认丢失时，核对或重放仍恢复成功事实；若原连接待退出，由原兑换动作幂等补做。纯状态 GET 只报告收尾进度。补做只针对持久记录中的原设备，核验归属、已撤销和新旧 ID 不同；不得按后来当前设备寻找目标。保留现有连接注册的设备行共享锁与先注册后解锁顺序，防止撤销后的迟到注册。发出 cancel 不算退出，须释放控制锁和连接表锁后核对原 entry 的 done；超时保留“成功、待收尾”，不重新撤销或创建设备。

## 新协议的接口职责

以下为新增契约；既有接口继续服务旧客户端，并接入共同关闭保护。实现时将类型固定在 Bee 的 `beewire`，Hive 引用固定 Bee 提交，不依赖未合并分支。

| 接口职责与拟用路径 | 认证及结果 |
| --- | --- |
| `GET /api/bee/pairing-recovery-capabilities` | 首次配对前可访问，明确返回恢复协议版本及支持的新建、核对、幂等兑换、旧申请关闭能力；不返回用户信息 |
| `POST /api/bee/pairing-attempts/{attempt}/begin` | 原设备秘密 Bearer；请求含规范化设备名、本地预存 token/code；按秘密与 attempt 隔离，返回不可变创建回执 |
| `GET /api/bee/pairing-attempts/{attempt}` | 原设备秘密 Bearer；返回原创建事实、当前进度、历史兑换身份、当前有效性及关闭证据；不返回原秘密 |
| `POST /api/bee/pairing-attempts/{attempt}/redeem` | 原设备秘密 Bearer，核验对应原申请及网页批准；重复调用重放原兑换结果并补齐原连接退出 |
| `POST /api/bee/pairing-attempts/{attempt}/close` | 原设备秘密 Bearer；匹配原申请参数，返回已关闭或原成功；原申请未到达也可持久封闭该 attempt |
| `GET /api/bee/pairing-legacy` | 原设备秘密 Bearer；核对全部关联旧申请和设备事实，不把查无记录当作安全结束 |
| `POST /api/bee/pairing-legacy/close` | 原设备秘密 Bearer及持久关闭编号；在同一作用域下核对原结果，安全关闭并保存原回执 |

尚未绑定或已撤销的秘密可以证明申请持有者，因此这些端点不调用只接受已绑定设备的 `currentDevice`。鉴权每次都执行，包括结果重放；作用域由后端计算，不接受前端指定别人的摘要、owner 或本地文件路径。

现有 `RuntimeFence` 也会在 handler 前要求已绑定设备认证：须精确识别上述新协议路由，交给专用秘密持有认证；不能只改 handler，也不能将整个 `/api/bee/` 免鉴权。网页确认继续要求登录用户和原有账号核验。

新建回执和实时状态分开验证。旧 `initial=true` 校验要求“此刻尚未到期且 pending”，不能用于已批准、过期或已兑换后的历史回执。状态优先识别已兑换、已关闭的事实，再处理未兑换配对的过期。

安全查询当前状态只返回本作用域事实；一次未查到不允许更换 attempt。参数冲突、已关闭、已兑换、当前失效等结果使用明确结构化原因，不靠错误文案或 HTTP 状态推断是否重试。沿用仓库现有 `net/http` 响应机制，不引入 Gin 或其他框架。

## Bee 的恢复与取消

继续使用现有私有原子写入：受限权限、防符号链接、临时文件写入、文件同步、同目录替换和目录同步。每个 Hive 的父意图、attempt、关闭回执和原绑定上下文独立保存。旧文件先保留原件，再迁移；缺字段或损坏不能当作从未发送。

新申请的顺序是：旧关闭/终态回执已持久保存 → 新 attempt 及完整原参数已持久保存 → 标记发送 → 网络请求。多个文件的替换不是一个事务；重启逐项核对已有归档和活动指针，一致才续办，不能因中间崩溃再次生成 attempt。

重新配对意图在重启后保留，关闭或创建结果未知均沿原编号核对。最新的显式取消意图优先：取消 A → B 后停止新建或兑换 B，已发送操作仍保留查询入口，下一次用户选择 B 时先核对原记录。不能自动恢复父切换，也不能宣称远端配对已取消。已完成的 B 绑定继续保存。

关闭弹框或页面只改变展示。App 正在退出时停止新增发送；未取消的操作可在下次启动按原意图继续。配对恢复保留既有未决账号操作、脏运行保护、绑定版本和 owner 确认，不能清记录以便重绑。

## 页面与自动核对

沿用现有配对页、重新绑定区域和切换目标步骤，保持紧凑布局：一条主要状态、具体原因及一个当前主动作；补充诊断折叠。首次配对与重新绑定继续使用各自正确的桌面接口，共用核心恢复能力。

原生桥需提供带原操作编号和预期修订号的显式重配确认；关闭中、关闭结果未知和已安全结束使用结构化状态，核对暂停另存为观察状态。旧界面不能按错误文案猜测可否重配，前端也不能指定私有路径或越过目标后台的准备权限。

| 当前事实 | 展示及动作 |
| --- | --- |
| 正在核对原申请 | 显示正在核对及实际阶段，禁用重复发起 |
| 原配对可继续 | 显示原配对码、有效期和网页确认入口 |
| 旧记录缺少 token，尚未成功 | 说明原配对无法继续；支持安全关闭的 Hive 提供“重新配对” |
| 用户已发起重配 | 显示核对旧结果、结束旧配对或生成新码的实际阶段 |
| 一轮检查结束或重试耗尽 | 停止进行中动画，保留状态、最后结果和“继续核对”；不表示业务失败 |
| Hive 不支持新协议 | 明确说明需要升级 Hive 后才能生成新配对码 |
| 记录矛盾 | 显示具体核对失败点及诊断导出入口，由管理员核实 |
| 配对成功但设备现已失效 | 说明实际撤销事实，按已有保护提供重新绑定入口 |

状态查询沿用 Hive 的现有配对间隔（默认 2 秒）及统一调度器。每轮最多观察 60 秒；一次临时查询失败后最多自动重试 3 次，最多共 4 次请求。鉴权、参数或完整性错误立即停下。重启不重置原观察期限、失败计数或原请求补发预算。用户“继续核对”才开启新一轮，原业务编号不变。

上述查询重试仅适用于纯结果读取。现有 `device_status` 和恢复 status 可能推进兑换及保存，不能作为无副作用 GET 套用重试；核心须将结果读取、已授权动作推进和各自预算分开处理。

一轮核对停止不释放操作，也不证明配对失败或过期，不能据此额外生成新码。已授权安全重配的流程在恢复条件和预算允许时继续原步骤。纯查询不擅自提交首次申请；新协议的原键重放须明确分开记账，不能套用查询重试次数。

“继续核对”不另起重配意图，也不生成超出原授权的额外 attempt；若用户之前已发起重配，它可以在确认旧申请安全结束后，完成原意图内尚未提交的一笔新申请。

错误保留本次环节、origin、实际响应码/字段失败点及时间，先展示具体原因；秘密、token、完整用户码和含码 URL 不进入错误、日志或诊断。配对网址由固定 Hive 同源校验后显式打开；禁重定向，远程只允许 HTTPS，HTTP 只限回环。

## 技术栈与升级边界

| 技术 | 用途与理由 | 状态及版本 |
| --- | --- | --- |
| Bee Go 核心、标准库随机源与摘要 | 生成及私有保存原申请，执行跨端核对 | 沿用、已确认；Go 1.27.3 或仓库更新后的最低版本 |
| Rust/Tauri | Hive profile 隔离、父切换/退出协调和原生桥 | 沿用、已确认；当前 Rust/Cargo 1.94.0，依赖锁文件固定 |
| React/TypeScript | 现有页面状态与恢复动作 | 沿用、已确认；Node 24.22.1 构建基线，依赖锁文件固定 |
| Hive Go、PostgreSQL | 持久受理、关闭、兑换事实及事务串行化 | 沿用、已确认；现有 PostgreSQL 18 部署 |
| 配对恢复协议版本 1 | 新申请编号、结果核对与安全结束 | 本次新增契约，随本设计待整体确认；不新增依赖或服务 |

选用 Bee 预存随机 token/code，以沿用服务器只存摘要的边界。备选为 Hive 加密保存原回包，但会引入新的密钥配置、备份和失钥恢复；当前没有可直接复用的通用在线密封设施。仅加只读查询无法阻止迟到写入；只修未来编号无法救回本机旧记录。

新建、重建配对先协商能力，不支持则引导升级 Hive；已有有效绑定继续正常使用，旧配对仍可安全完成的部分继续核对。不向旧创建接口直接追加字段，旧 Hive 会严格拒绝未知字段。

部署沿用 Hive 的单实例约束：停止旧实例、备份、迁移并启动新版，最后安装匹配 Bee。旧二进制不认识关闭标记，不能与新版混跑或写入新库；数据库迁移锁不能代替停旧服务。数据库回滚/替换须连同恢复事实处理，不能通过旧库缺记录证明旧请求未发生。

## 验收条件

实现前先为权限、持久化与并发边界写失败测试；使用独立数据库/schema、私有临时配置和合成秘密。以下是待执行验收，不能表述为已通过。

| 场景 | 必须证明 |
| --- | --- |
| 与当前本机记录同形的旧未知创建，无 token | App 能取得安全关闭回执、保留旧证据、显示新码，不改真实数据来伪装恢复 |
| 创建已提交但响应丢失、格式错误，或回包后本地保存失败 | 多次重启仍只有一个原 attempt/配对；原秘密不丢，能查到原结果 |
| 原请求迟到、与关闭并发 | 关闭前已成功则恢复成功；关闭后迟到的创建/确认/兑换均不能生效 |
| 同键并发、不同参数、不同秘密 | 原键只执行一次；参数冲突明确；不同秘密不能读取或关闭彼此结果 |
| token/code 碰撞及数据库提交结果不明 | 碰撞拒绝可持久查询，未知提交保持未知；不在已失败事务中伪写拒绝 |
| 兑换响应丢失、之后配对过期或设备被替换 | 保留原成功身份与当前有效性；本机从未保存身份也能进入受保护的重绑，重复兑换不产生第二次接管 |
| 兑换已提交但旧连接收尾未执行 | 按原持久目标补做退出，无迟到注册，无持锁等待死锁，不误关后来设备 |
| 多笔 legacy、已批准替换、不同秘密竞争同一旧设备 | 可安全关闭的统一关闭；原设备不被错误撤销/停单，任务和结算检查仍生效 |
| 每个落盘边界崩溃、写入/同步失败 | 无保存则不发送；有保存则沿原记录续办，旧终态不覆写，新 attempt 不重复生成 |
| 核对 60 秒、失败重试及重启 | 持久预算不重置；停止动画并给实际下一步；继续核对不另起意图或额外 attempt，可完成原已授权重配 |
| A → B 目标配对中取消、退出、稍后再选 B | 父取消后无新增 B 写入；已有远端结果保留、可核对，A 和 B 记录不混用 |
| 旧 Hive、离线 Hive、归属矛盾 | 各自显示实际原因与可用动作，无绕过入口，无秘密泄漏 |
| 升级后真实本机恢复及 A → B → A | 部署匹配版本后执行实际 App 联调，记录用户网页确认及结果；合成测试不冒充真实通过 |

实施时同步首次配对设计、桥协议、页面主预览与历史快照，以及 Hive 的接口、迁移和部署文档。本设计相对旧文档中“无 token 只能阻塞、未知 POST 一律不重发”的增量，仅在新能力确认并遵守原键/原参数时生效；旧请求仍不能直接重发。
