# 桌面设备配对与恢复

Bee 使用浏览器确认设备归属，并由 Go 保存独立设备凭据。设备绑定、设备在线和贡献运行是不同状态：绑定核验后可自动连接 Hive，接入账号及开始贡献仍需明确操作。

## 首次配对

1. 按[构建说明](../../desktop/README.md)打开当前原生 App；确认未配置且无未完成事务后，显示“连接 Hive → 绑定设备”向导。填写自己的 Hive 地址和设备名称，再点击“继续绑定设备”；不预填公共 Hive 地址。
2. 点击“打开 Hive 确认网页”，在 Hive 确认设备归属；Bee 自动检查原事务、确认身份并保存本机配置。网页批准本身不等于绑定完成。
3. 本会话绑定成功后停在完成页，点击“前往接入 AI 账号”进入[现有账号页](ai-accounts.md)，也可选择“进入概览”。导航不自动登录、接入、开始贡献或解除暂停。

首次绑定完成前不显示普通概览、账号或完整设置页，也没有“稍后设置”；故障诊断在向导内可达，返回保留本会话输入。重新打开时恢复原配对阶段，不重复创建或兑换；若首次可信观测已经完成绑定，进入概览。读取失败不能解释为首次使用。已有绑定的凭据恢复仍保留完整导航。

精确页面、恢复许可和验收要求见[首次启动向导规格](first-launch-design.md)；本轮验证证据见[验收记录](evidence/2026-11-12-first-launch/validation.md)。

## 保存与恢复

Go 将设备配置保存到系统用户配置目录下 `tokhive/bee-desktop.json`，macOS 为 `~/Library/Application Support/tokhive/bee-desktop.json`。它独立于 CLI 的 `bee.json`，使用权限、锁、原子替换与读回保护。设备凭据和配对令牌不进入前端、日志或导出。

兑换结果未知时保留原事务并核验原凭据，不自动创建新设备。设备已被替换、凭据撤销或归属变化时显示原因；明确恢复通过现有 prepare／confirm／status 流程核对设备、运行和账号未决操作，不通过删除配置跳过保护。恢复完成后重新核验新设备和网络，不继承旧设备的账号选择或自动开始贡献。精确阶段和恢复边界见[桥协议](bridge-protocol.md)。

## 验证

受控设备／恢复测试使用本地 HTTP fixture 和独立配置；原生配对会修改指定 Hive 的设备记录，应使用明确的测试设备与账号。真实核心子路径已有证据，隔离 GUI 全链路及无 token 的未知创建恢复仍有缺口，见[当前验收状态](acceptance.md)和[交互台账](interaction-clarity-validation.md)。

执行入口为 `npm --prefix desktop run test:device`、Go 设备／恢复测试和 Cargo 原生契约测试。普通浏览器开发使用正式 mock 预览；真实配对必须在 Tauri 环境验收。
