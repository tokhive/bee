# Bee 原生自动服务

2026-11-05 实施，2026-11-06 完成登录回收补验。本文记录本轮已批准的原生行为与接口。实现及测试边界见[实施验证](../../.scratch/bee-native-interface/implementation-validation.md)；生产 Hive、真实官方登录、签名候选包和三系统验收不由受控测试替代。

## 用户流程

配对并核验设备 → 读取或登录官方账号 → 明确接入 → Bee 自动准备服务，平台保持暂停 → 用户逐平台恢复接单。无账号时先核验当前设备身份与原绑定，再显示等待接入；身份被拒绝、绑定变化或未决保护受阻时保留失败，不创建贡献 worker。日常没有总开始／停止按钮；服务受阻时提供核对、重试准备及设备／连接／来源的对应入口。关闭窗口继续后台，明确退出才回收本 App 的工作。

接入、主动重新登录和确认换号后暂停；同号后台刷新、重连、正常重新打开与网络应用保留 Hive 当前平台选择。暂停作用于同一 Hive 用户下的该平台。候选不自动接入，自动维护不等于允许接单。本机转发必须先就绪，再发布当前连接的授权；Hive 可在上传响应前立即派发请求。

主动登录只维护目标平台：确认暂停、隔离新请求、运行 owned 官方登录、核验来源，随后恢复原身份维护或等待明确换号。已有请求按其原上下文收尾；不承诺任务排空。不采用临时暂停后按旧快照自动恢复接单的流程。

## 前端接口变更

沿用固定账号、登录、供给、运行与网络命令，没有新增任意 URL、Shell 或凭据入口。布局、文案或状态呈现的修改通常只改前端；若新增动作、改变动作前提、增加事实或恢复能力，必须同步 Go DTO、Rust 验证、TS 严格解码、所有模拟响应与对应行为验证。

账号快照新增必需 nullable `login_maintenance`：

| 字段 | 含义 |
| --- | --- |
| `operation` | 原 authorize 操作，保留 ID、平台、修订、原结果和错误；中断未知为 `unknown`，仅 authorize 可使用该状态 |
| `phase` | pause_pending / paused / isolated / authorizing / reconciling / restored / confirmation_required / blocked |
| `source` | 原目录与存储类型，平台校验保持一致，不含凭据 |
| `started_at` | 原开始 UTC 时间 |
| `can_recheck` | 是否可只读核对原维护；不重新暂停、不重放官方登录 |
| `error` | 维护本身的公开错误，与原操作错误分开 |

历史维护通过 `account_snapshot(platform,refresh=true)` 核对。新实例没有原登录 job，不先调用其 `authorize_status`／`cancel`。原失败、取消或未知结果不会因维护恢复而改写为成功。维护未恢复时禁止新登录和恢复接单；confirmation_required 保留明确换号入口。暂停仍受原供给保护。

运行快照增加 `local=waiting`，以及必需 nullable `legacy_stop`：phase 为 processing/reconciling/blocked/completed，platforms 为最多两项的不重复平台数组，另有 error 和 can_recheck。后者表示继续已批准的旧状态转换：已提交步骤只 GET；从未提交的步骤修复并重验后允许首次提交。原操作仍未确认时不自动重放。

## 持久化与恢复

账号状态升级为 v3，严格兼容 v1/v2，首次替换 v2 前保存受保护备份。旧 `running=false` 且有选择的账号先统一确认平台暂停，转换完成后自动维护；仅当前已核验 scope 转换一次，不再覆盖后来的用户选择。不同 Hive／owner／device、来源异号、脏会话、dirty guard 或未决事务不会因迁移被清除。

登录 journal 原子保存与读回受独立锁保护，双平台不能互相覆盖。只有恢复完成证据持久化后才解除平台隔离。中断恢复须证明原操作的 owned 官方进程已经结束，并再次验证设备、来源和运行保护；损坏或保存失败仍保持受阻。Unix 的独立 guardian 统一处理取消及管理进程突死；只有 OS 确认原登录组无活成员后才释放恢复锁，清理未确认时保留锁及具体错误。它使用固定内部 CLI 和继承管道，不向前端协议开放任意命令。

网络应用依次证明停止、配置、生效读回和恢复。成功阶段必须推进运行修订；失败后的查询不得倒退。期间保存新配置、明确退出或安装更新会阻止旧流程继续恢复。保存值与实际生效值分别显示。

明确退出和已准入的更新安装先冻结新启动／恢复，回收 owned worker、登录组和 Bee 子进程；停止保存、session clean 和 child reap 分别核对。失败先保存具体诊断，再释放 App 单实例，不把回收尝试报告成干净完成。检查和下载更新不停止服务。

## 仍需补充

设备创建响应未知且没有取得原 token 的恢复由 ticket 10 独立跟踪。现 Hive 只存摘要，当前协议无法取回原 token；必须先明确原事务关联、授权与权威终态／恢复证据，不能用任意 token、清事务或重新创建代替恢复。

正式 App／WebView 的连续流程、真实官方登录与生产 Hive、三系统关窗找回和签名安装仍须绑定实际候选包验收。受控进程重启、HTTP／WebSocket／relay 和严格契约测试只证明其覆盖的真实模块与故障路径。
