# Bee 桌面产品需求

维护范围：当前四页产品及交互要求。实现和真实环境验收分别记录在[验收状态](acceptance.md)，本文不把目标要求写成已经通过的结果。

## 一、产品是什么

Bee 是 TokHive 面向 AI 订阅账号贡献者的桌面应用。用户将本机已有的 OpenAI／Claude 官方登录接入 Bee，明确接入账号，由 Bee 自动维护，并选择是否允许各平台接收新任务，并查看账号授权、订阅额度和不能接单的原因。

Bee 需要让用户清楚回答四个问题：**我接入了哪个账号？贡献有没有运行？这个平台能不能接单？遇到问题该做什么？**

贡献会使用所选 AI 账号的订阅额度。用户应在接入和开始使用前理解这一点，并能随时暂停某个平台接收新任务，或明确退出本机 Bee。

Hive 是与 Bee 配合使用的网站和服务。设备配对在浏览器中确认；用户、收益、钱包、报价、划转、提现等业务由 Hive 网站承接，Bee 提供“打开 Hive 控制台”入口。

## 二、目标用户与使用场景

| 用户／场景 | 需要完成的事情 |
| --- | --- |
| 首次使用的贡献者 | 安装 App、配对设备、接入 AI 账号、理解贡献影响并开始使用 |
| 已在官方客户端登录的用户 | 自动发现已有登录，确认使用哪个账号，减少重复操作 |
| 日常后台运行的用户 | 快速查看运行、连接、额度和接单状态，按平台暂停或恢复 |
| 授权失效或更换账号的用户 | 看清当前账号与新候选，完成重新登录或确认换号 |
| 遇到网络或运行异常的用户 | 找到具体问题、运行诊断、查看日志并导出脱敏报告 |
| 已通过其他方式运行 Bee 的用户 | 识别已有配置和运行归属，避免重复启动及误停止 |

首版面向 macOS、Windows、Linux。普通用户完成 Bee 的安装与日常操作应以图形界面为主；AI 官方登录由对应官方客户端／官方交互完成。

## 三、本次设计范围

设计覆盖四个一级页面：**概览、AI 账号、诊断、设置**，以及首次使用引导、账号详情侧面板、必要确认弹窗、系统通知和托盘／菜单栏交互。

当前约束是每个平台最多接入一个账号；同一 Hive 用户同一时间只有一个有效 Bee 设备。默认连接官方 Hive，高级设置允许自定义地址，同一时间连接一个 Hive。

以下内容不进入本次 Bee 界面：收益和资金页面、Hive 用户登录页、多账号池、独立模型市场列表、模型详情标签页、全局“全部暂停／全部恢复”、已注册账号的完整移除、等待任务完成后退出。不要为这些内容保留占位导航或“即将开放”按钮。

页面应完整保留接入、贡献、暂停、恢复、换号和异常处理能力。减少用户必须理解的日常按钮：账号读取、额度更新和过期报告核对在后台自动完成。

## 四、信息架构与通用框架

| 位置 | 内容与作用 |
| --- | --- |
| 左侧导航 | 概览、AI 账号、诊断、设置；图标配文字，选中状态明确 |
| 主内容区 | 页面标题、当前最重要的信息和操作；低频配置放入详情或设置 |
| 顶栏右侧 | 本机设备标识；不重复页面标题，不设置“工作空间”面包屑 |
| 侧栏底部 | 简要本机／Hive 状态，以及“打开 Hive 控制台”入口 |
| 账号详情 | 从平台行右侧进入，在右侧面板展示，关闭后返回原位置 |

“打开 Hive 控制台”使用系统浏览器打开当前配置的 Hive 站点。若网站要求登录，由浏览器处理。Bee 内不嵌入网站登录流程，也不把网页登录作为日常查看本机状态的前提。

首次尚未配对时，概览提供清楚的引导；诊断、网络和外观设置仍可到达。已有配置和已完成的步骤应复用，避免每次打开 App 重新走完整向导。

## 五、核心用户流程

### 1. 首次使用

安装并打开 Bee → 浏览器确认设备配对 → 进入 AI 账号页 → 自动读取已有官方登录，或发起官方登录 → 确认接入 → Bee 自动准备服务且保持暂停 → 对需要接单的平台点击“恢复接单”。

- 配对、接入账号、服务自动准备、恢复接单是不同阶段，各自有明确结果。
- 接入成功后平台保持暂停；已绑定设备在核验后可自动连接 Hive；明确接入后自动进行授权维护与服务准备，不顺便恢复接单。
- 一个平台完成接入即可使用，不要求两个平台全部接入。
- 中途关闭页面或浏览器后，可继续已有流程；配对码过期时提供重新配对入口。
- 更换有效设备必须明确说明影响，并在配对网页完成必要确认。

### 2. 日常运行

打开概览 → 查看运行／连接／各平台状态 → 暂停或恢复某个平台 → 后台持续运行。

暂停接单只停止该平台接收新任务，不终止已经接收的请求。恢复接单只解除手动暂停；授权、额度、连接等条件仍需满足，不能承诺点击后立即可接单。

### 3. 重新登录与换号

从账号详情重新登录官方客户端 → Bee 重新读取并核验 → 相同账号更新授权；不同账号显示“当前账号”和“要换成” → 用户确认换号 → 成功后保持暂停 → 用户自行恢复接单。

发现账号变化不能自动换号。响应丢失或结果无法确认时显示“结果待确认”，继续核对原操作；不提示重复提交，也不提前显示成功。关闭弹窗不代表撤销已提交操作。

### 4. 故障处理

从平台状态了解原因 → 进入账号详情处理授权／换号，或进入诊断检查网络与运行问题 → 按具体指引处理 → 页面自动更新状态。

报告过期、读取失败等只读状态问题由后台自动核对和重试；接入、主动登录、换号、解除暂停及故障后的明确重试仍由用户操作。

## 六、页面需求

### 6.1 概览

概览按“运行摘要 → 设备摘要 → 平台账号列表”排列，帮助用户快速判断当前情况。

**运行摘要**

左侧为状态图标、贡献运行标题和简短说明，下方分别展示 Bee 运行、Hive 连接；按当前受阻原因提供恢复动作，不放日常总开始／停止按钮。

| 情况 | 展示与操作 |
| --- | --- |
| 等待接入 | 说明接入账号后自动准备服务，提供账号入口；Hive 连接按事实显示 |
| 服务已准备 | 分别显示实际运行和连接状态，按平台暂停／恢复接单 |
| 启动／停止进行中 | 按钮显示进度并防止重复提交；在确认结果前不显示完成 |
| 尚未完成配对或账号接入 | 说明缺少哪一步并提供入口，不自动接入候选 |
| 网络中断 | 显示未连接／重连中；不因本机进程仍在运行而显示一切正常 |
| 运行失败或归属冲突 | 显示具体问题及处理入口，不自动接管其他方式运行的 Bee |

明确退出、网络重启或退出安装时说明可能中断正在处理的任务。不要显示无法证明的“当前没有任务”或“任务已清空”。

**设备摘要**

使用三列摘要区，允许长文本换行，不展示设备 ID 等内部字段。

| 情况 | 三列内容 |
| --- | --- |
| 已配对 | 本机设备名称、归属账号邮箱、Hive 地址 |
| 等待网页确认 | 配对码、剩余有效期、确认网址及“打开确认网页” |
| 尚未配对／配对失效 | 接入引导或具体原因，以及开始／继续配对入口 |

设备归属邮箱与 AI 订阅账号属于不同信息，不要混用。

**平台账号列表**

顺序固定为 OpenAI、Claude。一行一个平台，采用紧凑列表，信息分为左侧身份与状态、中间额度、右侧操作，不做横向宽表。

- 身份：平台图标、平台名称、账号身份前缀、订阅套餐。AI 账号不显示邮箱；未选择时写“尚未接入”，套餐未知时写“未知套餐”。
- 额度：每个已有额度窗口分别展示名称、已用百分比和细进度条。OpenAI 按“5 小时”“7 日”顺序；其他窗口按实际数据展示。没有数据写“尚未核对”，不能显示成已用 0%。
- 接单：使用下文统一状态，不能接单时逐条展示所有原因。
- 操作：贡献运行后，已接入平台显示“暂停接单”或“恢复接单”；未运行或未接入时不显示这两个按钮。

概览不承载官方登录、账号接入、换号和凭证读取设置；这些操作统一放在 AI 账号页。

### 6.2 AI 账号

页面沿用概览的平台紧凑列表，负责官方登录、确认接入、账号详情和换号。进入页面后自动读取本机已有官方登录，不设置日常“检测已有登录”“检查账号”按钮。

| 账号情况 | 行内信息与主操作 |
| --- | --- |
| 已确认没有官方登录 | “还没有 OpenAI／Claude 登录”；按钮“登录 OpenAI／Claude” |
| 登录读取失败、权限拒绝或存储方式不支持 | 说明具体原因及处理入口；不能等同于“尚未登录” |
| 已有官方登录，尚未接入 | “已有登录，尚未接入”；按钮“接入” |
| 已接入、贡献未运行，报告新鲜 | 显示账号、套餐、额度及“已暂停”；不显示暂停／恢复按钮 |
| 已接入、贡献运行中 | 显示当前状态，以及该平台“暂停接单”或“恢复接单” |
| 授权失效或发现不同账号 | 显示具体问题；从详情进入重新登录或换号确认 |
| 尚无报告、报告过期或读取失败 | 使用对应待确认／待更新状态，不保留旧成功结论 |

详情入口始终可用，采用右箭头并提供平台名称提示；无主操作时也能进入详情，不保留宽大的空白按钮槽。

**官方登录与接入确认**

登录前说明会打开对应官方客户端，可能改变该客户端当前账号；登录内容在官方界面完成，Bee 不收集密码、验证码或粘贴的 token。缺少客户端、版本不支持、权限拒绝、取消和超时均需有对应状态及下一步。

官方登录完成不等于账号已接入。Bee 核验来源后，用户再确认接入；确认内容说明所选账号、贡献将使用该账号额度，以及接入后保持暂停。平台暂停可能影响同一 Hive 用户下该平台的接单，应在确认时说明。

**账号详情侧面板**

详情补充列表看不到的信息，包含当前账号身份前缀、订阅套餐、授权到期时间和各额度窗口重置时间。授权到期时间始终保留，未知时写“未知”。

操作包括重新登录、存在新候选时确认换号，以及满足条件时取消接入：**只有尚未注册到 Hive 的本次选择可取消接入**；已注册账号不显示完整移除入口。

“凭证读取方式”仅放在详情，默认展开：目录留空表示官方默认位置；OpenAI 支持自动／文件／钥匙串，Claude 支持文件／钥匙串。当前系统不支持的方式显示“暂不支持”。说明只有登录保存在其他位置或默认位置不是目标账号时才需要修改；不提供粘贴密钥的输入框。

用户修改来源后重新读取登录，已经接入的账号不会自动替换成新来源中的账号。系统钥匙串需要权限时按需提示，并覆盖拒绝授权的处理方式。

详情不显示模型名称列表、市场开放列表、内部代次、原始错误码和多套技术时间戳。技术诊断资料放在诊断页，用户不需要理解后台核对机制才能使用账号。

### 6.3 诊断

进入页面展示已有结果，用户点击“一键诊断”后再执行检查。诊断本身不开始贡献、不更换账号、不修改暂停选择，也不自动修复。

检查覆盖设备配对及归属、运行归属、Hive 连接、所选官方登录、授权、额度与同步、接单条件、实际网络／代理路径。

每项结果包含：检查名称、通过／提醒／失败／未检查、检查时间、具体原因和处理入口。取消或超时保留已完成结果，未完成项明确标注。问题说明应区分本地登录读取、连接／TLS、身份拒绝、账号变化、限流等原因。

日志支持查看最近记录及按模块、平台、级别筛选。脱敏报告导出前说明包含版本、系统信息、诊断结果和脱敏日志；用户确认后保存到本地，实际保存成功才显示完成。取消或保存失败可以重试，不自动上传报告。

### 6.4 设置

设置按关联内容分组，优先展示普通用户常用项，低频连接配置放在高级区域。

| 分组 | 设计内容与规则 |
| --- | --- |
| Hive 与设备 | 当前 Hive、设备配对状态、必要的配对／异常处理入口；默认官方 Hive，高级设置允许自定义地址。已配对时切换 Hive 涉及身份范围变化，不设计成即时无感切换；具体配置承接方式需在设计评审中单列核对 |
| 网络代理 | 留空或填写本机无认证 HTTP 代理，例如 `http://127.0.0.1:7890`；包含校验、连接测试、已保存值和当前生效路径 |
| 启动与后台 | 开机启动默认关闭；说明实际为当前用户登录电脑后启动；展示系统登记失败／权限不足等反馈 |
| 通知 | 应用通知开关与系统权限分别展示；拒绝权限后提供系统设置指引 |
| 语言 | 中文、English、跟随系统，默认跟随系统 |
| 外观 | 浅色、深色、跟随系统，默认跟随系统 |
| 版本与更新 | App／Bee 版本、最近检查时间、检查更新、版本说明、下载进度、校验状态和“退出并安装” |

代理设置只覆盖 Bee 对上游的相应连接，不承诺改变 Hive 连接或官方客户端的网络。运行中保存新代理时显示“下次启动生效”，提供明确的“停止并重新启动以应用”操作，并说明可能中断任务；保留各平台暂停选择。首版不设计 SOCKS5、远程代理或代理用户名密码字段。

检查或下载更新不停止贡献。用户明确选择“退出并安装”后才停止 App 管理的 Bee 并进入安装；失败时说明当前实际状态，保留设备配对、账号选择、暂停和偏好。版本检查失败不能阻止使用当前版本。

偏好应在重启后保留。保存失败要明确提示未保存，不把仅在当前页面预览的值当成已生效。

## 七、统一状态与交互规则

### 1. 分清三种状态

| 状态 | 回答的问题 | 不代表什么 |
| --- | --- | --- |
| Bee 运行 | 本机贡献任务是否在运行 | 不代表已经连上 Hive |
| Hive 连接 | 本机设备是否与 Hive 建立有效连接 | 不代表所有平台都能接单 |
| 平台接单 | 该平台当前是否允许接收新任务 | 不代表此刻有任务正在处理 |

账号是否接入、用户是否暂停也需独立表达。避免用一个“在线”徽标代替全部状态。

### 2. 接单结论

| 标题 | 使用条件 |
| --- | --- |
| 可接单 | 贡献正在运行、该平台未暂停、报告新鲜且没有阻碍原因 |
| 不能接单 | 已有新鲜报告，并存在阻碍原因；标题下列出全部原因 |
| 状态待确认 | 尚无报告，首次核对未完成 |
| 状态待更新 | 上份报告过期或本次读取失败，正在自动核对或等待重试 |

原因可能同时存在，包括手动暂停、Hive 未看到连接、未接入／未配置、官方登录不可读、授权失效、换号待确认、额度未知或耗尽、限流、并发已满、平台禁用、设备替换等。平台通用原因和账号原因要准确对应，不能把所有问题归为“网络异常”。

报告过期后自动核对；短暂失败按资源退避重试，原请求尚未结束时显示等待状态。认证、TLS、数据完整性等终止自动重试的问题给出修复方向，修复后允许明确重新核对。列表和详情共用状态，普通后台刷新不增加日常操作按钮。精确调度见[请求重试设计](../superpowers/specs/2026-11-03-desktop-request-retry-design.md)。

首次正常读取，以及报告仍有效时的常规后台核对，保持安静；有效结论可继续显示。报告缺失、过期或读取失败时不能保留旧的“可接单”。只读核对不得修改账号选择、解除暂停或重复提交写入；原生自动维护按已核验选择和运行归属进行。

### 3. 操作反馈与数据表达

所有操作都要区分进行中、成功、失败、结果待确认；防止重复点击，失败说明下一步。单个平台异常不应把另一个平台的成功或正常状态覆盖掉。

未知额度不按零处理，未知套餐不猜测，恢复时间不编造；进度条明确表示“已用”比例。长原因完整换行，多条原因全部可见；颜色之外同时提供文字或图标说明。

### 4. 关闭、退出与再次打开

关闭主窗口后继续在托盘／菜单栏运行；明确退出才停止 App 管理的 Bee，并如实提示可能中断任务。首版没有“等待任务完成后退出”。托盘至少支持找回窗口和退出；Linux 没有托盘时也需能可靠找回窗口。

正常重新打开时先核验，再恢复已接入账号的自动维护与 Hive 当前平台选择。旧版停止记录先统一确认平台暂停后自动维护，仅转换一次；首次接入、主动重新登录及换号后保持暂停；异常退出或上次状态无法确认时不自动恢复，给出明确处理入口。App 不自动停止或接管由其他方式运行的 Bee，不覆盖已有 CLI 或官方客户端配置。

### 5. 隐私与通知

账号用身份前缀表示，日志和导出脱敏；不展示或导出官方登录凭证、设备秘密、买家身份、请求／响应正文和逐次任务详情。设备归属区只展示必要的已确认信息。

系统通知覆盖授权失效、待确认换号、持续离线、额度耗尽，同一未恢复问题避免重复打扰。点击通知打开相应页面，不直接执行换号、恢复接单或开始贡献。关闭通知后仍保留应用内的问题提示。

## 八、视觉与桌面适配要求

整体沿用已确认的“银白精工”布局，组件采用 shadcn/ui 风格：浅银灰背景、白色工作区、细分隔线、紧凑按钮和账号行、克制阴影，琥珀色用于导航强调、额度条和少量点缀。

浅色主题主按钮使用深色实心，深色主题主按钮使用浅色实心；次要操作描边或弱化。正常状态保持安静，异常状态提供清楚文字和可执行入口，避免大面积警示色。

参考尺寸：侧栏约 178px、顶栏约 52px、内容左右留白约 29px；正文约 13px、辅助文字 10–12px、页面标题约 24px；按钮约 32px 高、6px 圆角；右侧详情约 430px，确认弹窗约 400px。具体排版可在既有方向内细化。

正式 App 使用系统原生标题栏。设计稿不复制 HTML 预览的仿制窗口按钮、演示场景切换器或主题方案切换器。

至少覆盖正常桌面窗口和 **860×600** 最小窗口。窄窗口允许额度组移动到账号行下一层、文本换行和内容纵向滚动，不能通过隐藏原因、截掉操作或改成横向宽表解决。

中文和英文、浅色和深色都需要完整设计。弹窗和详情支持键盘操作、Escape 关闭、焦点约束及关闭后返回触发入口，图标按钮有可访问名称；正常文本对比度达到 WCAG AA。

实现沿用 Tauri 2 桌面壳、React 页面和独立 Go Bee；这是既有且已确认的基础，本文不新增框架选型。产品交付应复用现有组件语义，系统权限弹窗标明系统承接，不画成 Bee 自建登录或权限系统。
