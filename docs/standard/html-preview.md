# HTML 预览规范

适用于界面设计讨论与人工评审使用的 HTML 预览。目标是让评审者选中一个场景，立即看到页面，并能理解和尝试页面操作。本规范不定义具体业务场景、状态机或业务验收清单。

工作量随改动范围确定：首次交付和公共机制变更做完整检查，局部修改只检查受影响部分。已有验证结果和完整快照仍适用时直接复用，不重复执行与本轮无关的流程。

## 快速设计沟通：先示意图，后 HTML

目标是快速、直观地展示页面，让用户立即看懂页面放什么、重点在哪里、按钮点击后发生什么。

- **默认先出文本线框图，涉及跳转或状态变化时补简短流程图。** 不用表格代替页面展示，不先写长篇设计文档；复杂业务的必要规格仍按项目规则执行。
- 助手沿用已确认规则，直接给出示意图，只标必要的未定项并集中确认，不要求用户从零描述，不重复讨论已定原则。
- 线框图展示主要区域、当前状态、主次按钮及折叠入口；流程图说明操作后的进行中、成功或失败结果，以及下一步。字体、颜色和精确间距留到 HTML 中评审。
- 用户认可布局与流程后，复用现有预览外壳制作 HTML。多个场景共用布局时，可以先展示代表场景再补齐；场景较少或一次完成更快时直接一起制作，不强制分批。保留完整的已确认范围，未完成部分明确标注，不因先做样例而删除其他需求。
- 已确认范围内的小调整直接完成；流程变化时只更新相关示意图，不重走整套讨论。用户仅问含义时先直接回答，不自动扩展为代码修改。
- 每轮只做约定范围，验证与受影响路径相匹配，不顺带重构、整理目录或扩写通用规范。HTML 仍遵守本文件的交互、历史留版和交付检查要求；文本示意图无需创建 HTML 快照。

页面示意（仅说明表达方式，不定义业务规则）：

```text
设置
──────────────────────────────────
名称  [当前名称                  ]

[保存]                      取消
──────────────────────────────────
```

操作流程示意：

```text
点击保存 → 保存中 → 保存成功，返回上一页
              ↓ 失败
          保留输入，显示具体原因 [重试]
```

## 页面结构

默认从上到下采用以下三层，作为可复用模板；有明确评审需要时可以补充内容，但不得妨碍查看页面和操作按钮：

1. **预览工具栏**：场景下拉列表、外观、应用窗口尺寸、重置场景。
2. **一句场景说明**：说明当前看什么、可以尝试什么或预期看到什么；不放长教程、步骤清单和验收进度。
3. **应用预览区域**：展示待评审的真实布局与交互，和外部预览工具栏明确分开。

```text
场景 [选择场景 ▾]   外观 [浅色 ▾]   窗口 [尺寸 ▾]   [重置场景]
一句话说明当前场景的评审重点。
┌─────────────────────────────────────────┐
│                应用页面                 │
└─────────────────────────────────────────┘
```

## 场景选择

- 列表应覆盖本轮已确认的评审范围，包含正常、空内容、进行中和异常等必要状态；具体清单另行维护，不写入本规范。
- 场景较多时按用户能理解的类别分组。使用描述页面状态的名称，不显示内部事件名、错误码或 mock 参数。
- 在同一个场景下拉中按“类别 → 流程 → 子场景”分组、缩进展示。流程中的各个可见状态均有可直接选择的子场景，包括确认弹窗、等待登录、自动核验、不同结果分支、准备中和完成状态；具体名称随已确认流程确定。
- 每个场景及子场景均能直接打开，不要求先完成其他场景、登录真实账号或组合外部条件。直接选择后停留供查看，自动阶段也不自行跳走。
- 选择场景会加载该场景的预设起点，关闭原场景弹层并取消原场景未完成的模拟操作。
- 点击产品按钮时按预设连续推进，下拉同步标示当前子场景；此同步只更新位置标示，不重新加载场景或中断当前操作。
- 重置恢复本次最后直接选择的场景或子场景起点，保留外观与窗口尺寸；操作推进后的下拉位置标示不改变重置起点。
- 外观和尺寸切换不重置已输入内容、已执行操作或当前弹层。
- URL 记录场景、外观和尺寸，便于分享同一个评审起点。无效参数回落到明确的默认值。URL 不用于记录凭据或敏感数据。

## 模拟交互

- 页面按钮、表单、弹层、折叠和导航应按展示语义工作；不放可点击却无结果的装饰按钮。
- 场景使用预先确定的模拟数据与操作结果，不要求评审者理解或配置外部事件。
- 用户发起页面操作后，可以演示必要的进行中状态和预设结果；需要用户确认的业务动作仍保留确认步骤。
- 直接选中的异常或进行中场景应停留供评审，不因后台定时器自行变成正常页面。想看其他状态时，直接选择对应场景。
- 不增加“演示恢复”“模拟登录成功”等独立外部结果按钮。外部操作由场景预设承接；不需要演练的外部变化通过切换场景查看。
- 禁止把打开详情、展开说明等查看动作当作修复动作。操作应保持业务语义一致。
- 切换场景只证明目标页面可以展示，不证明原场景已正确恢复。新增或修改交互时，验证受影响的状态转换、成功与失败后的下一步，以及相关业务约束；纯视觉修改只检查显示效果。真实后台的业务正确性在正式实现阶段验证，不要求每轮预览重复执行业务回归。
- 无法模拟的能力在交付记录中说明，不用伪成功掩盖缺口。开发调试工具可独立保留，但不进入人工评审页面。

## 内容与可用性

- 页面突出一个当前主状态，区分主要操作与次要入口。重复原因合并，独立问题保留，低频详情默认折叠。
- 失败提示说明具体失败条件和可执行的下一步；必要证据放在展开详情中，不用一条笼统失败信息覆盖原因。
- 故障状态聚焦解决当前故障：保留账号身份、一个主故障状态、必要步骤、修复按钮及默认折叠的错误详情。隐藏无助于修复的额度、套餐及其占位提示；低频管理操作放入详情。当前只有一个必要修复动作时，只突出该按钮。
- 多个独立阻塞条件仍须保留，按处理顺序展示当前必要动作，不把暂停等独立条件当作故障原因。故障解除后恢复正常布局，保留既有接单选择；修复故障不自动解除用户暂停。
- 统一字体、颜色、间距和组件风格；沿用项目已有视觉规范。示例外壳不强制产品页面采用相同风格。
- 控件有明确标签，键盘可操作，焦点可见。切换状态后的反馈可被辅助技术感知。
- 应用窗口尺寸指应用预览区域，不包含工具栏。较小屏幕下外壳可换行、滚动，不缩放文字冒充目标尺寸。
- 预览必须明确是模拟数据，不接触真实账号、凭据、业务写入或外部消息发送。

## 唯一主预览与固定目录

- 规范源文件位于 Bee 主项目的 `docs/standard/`；参与预览工作的 worktree 在相同相对路径保留同步副本。通常修改规范时同步正文、示例及历史索引，交付前核对内容一致；用户明确要求仅在 worktree 修改时，只更新该 worktree，后续合并或获准同步时再更新主工作区。同步副本不产生第二个 App 主预览。
- **整个 App 只维护一个主预览入口：`docs/preview/index.html`**，路径相对于 Bee 项目根目录。各页面、流程和场景通过主预览内的应用导航与场景列表切换，不按页面、日期或会话另建主入口。
- 固定目录为当前 Bee checkout 的 `docs/preview/`。本轮用户明确要求仅在 `bee-desktop-ui` worktree 整理和维护，以该 worktree 的主入口为准；不自动写入 Bee 主工作区。合并分支时沿用相同相对路径，不产生按会话区分的第二个主入口。
- 主预览表示最新已确认的累计方案。只有用户明确认可的修改才能纳入；只确认局部时只更新该部分，不顺带纳入其他未确认设计，不删除此前已确认且仍有效的页面和场景。
- 后续调整使用同目录的 `draft.html`。它是待评审稿，不替代主入口；也可以保留多个有明确名称的候选，但必须在索引中标明待评审状态。
- 确认后更新 `index.html`，保持入口路径不变。HTML 视觉方案的确认不等于正式应用代码或真实业务验收通过。
- 通用示例仍位于 `docs/standard/examples/`；它用于说明规范，不是 App 主预览。测试 fixture 也不作为设计评审的主入口。

```text
docs/preview/
├── index.html                 # 全 App 唯一主预览，累计已确认方案
├── draft.html                 # 有调整待评审时才创建
├── README.md                  # 固定入口、启动方式、当前已覆盖范围
└── history/
    ├── README.md              # 历史索引与确认记录
    └── YYYYMMDD-HHMMSS-说明/
        └── index.html         # 完整冻结版本，保留归档时的文件名
```

## 版本更新与历史

- 简单讨论预览优先使用单文件 HTML，内联 CSS、JavaScript 和模拟数据，可直接打开；需要依赖或服务时记录启动命令和访问地址。复用已有前端与 mock 时不必复制业务实现。
- **保留修改前、交付评审和确认纳入主预览的关键版本，但不要求每个节点新建一份快照。** 首次交付保存完整快照；修改前已有相同内容的完整快照就直接复用，交付时仅为尚未留存的版本新增快照。确认时内容未变，只更新认可状态；轮内临时修补不必逐次留版。
- 主预览和候选稿的历史统一保存在 `docs/preview/history/YYYYMMDD-HHMMSS-简短说明/`。保留归档时的 HTML 文件名与全部依赖；历史内容只追加，不覆盖、改写或删除，除非用户明确要求。
- `history/README.md` 必填版本标识（可用时间戳）、修改摘要、评审状态（待评审／已认可／已否定／部分认可）及 HTML 链接。时区在索引中统一声明；部分认可时补充认可范围，迁移旧资料时补充来源，确认依据仅在需要解释范围或分歧时补充。评审状态变化只更新索引中的认可记录，不改写冻结文件。
- 用户确认后：确认现有主预览已有完整快照，再纳入已认可修改，检查已有场景未丢失。更新后的主预览若与已归档候选内容及依赖一致，复用该快照并记录为已认可；合并局部修改等导致内容不同时才新增快照。最后更新索引及发生变化的覆盖范围，交付时仍以固定主入口为首要链接。
- 历史版本不能引用会变化的当前版资源。截图只能补充说明，不能替代可运行历史。旧资料迁入时保留原文件名与来源；重建版本和无法冻结的依赖须如实标记。

## 交付检查

- **首次交付或公共机制变更**：完整检查场景切换、重置、外观、尺寸、键盘、弹层和操作反馈，以及切场景后旧操作不会影响新场景。公共机制包括预览外壳、共享样式、场景加载与模拟任务管理；检查覆盖其影响的页面与必要状态，不机械遍历无关组合。
- **局部修改**：只检查受影响的页面和路径。改按钮或交互时检查相关操作、状态转换及恢复路径；只改颜色、间距等视觉时检查对应显示效果，不重跑无关流程。未受影响且仍适用的验证结果直接复用。
- 新交付版本打开主预览（或待评审稿）和新增历史快照，核对资源、初始场景及本轮涉及的关键交互。复用内容和依赖均未变、已验证可独立打开的快照时，不重复检查；归档方式或依赖路径改变时重新验证历史可用性。纳入主预览时确认仅包含已认可修改，已有场景未丢失。
- 交付固定主入口、必要的待评审稿及历史索引，说明本轮验证范围与真实业务边界。

## 示例

[打开示例 HTML](examples/preview.html)。示例用通用内容展示工具栏、分组选择、编辑弹层、错误详情和重置行为；其中的少量示例状态仅用于说明规范，不是业务场景清单。

示例无依赖，可直接在浏览器打开。也可在本目录运行 `python3 -m http.server 1494 --bind 127.0.0.1`，访问 `http://127.0.0.1:1494/examples/preview.html`。支持 `scene`、`theme`、`size` 参数。
