# Bee 自动启动调整核验

## 行为

启动入口只询问是否引导补齐配置。运行方式按实际能力决定：匹配的 Linux 安装器服务自动后台运行，macOS、缺少 systemctl、明确非 systemd 环境或缺少 Bee unit 自动前台运行。已运行的后台服务直接返回。查询错误、服务匹配错误、启动失败保留证据并停止，不转为另起前台进程。

普通启动不再重复确认启动方式或启动动作；配对与账号保存的确认仍保留。取消引导不继续启动。高级选项保留显式前台运行、自定义供给路径及仅在线行为。普通启动使用设备文件旁的 egress.json，结束后恢复会话选项。现有配置锁、Ctrl+C 退出以及后台服务继续运行的语义保持。

## 验证证据

- TDD：新自动启动测试先因旧菜单要求额外输入而失败；缺失 systemctl 与非 systemd 的能力识别测试先失败；实现后相关 Go 测试通过。
- 安装器：64 项测试中，本机 macOS 通过 62 项，2 项原生 systemd 检查由 Linux CI 执行。
- 真实 PTY：15 项通过，包含中英文单次配置问题、取消、首次配对和账号选择后直接连接、已有配置直接连接、高级前台入口与 Ctrl+C 退出。
- Go：go vet 与 go test -race -timeout=600s ./... 通过。首轮新增未配对测试错误期待中文消息，核对源码后改为检查既有 BEE-DEVICE-NOT-PAIRED 错误码，全量重跑通过。
- make build、两仓库 git diff --check、文档站 npm run build 通过。
- 测试使用临时路径、合成凭证、合成 Hive 和模拟服务；没有操作用户实际 Bee 服务或账号。

本次未修改 Makefile、CI workflow、安装脚本或依赖，现有 make test 和 Linux CI 直接运行增加后的测试。
