## 1. 方法、证据和范围闭合

从 `NativeApp` 四页入口追踪到 React 状态协调器、TS 私有协议、Rust 命令门禁、Go 账号／设备／运行操作及 Hive 配对与供给协议。结合既有 specs 核对已确认能力，尤其是取消接入的边界、官方登录、结果未知、正常退出与异常退出、更新后恢复。

“全部”指当前正式产品已定义的能力与状态，不仅是 39 个预览，也不包含已排除的收益／资金、完整移除已注册账号、等待 Hive 任务结束后退出、自动接管其他 Bee、自动安装官方客户端。新增枚举、动作或前置条件时，必须先补本表对应项；不能以有限截图声称覆盖任意未知环境。

每条路径检查：入口及前置条件 → 读取／提交 → 等待与反馈 → 成功或明确失败 → 结果未知 → 恢复后下一步。对有副作用的动作追加双击、离开页面、响应丢失、保存失败、重启及旧回调检查。独立平台、共享身份和全局操作分别建模，不做没有业务意义的全组合穷举。

证据等级：**原**＝此前真实原生 App 取证；**浏**＝本轮浏览器操作正式组件，IPC 为隔离模拟；**自**＝本轮运行的现有自动化断言；**源**＝源码／契约与既有测试核对；**待真**＝仍需真实核心、Hive、官方客户端或原生系统验收。单元测试或浏览器通过不等于“待真”完成。

证据目录：[本轮日志、截图与页面记录](/Users/dayong/myspace/mywork/tokenhive/design-previews/2026-11-01-bee-interaction/full-review)。此前真实故障见[原生走查报告](/Users/dayong/myspace/mywork/tokenhive/design-previews/2026-11-01-bee-interaction/usability/REPORT.md)。当前用户设备和登录配置未更改。

## 4. 具体发现与必要修订

### F01：启动／身份错误会封锁恢复页面（原生已确认）

`NativeApp.tsx:79` 用单一 ready 隐藏概览和账号，`experience.rs:35` 将业务核对失败改成管理进程失败。已在上一轮 T4a/T4b 纳入，但只是 S04/D09 的一组场景，不能代替整个 App 的验收。

### F02：初次读取中缺少分阶段事实，一平台慢请求拖住共享结果（浏览器＋源码）

`desktopState.ts:34` 开始读取，直到两平台循环结束才统一发布设备、runtime、defaults和账号；`NativeAccountList.tsx:16` 对缺少的账号直接计为零。account-reading 场景挂起 OpenAI 查询时，页面显示“0 个已接入”“登录状态待确认”，已读出的共享事实也尚未发布。预览断言连续两次失败。

T5 应按已确认阶段发布共享事实及独立平台结果，保留同一协调器和版本屏障；独立平台慢请求不能挡住另一平台。T7 按实际读取阶段显示加载及禁用原因。验收用受控延迟／实际请求期限，不要求无限挂起是真实网络常态。

### F03：诊断一次读取失败后停止轮询，缺少继续原报告的入口（浏览器＋源码）

`NativeDiagnosticsPage.tsx:35` 的 poll catch 只记录错误，不安排下次查询。注入一次 diagnostics_snapshot 临时失败后，47,616 ms 内查询计数仍为1；页面仍“诊断进行中”，“重新运行诊断”禁用。离页再返回才恢复并完成。证据见 `diagnostic-poll-failure.json/png`。

T8 必须保留原报告 ID，展示读取失败与真实重试状态，提供“重新读取本次诊断”或按既有有界策略继续查询。只重读，不再次 diagnostics_start；上下文变化／终态后停止。开始回执未知、取消回执未知另测，不伪造可查回不存在的报告 ID。

### F04：设置草稿跨页面丢失（浏览器＋源码）

输入代理草稿 `http://127.0.0.1:8877`，离开设置到概览再返回，值变为空，保存／应用请求数为0。`NativeSettingsPage` 本地 state 随 `NativeApp` 条件挂载销毁。既有测试只覆盖设置内部页签切换。

T5/T8 的草稿保留要覆盖四页导航、失败后的处理入口与返回；草稿按当前绑定隔离，不能跨身份自动采用。证据见 `settings-draft-loss.json`。

### F05：首次配对的结果未知边界不能只在重绑新路径修正（源码确认）

`agent/desktop_device.go:132` 创建请求没有先持久化“已尝试创建”，响应丢失且 Pairing 为空时，下一次 Begin 可再次 POST。`:171` 的 approved 分支对先前 `redeeming` 也进入兑换 POST；Hive 的状态查询不锁定未结束的兑换事务，approved 本身不是先前写入未提交证明。现有测试保护“未知时不清空”，未证明“再次Status/Begin不重发兑换”。

T4b 必须同时覆盖首次配对与撤销恢复的创建、兑换、保存、重启。已有 Hive 服务端事务保护不能替代客户端“不盲目重放”的交互承诺。明确业务拒绝且保证未提交（如 device_draining）与传输未知分别处理；后者只能核对。无 token 的创建未知同样保留协议限制。

### F06：被禁用的账号动作缺少可执行的原因（源码／预览）

`NativeAccountActions.tsx:29` 使用 features.available、候选期限、运行转换、unknown 等条件禁用，但未呈现对应 features.reason／客户端条件；部分原因仅在详情页解释。用户看见灰色“登录”或“接入”，仍不知道下一步。

T7 使用与启用条件相同的事实生成邻近说明与定位动作，覆盖运行中登录、候选待刷新、未决写操作、启动门禁和不支持来源。提交时条件改变不能静默退出，必须说明需重新核对／确认。

### F07：过期与自动恢复过程的预览断言失败，调度语义未对齐（自动化＋源码）

check-sequence 预期报告过期后出现“核对中”，连续两次未出现。`useSupply.ts:32` 在统一协调模式下到期只失效展示，不发起协调器刷新；`desktopState.ts:69` 继续按10秒安排读取，期间存在已过期但尚未读取的状态。它不证明发生错误写入；本次失败是恢复时序／展示与预览断言不一致。

T5 显式区分已过期等待读取、读取中、失败待重试和已恢复，显示协调器实际时间；如选择到期触发读取，必须合并到唯一协调器且不增加重叠请求。T10 按正式选择修正 fixture 和断言，不能删掉失败断言或编造“正在核对”。

### F08：原因、动作与结果文案在多条路径仍未统一（源码／浏览器）

`NativeDiagnosticsPage.tsx:14` 仍有“去设置配对”“重新检测”、将 source_missing 扩大为“官方登录不存在”；账号操作错误、设置测试 message、更新错误仍直接输出原文；多个时间 formatter 使用系统 locale。已有测试通过的是部分已知词条，不是全部错误本地化。

T4/T6–T9 必须按本表所有可达入口审计中文主提示、禁用理由、确认影响和完成事实；保留安全原始证据，但不能让它取代主说明。平台市场原因从 Hive 事实产生，不靠翻译猜测。

实施完成后，所有矩阵行必须登记“最终证据／未通过原因”，不得只保留当前401组合。至少真实走通：首次配对到接单、网络断开再恢复、失效设备恢复到重新接单、官方登录及取消、换号结果未知后的核对、代理应用部分失败后继续、诊断查询失败后继续、正常／异常退出重开、更新失败及重启核验。覆盖两平台差异；当前环境不具备真实条件的行标待验，不用模拟替代。

最终台账使用计划“如何判定功能完整”的字段，将能力、入口、状态、场景、任务和证据双向关联；一个场景包含多个异常时，分别登记子用例，不能用其中一个通过覆盖整行。R03 沿用既有账号运行验收要求，在明确用于验收的环境、账号及请求范围内记录两平台实际受控请求返回和暂停／停止后的结果；缺该证据时 ready 不足以证明能完成贡献。D07 无token时的人工处理须有实际可用路径证据，不能把“联系管理员”本身作为恢复完成。

需真实环境的主要条件：隔离 Hive 与可用平台市场、明确用于验收的官方账号／客户端、原生通知与自启权限、签名更新包及相应系统。当前开发 App 的401证据不能替代这些路径，也不隐式授权替换用户设备、改变官方登录或恢复真实接单。
