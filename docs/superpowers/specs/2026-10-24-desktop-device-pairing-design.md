# 不修改 Hive 的桌面设备配对

状态：按用户 2026-10-24 明确指令实施的设备配对增量。2026-10-26 范围更新：现有浏览器设备配对与设备凭证通信继续沿用；独立 Hive 用户会话和登录授权回跳已移出 Bee 当前范围。下文“不启动贡献”等限制只描述本批交付，后续运行 spec 可在真实运行条件满足后接通贡献；本增量不宣称完成 P2 或 P0/P1。当前范围见[需求清单](../../../../../docs/discussions/2026-10-21-bee-desktop-requirements.md#当前有效范围2026-10-26)。

## 范围与技术栈

沿用 Go 1.27.3 设备核心、Tauri 2.12.5/Rust 1.90+ 系统壳、React 19.2.8、TypeScript 7.0.2、Vite 8.2.4 和既有私有管道，全部已确认；不增加依赖、Hive 接口或数据库迁移。普通原生构建接真实设备配对，显式 demo 构建保留演示，普通网页仍显示未接通。

复用 POST /api/bee/pairings、GET /api/bee/pairings、POST /api/bee/pairings/redeem、GET /api/bee/identity。用户输入合法 Hive origin 和设备名，打开现有 /devices/pair?code= 网页，必要时先网页登录，再核对和确认设备。客户端轮询结果；网页不自动返回 Bee，页面明确提示用户自行回到 Bee。替换设备只在 Hive 现有网页明确确认。

## 边界

- 设备归属不表示独立桌面账号会话。只显示 Hive 核验的设备 ID、归属和名字。
- 使用 UserConfigDir()/tokhive/bee-desktop.json，沿用私有文件、原子写入、no-follow 与跨进程锁。不得覆盖 bee.json 或接管外部进程。
- 设备凭证先持久化再请求配对；配对令牌只在 Go。前端只得到白名单状态、公开配对码/URL、过期时间和公开设备身份。
- 配置已有 Hive 后拒绝换 Hive；已绑定凭证失效和身份改变时阻断，不重新绑定。未完成配对可通过明确点击继续/重新生成，复用原设备凭证。
- 兑换结果未知时先核验原凭证；仍未知则保留事务并报错，不自动生成新身份。重启从相同配置恢复核验。
- URL 必须与配置 Hive 同源且精确指向 /devices/pair；打开浏览器由受限原生命令执行，不给 JS 任意命令或路径。
- hello/ping 不读设备配置或启动供给。设备业务错误作为结构化结果返回，不杀死管道；协议/来源错误继续 fail-closed。
- 本增量不连接贡献 WebSocket，不启动真实贡献，不显示虚构账号/余额/收益；账号、收益和运行控制明确未接通。

## 验证

Go 测试覆盖创建、pending/draining/approved、兑换响应丢失恢复、重启、过期重新开始、Hive/身份变更、失效凭证、恶意 URL、锁冲突和秘密不出界；HTTP 字节与 Hive 现源码交叉核对。管道测试证明业务失败后 ping 可用和参数严格校验。Rust 验证白名单、URL 和真实子进程。前端测试证明普通原生入口、错误/未确认、轮询及不混入演示。最终运行相关 Go/Rust/TS 检查和构建，保留尚未具备的目标系统原生验收缺口。
