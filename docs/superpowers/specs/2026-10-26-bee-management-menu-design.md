# Bee 数字交互管理菜单

## 状态与已确认需求

用户已确认：在终端直接输入 `bee` 进入管理菜单，通过数字选择动作并按提示逐步完成；操作后返回菜单，退出菜单不停止后台 Bee。第一版采用已展示的常用入口：状态、设备配对、供给账号、后台服务、日志与诊断、语言、退出。保留已有带参数命令。

本文记录该方向的设计。用户在收到本文后要求清理已合并安装功能的 worktree 并继续 Bee 功能，按该指令落实；实施结果与验证记录见对应实施计划。

## 技术方案与取舍

| 技术 | 用途与理由 | 版本及状态 |
| --- | --- | --- |
| Go、标准库 | 菜单随 Bee 二进制发布；逐行读数字、函数调用、带参数的外部命令执行，无额外菜单运行时 | 沿用仓库 Go 1.27.3；按继续执行指令采用 |
| 既有终端检测和双语输出 | 复用语言、颜色、纯文本规则；把适用于菜单的输出能力与安装器上下文分开 | 沿用，无新依赖 |
| systemd / systemctl / journalctl / sudo | Linux 后台服务、开机自启和日志；继续使用已有 tokhive-bee 系统服务 | 沿用安装器要求 systemd 243+；按继续执行指令采用 |
| Go test、Python 3 PTY、ShellCheck、现有 CI | 业务、真实终端导航、安装兼容和 Linux 服务命令回归 | 沿用；测试不操作真实账号或生产服务 |

采用 Go 逐行数字菜单。可选的全屏 TUI 同样能覆盖需求，但会增加键盘事件、屏幕刷新和新依赖，当前数字选择流程不需要这些能力。两者业务步骤相同；逐行方案更便于 SSH 使用、保留排障输出和自动测试。

## 入口与通用交互

- 只有无参数 `bee` 且标准输入、输出均为交互终端时进入菜单。无终端时沿用帮助输出并退出，不等待输入、不执行动作。
- `bee help`、`bee --help` 和已有子命令继续按原语义运行；第一版菜单使用当前用户默认设备配置和相邻供给配置。高级路径继续使用已有子命令。
- 首次进入当前菜单会话且未设置 `BEE_LANG` 时，提供中英文数字选择；显式 `BEE_LANG=zh|en` 跳过选择。菜单中可随时切换，选择只作用于当前进程，不写服务或账号配置。
- 一套共享输入读取器负责菜单和操作向导，防止嵌套缓冲读取吞掉后续答案。调用配对和账号功能时显式传递本次语言及输入输出上下文。
- 所有子菜单 `0` 返回上级，主菜单 `0` 退出。自由文本输入前提供取消说明；Hive 地址输入 `0` 取消该动作。数字或文本无效时显示合法范围并重问。
- 涉及重新配对、账号替换、暂停/恢复供给、改动现有账号选择，以及服务变更时，确认页展示实际目标及影响，以 `1) 确认  0) 取消 [0]` 收尾。空输入和 EOF 均不表示同意；菜单自身优先使用数字，原 CLI 的 y/n 交互保持兼容。
- 操作完成后先显示结果，按回车返回菜单；失败停止当前动作，保留具体原因、错误码、路径或实际服务状态，用户可返回菜单。全局 Ctrl-C/EOF 结束菜单并取消未完成的前台调用，不停止后台服务，不把部分完成显示为成功。
- 适合终端时使用 emoji、明显分割线和颜色；`NO_COLOR`、`TERM=dumb` 延续现有规则。状态、步骤、确认和结果文案均支持中英文；外部日志和原始错误保留原文及诊断证据。

## 主菜单样例

```text
🐝 Bee 管理
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
版本：vX.Y.Z

  1) 查看运行状态
  2) 配对 / 重新配对 Hive
  3) 管理供给账号
  4) 管理后台服务
  5) 查看日志与诊断
  6) 切换语言 / Language

  0) 退出
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
请输入选项：
```

进入菜单不自动配对、重启或发起写请求；只在用户选择对应动作后执行。主菜单不轮询 Hive。

## 1. 查看运行状态

展示 Bee 版本、当前配置路径、Hive/设备信息、各平台账号与接单状态，以及可管理的 Linux 服务状态和开机自启状态。复用既有状态查询，明确区分“服务正在运行”和“账号可以接单”。

配置缺失显示未配对或未选择账号，并指向对应菜单；Hive 请求失败时，仍展示已获取的本地服务信息，远端项显示查询失败及实际错误，不用本地进程状态推断在线。选择该动作只读，不因凭证失效直接进入重配对。

## 2. 配对 / 重新配对 Hive

- 没有设备配置：询问 Hive 地址，展示目标后确认，复用配对流程，显示网页链接、配对码、等待和结果。
- 配对未完成：允许继续原配对；保留已生成凭证。用户选择重新配对时另走明确确认流程。
- 已有配对：展示当前 Hive 和设备，可选择验证或重新配对。验证只查询身份，不为验证停止运行中的服务；网络或权限等错误不会自动清理配置。
- 重新配对：先输入目标 Hive（可回车沿用已有地址）并确认。说明将备份设备配置、保留供给选择，以及在 Hive 网页确认替换可能停用另一台 Bee。有效配对也必须经过该明确动作与确认，不自动替换。
- 如本机匹配的托管服务正在运行，确认内容同时说明将停止服务及影响。先成功停止，再使用 Bee 原有配置锁；锁内重新检查文件类型、权限和内容与确认时快照一致。其他进程占锁或文件已变化时停止，不移动配置。
- 创建相邻唯一 0700 备份目录并保留原 bee.json 的私有权限，公布备份路径，再执行正常配对。失败保留备份和新配对进度，不自动覆盖新状态或声称成功。
- 成功后，若供给配置缺失，可选择继续账号配置；若已有则保留。服务已安装时询问是否启动，默认取消；拒绝后明确“配对完成，服务尚未启动”。服务启动成功也单独检查实际状态。
- 无可管理服务但存在占锁的前台 Bee 时，提示用户先停止该进程。macOS 可以配对，第一版不创建或控制 LaunchAgent。

恢复行为与已批准的安装器恢复设计保持相同授权、备份、锁和失败保留原则；Go 内部使用原生文件锁，不要求安装 Linux flock 工具。安装脚本继续兼容旧 release，不在本次强制改成调用新菜单或新增命令参数。

## 3. 管理供给账号

子菜单：查看账号与供给状态、重新选择供给账号、暂停接单、恢复接单、确认账号变更、返回。平台通过数字选择 OpenAI 或 Claude；不要求用户输入平台标识或复制完整指纹。

- 重新选择账号：复用本机官方登录发现和现有配置保留规则；逐个展示账号并用数字选择，最后展示完整供给列表及被移除的平台，再确认写入。取消/EOF 不落盘；没有选择任何账号时不清空配置，提示可用暂停功能停止接单。手写的高级配置继续按既有规则拒绝自动覆盖。
- 菜单展示发现的官方账号及其来源，但不打印凭证；如果未登录，给出对应官方客户端的登录指引，完成后用户可重新检测。
- 保存账号配置后明确显示“配置已保存”。如果匹配服务正在运行，询问是否立即重启应用；取消或重启失败时显示“尚未应用到当前进程”。当前服务停止时不因保存配置自动启动。前台或自定义服务给出对应的重新启动提示。
- 暂停/恢复：显示选定平台和影响，确认后调用已有平台控制逻辑。暂停仅停止该平台接收新任务，不等同于关闭整个 Bee；恢复后仍需依据返回状态说明是否可接单。
- 确认账号变更：读取待确认账号，展示平台、当前与待确认指纹及可用摘要。用户确认后重新核对同一待确认指纹和确认标识，再提交；记录改变/过期则停止并重新展示，绝不自动确认另一个账号。保留原有手动暂停状态，不把确认成功描述为授权已同步。
- 远端写入结果不确定时显示原始错误，并提供重新查询入口；不自动重试或输出成功。

## 4. 管理后台服务

```text
⚙️ 后台服务
────────────────────────────────────────
  1) 启动 Bee
  2) 停止 Bee
  3) 重启 Bee
  4) 开启开机自启
  5) 关闭开机自启
  0) 返回
```

- 第一版控制 Linux 安装脚本创建的系统级 tokhive-bee 服务。修改前验证服务存在、受安装器管理、运行用户与当前用户一致、配置和可执行文件目标与本菜单一致。二进制路径解析符号链接后比较，配置路径必须与安装器记录完全一致；配置路径别名等无法证明匹配的情况停止并显示冲突证据，不控制其他用户或其他配置的服务。
- 手写 unit、改变目标的覆盖配置、旧用户级服务不自动迁移；展示实际状态及原命令管理指引。服务未安装时提示运行安装脚本；第一版菜单不自行下载程序、创建服务或卸载 Bee。
- macOS 和无 systemd 的 Linux 保留菜单入口，进入后明确说明当前平台不提供该后台管理功能，并给出前台 bee start 指引。
- 通过固定可执行程序和参数数组调用 systemctl；涉及权限时仅为该条服务命令调用 sudo，不把整个菜单转成 root，也不使用 sudo -v 预验证。取消/拒绝提权保留原诊断。
- 启动前检查配对和供给配置；缺失时可选择进入相应向导，完成后重新确认启动。停止/重启说明可能影响当前任务，默认取消。
- 开启/关闭开机自启分别执行 enable/disable，不隐含 start/stop；结果明确说明当前运行状态与下次开机行为。
- 每次操作后查询真实状态：启动/重启期望 active，停止期望 inactive，开机自启读取实际 UnitFileState。启动被配置条件跳过、服务仍过渡中或查询失败均不得报成功。
- 服务操作前再次检查目标和状态；外部命令响应失败不继续后续修改，显示命令、退出码及 stderr。可取消等待，取消后提示再次查询以确认外部服务操作是否完成。

## 5. 查看日志与诊断

提供“最近 50 行服务日志”和“运行诊断”两个动作，不在首版加入无限日志跟随。日志使用固定单位和 --no-pager，展示后可立即返回；权限不足提供单次提权读取选项，默认取消。无支持的服务时说明日志来源不适用，诊断仍可运行。

复用 doctor 的只读检查能力，展示每项结果与修复建议；复用时不让其日志配置改变后续菜单操作的日志。原始诊断错误码、上游正文和服务日志保持原文，不暴露秘密。

## 实现边界与发布

- 菜单只协调现有动作，复用结构化查询/动作结果，不解析面向人的 stdout；按需抽取小函数处理输入、渲染和执行，不重写账号/配对业务或创建通用工作流框架。
- 菜单正常步骤和被其直接调用的面向用户报告需跟随所选语言；原 CLI 参数、退出语义、JSON 结构和服务运行日志格式保持兼容。
- 本次不增加持久菜单偏好文件、新环境变量、远程管理服务、全屏终端库或 macOS 自启实现。
- README、安装指南说明裸 bee 的菜单入口、子命令兼容、菜单退出与后台进程的关系、平台边界以及配置保存后应用方式。
- 菜单必须随新版 Bee 二进制发布。仅更新 install.sh 不会给旧二进制增加菜单；PR 阶段用分支构建测试，不自动发布 release。

## 验收与验证

1. 真正 PTY 中裸 bee 显示中英文数字菜单；各入口、返回、切换语言、无效输入、EOF、Ctrl-C 可验证；连续输入不丢失。非交互执行和已有帮助/子命令保持兼容。
2. 成功、失败、取消流程均显示实际结果，取消不执行未授权动作，退出菜单不发送后台停止命令。覆盖纯文本、NO_COLOR 和终端样式。
3. 配对覆盖首次、继续、有效/失效身份的显式重配对、网络失败、拒绝、锁冲突、文件变化/符号链接、备份权限和新配对失败保留。
4. 账号覆盖发现、完整选择预览、取消无落盘、保留配置、重启应用与未应用、暂停/恢复及远端不确定结果；账号确认覆盖展示后目标变化，不误确认其他记录。
5. 服务覆盖缺失/手写/其他用户/目标路径不匹配、权限失败、启动条件跳过、过渡状态、enable 与 start 分离、disable 与 stop 分离；验证参数不会被当作 shell 代码。
6. Linux CI 验证实际 systemd unit 解析及参数边界；macOS 验证功能边界。外部系统与凭证使用测试替身，保留已有配对及安装回归，运行 go vet、go test -race、安装测试、ShellCheck 和更新文档构建。
