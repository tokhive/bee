# Bee 交互菜单的完整命令覆盖

## 状态与需求

状态：用户已于 2026-10-26 明确批准；按本设计编写计划并直接执行，不使用子代理。

用户明确要求：交互菜单应包含所有既有 Bee 命令的功能。此前菜单按常用管理动作实现，遗漏了前台引导启动、按现有配置前台运行、官方客户端专项检查以及部分高级参数。本设计补充既有菜单，不改变现有命令的业务含义。

## 源码核对与覆盖目标

依据 agent/cli.go 的命令分派、agent/start.go 的帮助和实现，以及各命令实际注册的参数。帮助文本中的“所有命令都支持 --config”并不适用于 codex-status / claude-status；覆盖以实际实现为准，并同步纠正该说明。

| 既有命令 | 当前菜单覆盖 | 补齐后的入口 |
| --- | --- | --- |
| start | 缺少前台引导启动；现有启动仅控制 systemd | 启动 Bee → 引导补齐配置 |
| run | 缺少前台常驻运行 | 高级选项 → 按现有配置前台运行 |
| login | 配对/重新配对已有；缺少自定义设备名称和配置路径 | 设备配对；名称在配对流程中设置，配置路径在高级选项中设置 |
| setup | 已有账号选择；缺少客户端目录、代理、自定义供给配置等设置 | 供给账号 → 选择账号及配置选项 |
| status | 已有默认配置的综合状态 | 运行状态；作用于当前选择的设备配置 |
| supply-status | 合并在账号状态中，前置账号请求失败会阻断供给查询 | 供给账号 → 接单状态，可独立查询 |
| account-status | 已有账号与接单的合并查询 | 供给账号 → 已登记账号，可独立查询 |
| pause / resume | 已有 | 供给账号 → 暂停/恢复接单 |
| confirm-account | 已有，绑定展示的待确认记录 | 供给账号 → 确认账号变更 |
| codex-status | 仅有配置时的账号检测，未覆盖独立检查和能力查询 | 供给账号 → Codex 检查：本地登录、模型与订阅额度 |
| claude-status | 仅有配置时的账号检测，未覆盖独立检查、身份验证和能力查询 | 供给账号 → Claude Code 检查：本地登录、在线身份、模型与订阅额度 |
| doctor | 已有检查；缺少 JSON 输出及自定义路径 | 日志与诊断 → 运行诊断 / 查看诊断 JSON |
| version | 版本显示在状态页 | 帮助与版本 → 程序版本，独立于配对和网络状态 |
| help、-h、--help、各子命令 -h | 菜单内缺少帮助入口 | 帮助与版本 → 使用说明 / 命令与参数参考 |
| --version | 与 version 相同的能力 | 共用程序版本入口 |

系统服务启停、开机自启和服务日志是菜单已有的附加功能，保留。

## 方案比较

推荐按用户动作分组：覆盖全部命令能力，主菜单保留九个清晰入口；参数放到对应动作的选项页，沿用逐行数字交互。业务规则复用现有命令，新增菜单组织与参数收集。

备选为逐条列出全部命令：同样能完整覆盖，但主菜单需要展示至少十五项命令加服务管理入口，用户需要理解命令名及重复的状态查询。实现稍直接，日常使用更繁琐，因此不推荐。

## 启动交互

2026-10-27 用户批准自动检查配置，替换此前“是否引导配置”的提问。选择“启动 Bee”后不再额外确认启动。

- 先检查实际后台能力和运行状态。匹配的服务已 active 时提示已经运行，不重复启动或配置；查询权限错误、unit 用户或路径不匹配、定制 unit、异常状态均保留具体证据并停止。
- 启动前只读检查设备和供给文件。缺少设备配对或配对未完成时自动引导；缺少供给文件时自动进入账号选择。两者均已就绪时直接启动。
- 文件读取失败、权限错误、JSON 或字段损坏时停止，显示路径、失败原因及修复指引，保留文件；不得当作缺失覆盖，也不能先改另一个配置再发现本地损坏。
- 已配对设备启动前向 Hive 验证身份。只有 Hive 明确返回设备替换或凭证失效（401/403 与对应机器码）才进入重配对引导；网络、服务端和未知认证错误停止本次启动并保留配置。
- 重配对保留最终确认、配置锁、变更检测和私有备份；只有确认后才停止匹配服务、备份旧设备文件、创建新配对。供给选择保留。未完成的配对直接续配，不再询问验证还是重配。
- 取消配对或账号选择、拒绝保存、EOF 均不继续启动。设备配对、账号保存等写配置确认仍保留；修改既有配置使用主菜单。
- 供给文件有效但官方 Codex/Claude 登录缺失或失效，不重新选择账号；允许启动并由运行时提示恢复官方登录和自动同步。
- Linux 且安装器管理的 systemd 服务与当前用户、程序、设备及默认供给路径匹配：自动后台启动，验证 active 后返回菜单。macOS、缺少 systemctl、明确未以 systemd 启动的 Linux、未安装 Bee unit：自动前台运行。
- 普通启动固定使用设备文件旁的 egress.json，完成或取消后恢复会话自定义路径。高级选项保留“按现有配置前台运行”，覆盖 run、自定义供给配置及缺少默认供给文件时仅在线的功能，仍展示并确认目标。

上述实现沿用现有运行器和系统服务管理，不增加服务安装、launchd、nohup 或持久化偏好。

前台运行前展示目标 Hive、配置和运行方式，并说明：当前终端会持续显示运行状态；Ctrl+C 停止本次前台 Bee 并退出程序，与现有 start/run 的生命周期一致，再输入 bee 可重新打开菜单。后台启动成功后返回菜单，退出菜单不停止后台服务。

2026-10-27 呈现补充：前台开始连接时显示黄色加粗“⏳ 正在启动 Bee…”，实际连接 Hive 成功后显示绿色加粗“✅ Bee 持续运行中…（已连接 Hive）”，上下留白突出状态。保留 Ctrl+C 退出说明及原文运行日志；连接成功不表示供给账号授权已就绪，账号告警仍照常显示。中英文随菜单语言，NO_COLOR 去除颜色，TERM=dumb 去除 emoji 与 ANSI；普通 CLI 日志格式保持。

前台与后台不能绕过配置锁并行占用同一设备配置。不自动停止现有进程、不擅自替换服务。引导和独立配对/账号选择共用输入读取器，避免嵌套读取吞掉数字选项。

## 参数与高级选项

- --config：选择本会话操作的设备配置；默认沿用当前用户默认路径。切换后明确展示当前目标，并重新计算关联供给配置和服务匹配信息。
- --egress-config：在原本支持此参数的 setup、run、doctor 动作中选择文件。start/status 仍使用与设备配置相邻的 egress.json；交互页明确展示实际路径，不暗中扩展命令语义。
- --hive、--name：配对流程中填写；已有配对切换 Hive 仍需原有显式重新配对和备份流程。
- --platform：通过 OpenAI / Claude Code 数字选项选择；setup 支持单个平台或两者。
- --account-fingerprint：从实际查询结果展示并确认完整待确认指纹，保留现有确认记录校验。
- --codex-home、--claude-config-dir：在账号配置或专项检查中选择官方客户端目录；保留未指定、明确清空及明确设置的区别，特别是 Claude 目录参数的环境覆盖行为。
- Codex --store=file/keyring/auto，Claude --store=keychain/file：专项检查按既有命令能力提供选择，展示当前平台的限制。Codex --keyring-backend 当前唯一实现是 direct，显示实际采用值，无需无意义地让用户二选一。
- --connect-proxy：账号配置中支持保持原值、设置本地 HTTP 代理、清除代理；沿用现有验证规则。
- --capabilities、Claude --verify：作为专项检查子项。展示本地读取与向官方平台查询的区别，用户选择后才执行在线请求。
- --json：诊断页支持查看完整 JSON，保持 CLI 的字段与含义；不新增自动上传或文件导出。
- --yes：交互中提供选择全部符合条件账号的操作，并在最终提交前明确展示目标和影响；脚本参数原语义保留。
- 帮助与版本：覆盖命令帮助、参数帮助和版本别名，不依赖设备配对、供给配置或网络成功。

会话参数选择本身不写服务、不改进程环境；只有用户执行并确认既有写操作时才保存相应配置。自定义路径不放宽服务管理的用户、可执行文件和配置匹配检查。

- 对照命令分派和参数定义逐项核验能力，任何未覆盖项都明确阻止宣称完成，不用显示一条需手动复制的命令替代交互功能。
