# Bee 桌面：AI 账号接入与贡献运行

日期：2026-10-26。状态：**spec 已获用户整体批准；对应实施 plan 待审阅和选择执行模式**。本文为三份后续 spec 的第一份，代号 S1；[S2 诊断与日常体验](2026-10-26-desktop-diagnostics-experience-design.md)、[S3 安装更新与发布](2026-10-26-desktop-release-update-design.md)已随本文整体获批。[对应实施计划](../plans/2026-10-26-desktop-account-runtime.md)已写成，待整体审阅。

## 1. 用户最终得到什么

用户完成现有设备配对，在 AI 账号页检测已有登录或启动官方登录，确认选择 OpenAI／Claude 账号后，点击“开始贡献”，Bee 才真正连接、同步账号并运行。用户能看到没有接单的具体原因，处理过期和换号，重启后保留选择。两平台可以分别接入、暂停、恢复。

S1 完成必须得到可操作的真实闭环，不能以“按钮显示依赖”“只读快照正常”代替。账号观察计划已经完成，本稿复用其成果，不重复实施六个 Task。

## 4. 运行归属、配置与状态

Rust 继续只管理它创建的 Go 子进程。Go 新增一个桌面运行控制器，管理运行上下文、每平台同步器和不可混用的运行实例编号；stdout 仍只写私有协议，诊断走独立通道。管理进程 ready 不代表贡献已启动。

设备配置仍为 `bee-desktop.json`。首次设备业务访问时，由共享设备会话取得现有配置锁并持有到管理进程结束；设备、供给、账号、运行入口共用它，不能各自重新取得同一跨进程锁。进程内将配置修改串行化，不在配置互斥锁内等待长期网络工作。未得到归属锁不能启动贡献或修改账号；hello／ping 仍不读取配置。CLI 使用原文件和锁语义，不覆盖 `bee.json`。

账户选择继续放在已批准的独立 `ai-accounts.json`：迁移现有提醒格式时保留去重信息，增加按 Hive／owner／device／platform 隔离的来源、指纹、已确认代次、选择修订、未决动作、运行意图和会话结束标记。存储仅保存必要元数据及来源引用，不复制官方 token。未知版本、损坏、保护失败均保留原文件并阻止有副作用的动作，不静默重建或猜选账号。

设备凭证或来源即使被复制到其他位置，也不能据进程名声称本机独占。首次连接遇到 Hive 重复连接冲突，显示“连接被占用／归属未确认”，停止自动抢占式重试，要求先处理外部运行。已有本次 owned 会话的网络重连可沿用核心退避；持续冲突转为需处理状态。设备身份不变不等于已有连接归本 App。无进程扫描杀进程、外部配置写入或新接管接口。

状态分四层显示：

| 层 | 状态与依据 |
| --- | --- |
| 管理进程 | 启动中／可通信／失败，依据现有桥 |
| 本机运行 | 未启动／启动中／运行中／停止中／失败，依据实际上下文及 worker 生命周期 |
| Hive 连接 | 未连接／连接中／已连接／重连中／身份拒绝／占用未确认，依据真实连接事件 |
| 各平台 | 未选择／待同步／授权异常／待确认换号／已暂停／可接单／状态未知，依据当前选择、真实同步及新鲜 Hive 供给 |

“可接单”不表示正在处理任务。只有运行确属本 App、连接正常、当前选择已同步且 Hive 允许准入时才显示贡献可用；没有可信任务观测时不显示虚构任务数或“任务已清空”。

## 5. 接入、开始与暂停

1. 检测后明确展示来源和账号；候选与选择分开。先核验设备、来源身份、候选修订和所需权限，再保存本次接入意图。
2. 首次接入前将该平台暂停并读回确认；失败或响应丢失时只核对，不继续注册或盲目重发。此暂停作用于同一 Hive 用户的平台，界面说明影响。
3. 原子保存经确认的来源和指纹并读回。尚未运行时显示“已选择，待开始”，不能显示已同步或已贡献。
4. 用户点击“开始贡献”：保存运行意图，建立 owned 运行和连接，在保持暂停时同步账号；核对指纹、generation、credential revision 和本次运行实例后，按本次明确授权恢复所选平台并读回。
5. 用户选了两个平台时逐平台反馈，不因一个成功将另一个标成功。一个账号异常不阻断另一平台的正常同步。不能自动读取或接入未选择的平台。

“暂停／恢复”继续使用已有供给控制，暂停不终止既有请求；恢复只改变平台准入，未启动运行时引导点击“开始贡献”。开始贡献可以合并本次用户明确选择的平台恢复意图，但不得顺便恢复未勾选平台或其他未决操作。

来源切换、增加平台及换号使用按平台的 worker 屏障：停止旧来源的后续维护提交，确认旧 worker 不再使用旧修订，才提交新修订并启动对应同步；不通过长时间持有全局锁阻塞另一平台。不要求为此实现完整账号移除或任务收尾事务。

## 6. 官方授权和授权维护

用户已确认方式 A：Bee 发起已安装官方客户端的登录动作；用户在官方页面／官方交互中登录，回到 Bee 后核验来源。缺少客户端时显示具体缺项和安装指引，不自动安装或冒充已授权。

按平台、已选来源命名空间解析可信官方可执行文件；固定参数直接启动，不把前端文本拼入 Shell。官方进程由独立句柄跟踪，记录启动／等待／完成待核验／失败／已取消；超时或取消只结束本次创建的进程，不退出已有官方客户端。需要终端交互的版本由官方交互界面承接，不在 Bee 收集密码、验证码或 token。若官方版本无法支持该入口，必须实现支持版本的适配或明确报告该平台未交付，不能以按钮不可用算完成。

登录可能改变官方客户端的当前账号，启动前说明。不要把 stdout、授权 URL 查询参数、回调码或完整路径转发到前端／普通日志。退出码为零只触发重新检测，必须核验预期来源和账号后才显示授权完成；仍由用户确认接入。取消不能撤销已完成的官方登录，迟到结果只能触发重新核验，不能自动选中账号。

运行期间复用现有维护任务、续期日记、写回并发保护和能力同步。相同身份的 token 更新不是换号；官方客户端并发写入后重新读取核验，不覆盖更新后的凭证。不支持续期写回的来源（包括现有 OpenAI Keychain 路径）说明须通过官方客户端更新；失效时停止使用该平台的新授权，保留恢复入口。页面刷新不触发续期。

## 7. 换号、结果未知与恢复

发现来源身份变化后，报告候选，停止以新身份接单或执行其授权维护；Hive 的 confirmation_required 只表示待确认，不能自动确认。原账号和新候选分别显示。

用户确认换号后：保存本次操作及原候选信息 → 确认平台暂停 → 核对当前来源和 Hive pending → 使用同一 confirmation_id 调用既有 confirm → 回读预期指纹及 generation → 原子提交来源修订 → 同步新授权 → 保持暂停。用户再点恢复。换号前是否运行不改变这个规则。

confirmation_id 只在 Go。POST 响应丢失、服务端成功但本地保存失败、重启、候选又变化时，恢复原操作并查询核对；不自动重复 POST 或新建一个确认操作。只有指纹相同不足以确认成功，还要检查代次和候选演进。无法证明结果时保留待核对，禁止恢复贡献。关闭弹窗不撤销已提交操作。

启动 App 时先加载选择和运行意图、核验设备及来源，再恢复此前用户选择的运行状态；首次从未开始过的账号不自动运行，暂停和换号后的暂停保持。明确停止贡献会保存“不运行”；明确退出 App 停止当前 owned 运行，但保留用户此前运行选择，下一次正常打开再按恢复规则核验。运行前先持久标记会话活动，正常退出后才确认结束；上次会话未正常结束、停止意图保存失败或状态不可证明时，下次启动先保持停止并要求明确恢复。更新遵循同一规则。

断网保留意图并按现有退避重连；401／403、设备撤销、身份改变和数据损坏阻断恢复，不能通过重新配对绕过。管理进程异常退出后界面撤销所有旧运行成功状态，先核对再由明确重启入口恢复，避免崩溃循环。

## 8. 停止、协议与跨 spec 交接

明确停止或退出先保存停止／退出意图，冻结新动作，再取消本次 owned 运行、关闭连接并等待本机 worker 退出；这是本机资源回收，不是等待 Hive 任务完成。界面说明可能中断任务。超过受控退出期限只可终止和回收本 App 的子进程；无法确认回收时不能报告已停止。停止意图保存失败也应继续回收本机运行，并明确报告保存未确认；不得因此在下一次启动自动恢复。关窗保持后台运行。

继续使用 typed 命令。新增逻辑能力为运行快照、开始／停止、官方授权开始／状态／取消；接入与换号沿用 account_action。快照携带实例、修订及观测时间，旧实例／旧修订结果不能覆盖新状态。长操作返回可查询的动作状态，不能让短请求一直占住桥；沿用现有请求期限，未知结果只核对。具体 DTO 在 plan 中一次定义并同步 Go／Rust／TS。

| 输出／输入 | 责任 |
| --- | --- |
| 运行、账号、供给和问题快照 | S1 提供真实且脱敏的数据；S2 用于诊断、通知和概览，不再维护第二套状态 |
| 停止及当前运行意图 | S1 提供；S2 的用户停止和 S3 的更新退出复用 |
| 有效网络配置及修订 | S1 先用现有网络环境和空的专用代理配置完成运行，预留明确配置输入；S2 接入持久代理设置，不成为 S1 开始贡献的前置条件 |
| 本机账号状态格式／迁移 | S1 负责，S3 验证升级与不支持的回退，不另外解释字段 |
| 真实三端来源和官方登录 | S1 实现适配并形成验收步骤，S3 在目标原生平台补齐证据 |

## 9. 验收与交付门槛

| 编号 | 用户可验收结果 | 必须覆盖的失败或恢复场景 |
| --- | --- | --- |
| R1 | 两平台检测、确认选择、重新打开保留选择 | 旧提醒文件迁移、写失败、身份改变、不读未选来源、不改 CLI／官方登录 |
| R2 | 已有登录能真实开始贡献，状态分别说明运行／连接／接单 | 管理 ready 但未运行；Hive 离线；重复点击；两个平台部分成功；锁冲突与外部 Bee |
| R3 | 两个平台均能由 Bee 发起官方登录并重新核验 | 未安装、不支持版本、权限拒绝、取消、超时、迟到完成、实际来源与选择不符 |
| R4 | 授权更新和来源恢复可继续使用，换号不自动恢复 | 并发官方写入、续期未知、Keychain 不可续期、候选替换、confirm 响应丢失、服务端成功本地失败 |
| R5 | 断网重连、重启恢复、手动停止与退出如实工作 | 未决操作跨重启；身份撤销；暂停不被解除；只回收 owned 进程；无任务收尾承诺 |
| R6 | 旧页面复用真实模型、额度及供给，消息无秘密 | 不显示资金或市场列表；未知／过期值不归零；旧实例结果丢弃；两平台问题独立 |

使用本地服务和合成来源验证副作用、响应丢失与竞态，不只直接赋值模拟终态。CLI 原有运行、续期与 doctor 相关回归继续通过。包内真实桥、原生页面和真实运行连接须验证，至少完成一套可用环境的真实授权与受控贡献闭环；实际任务验证须使用明确授权的测试账号和流量，不能自动消费用户账号。

S1 的 plan 应覆盖 R1–R6 的完整交付，不另把接入／运行／换号拆成长期“后续依赖”。三端原生环境或官方版本确有外部阻塞时，逐项说明已实现、已验证和未验证，不能宣称全部完成；这些证据在 S3 汇总。完成 S1 后，用户应能实际管理账号和运行贡献，S2／S3 补体验及发布，不替 S1 补核心功能。
