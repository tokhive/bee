# Bee 桌面：诊断、网络与日常桌面体验

日期：2026-10-26。状态：**spec 已获用户整体批准；对应实施 plan 待审阅和选择执行模式**。本文为 S2，依赖[S1 账号与贡献运行](2026-10-26-desktop-account-runtime-design.md)的真实状态和运行控制；[S3 安装更新与发布](2026-10-26-desktop-release-update-design.md)验证原生平台行为。[对应实施计划](../plans/2026-10-26-desktop-diagnostics-experience.md)已写成，待整体审阅。

## 1. 用户最终得到什么

用户遇到不能贡献时，能在诊断页看清是网络、设备、官方授权、额度还是 Hive 接单条件的问题；能查看运行日志、导出脱敏报告、配置本机代理。语言、主题和偏好重启后保留，关窗能找回，必要时收到系统提醒，开启后登录电脑可自动启动 Bee。

界面固定为概览、AI 账号、诊断、设置，另有“打开 Hive 控制台”。去掉普通原生界面的收益页面及资金引导；网站功能是否齐全不属于本稿任务。设备配对保留，设置不增加 Hive 用户登录。现有 demo 的资金内容只属于历史演示，不成为新验收前提。

## 3. 全局状态与导航

概览显示 S1 的本机运行、Hive 连接、两平台接单状态、原因和必要额度；不显示收益摘要。账号页复用已有原生卡片和详情；两页消费同一状态与供给控制。

S1 的后台运行和问题观测不依赖当前打开哪个页面。新增一个应用级状态订阅与周期核对入口，页面只订阅，避免每页各自轮询、重复维护授权或发通知。实例替换后清除旧运行状态；窗口隐藏时继续维护已确认账号，未选择来源不自动读取。

“打开 Hive 控制台”打开当前已配置 Hive 的站点根入口；地址由保存的 canonical origin 构造，不从网页传入任意 URL，不携带设备凭证、Cookie、登录码或账号信息。没有 Hive 地址时先进入设置／配对。站点要求登录时由浏览器处理，不嵌入登录 WebView、不自动回跳。平台准备、账号或报价需要运营处理时可指向此入口，但不能承诺站点一定存在某个资金页面。

## 4. 诊断与问题处理

点击“一键诊断”后，展示设备归属、运行归属、Hive 连接、所选官方来源、授权、额度、能力同步、接单条件及实际代理路径。结果为通过／提醒／失败／未检查，含检查时间、失败环节、可公开证据和处理入口。检查取消或某项超时保留已有结果并标出未完成项，不显示全部正常。

复用 doctor 的结构化检查函数；将 CLI 参数解析、输出和全局日志器修改留在 CLI 包装外，给桌面传入已核验的设备／账号快照及网络配置。不让 doctor 回退到默认 `bee.json`，不因诊断启动运行、续期、配对、暂停或自动修复。

进入诊断页仅展示已有结果；明确执行诊断才开展网络检查。已经确认接入的来源可以检查；未接入的平台显示“未检查／去检测已有登录”，不借诊断绕过首次读取确认。运行中检查使用 S1 的共享配置会话，不重新取得设备锁而失败。

错误说明至少区分本地读取、DNS／连接／TLS、HTTP 拒绝、身份不匹配、来源变化、限流和结果未确认。保留安全的检查项、平台、方法／路径、状态码和时间等证据，不把失败统一替换成“网络错误”。日志详细程度不能成为泄露响应体、凭证或个人路径的理由。接口要求未知原因时按未知显示，不能为诊断通过放松校验。

## 5. 日志与脱敏导出

运行核心输出结构化事件，日志是诊断资料，不作为运行状态的解析来源。记录时间、级别、模块、平台、公开错误码及已脱敏上下文；默认排除请求正文、模型输入输出、Authorization、Cookie、官方 token、配对令牌、confirmation_id、完整账号指纹和本机个人目录。命令及原生错误通过相同脱敏边界后才可持久化或展示。

保留有界本地滚动日志，建议每文件 5 MiB、最多 3 份；界面按模块／平台／级别筛选和查看最近记录，分页读取，不把完整日志反复推入前端。正式构建默认不启用调试正文；原有 stderr 尾部只作管理进程故障依据，不能未经处理直接导出。

导出包含版本、OS／架构、选择的诊断结果、脱敏运行日志、配置是否生效及观测时间。使用字段白名单再脱敏，路径只保留来源类型及必要末级名称；不导出任何配置文件原文、官方凭证或身份完整值。导出前给出内容范围，下载完成才显示成功，取消／写失败可重试，不伪造“已保存”。报告大小有上限，截断时说明截断范围。

不自动上传报告。真实外部故障如 409／EOF／TLS 应能由这些结果定位；不能仅靠改文案、忽略失败或关闭校验声称已修复。

## 6. 网络与代理（方式 A 已确认）

界面只接受空值或无认证、显式回环 IP 与端口的 HTTP 地址，如 `http://127.0.0.1:7890`、合法的 IPv6 回环地址。沿用核心校验，不接受 SOCKS5、远程代理、用户名密码、查询参数或任意路径。说明用户需要先启动本机代理工具。

| 流量 | 本次设置的作用 |
| --- | --- |
| Bee 向 OpenAI／Claude 转发的上游连接 | 使用配置的本机 HTTP CONNECT；空值沿用直连路径 |
| Bee 自己的官方 profile／额度／续期请求 | 复用 officialTransport；已有 HTTPS_PROXY／https_proxy 及 NO_PROXY 规则仍生效，否则使用本次本机代理 |
| Bee 与 Hive 的 HTTP／WebSocket | 不由本次专用代理字段控制；沿用原网络栈及进程环境配置 |
| 官方客户端执行登录时的请求 | 官方客户端自己管理；不声称 Bee 设置已替它配置网络 |

界面分别展示“已保存配置”和“当前实际生效路径”，只显示无凭证的摘要，不回显环境变量原文。原生账号查询也要接入同一官方 transport 策略，不能运行走代理、账号页面却另走一套未知路径。

保存前校验格式；用户可显式测试本机代理连接与固定官方只读端点，按检查结果说明可达性，不触发贡献或续期。测试失败不把旧生效配置抹掉。

运行期间保存新代理配置后显示“下次启动生效”；提供“停止并重新启动以应用”，用户明确确认可能中断任务后复用 S1 的停止／启动路径。保持此前平台暂停和未决换号状态，不顺便恢复全部平台。只读查询在当前配置应用后清理旧传输对象及来源缓存；旧请求的结果不能覆盖新配置修订。进程环境与本机代理导致不同流量实际路径不同时，界面据实说明。

## 7. 普通偏好、开机启动及窗口

新增普通配置 `desktop-preferences.json`，不与设备凭证或账号选择文件混存。语言、主题、通知开关和自启期望属于当前系统用户的 App 偏好；专用代理设置按当前 Hive origin 和已知设备范围保存；未配对时允许为所选 Hive 保存代理草稿用于官方只读查询，配对核验后再关联设备，不能因网络设置反过来要求先登录 Hive。无需 Hive 用户会话，也不导入 demo 的 localStorage。

偏好保存须原子写入并回读；失败保留此前已保存值并提示本次未保存。首次默认语言和主题跟随系统；中英文和浅色／深色／系统三种主题重启有效，系统变化可更新“跟随系统”模式。界面可在暂存状态预览，但要明确是否保存成功。

开机启动默认关闭，实际含义是当前用户登录桌面后启动 Bee；开启／关闭后查询系统登记结果再显示成功，权限拒绝或登记未确认不假报。只控制 Bee 自身启动项，不要求管理员权限或设置系统代理。自动启动恢复 S1 的此前运行选择，不自动授权、首次接入或解除暂停；托盘可用时后台启动，无托盘时显示可找回的窗口。

关窗继续后台运行；托盘、菜单、Dock／任务栏和再次启动 App 可找回原窗口，不再创建第二个 Bee。明确退出通过 S1 回收 owned 运行，可能中断任务；不实现等待任务退出。Linux 缺托盘时使用已有单实例重开等可靠入口，不能留下用户找不到的后台 App。

## 8. 系统通知

通知覆盖授权失效、待确认换号、持续离线、额度耗尽。来源必须是 S1 的真实、当前问题状态；保持现有问题去重与恢复语义，不因为切页、重开窗口或进程恢复重复轰炸。

“希望接收通知”和“系统实际允许”分别显示。请求系统权限由明确的开启入口触发；拒绝后保留应用内提醒及系统设置指引，不自动反复弹权限框。关闭通知不关闭诊断或清除问题状态。

通知内容只含平台、问题和处理入口；点击打开对应页面，不自动执行恢复、换号或开始贡献。发送失败不标记为已送达，同一未恢复问题不持续重试；权限改变或用户主动测试后可重新尝试。持续离线沿用当前已有去重延迟；网络恢复后重置对应问题，不能把一次失败直接当成持续离线。

S1 提供运行与问题事实，S2 负责用户诊断、日志存储、普通偏好和系统集成；S2 先显示现有桥提供的 App／Bee 版本；S3 接通更新状态及操作后接入设置页，不成为 S2 诊断／偏好交付的前置条件，S2 不自己实现更新。S3 的打包与升级必须保留本稿配置，并验证通知、自启和窗口在正式安装路径可用。

本稿功能先以本地服务、合成日志和原生适配器验证；实际网络和系统通知需原生证据，浏览器页面通过不能替代。S2 的 plan 覆盖 E1–E6 全部功能，不能只交页面后把 doctor／代理／持久化留成下一批。原生目标环境矩阵在 S3 统一汇总并复用仍有效的证据，不重复跑与改动无关的历史版本。
