# 安装器恢复已失效设备配对

## 已确认需求

用户在 Hive 删除或替换设备后，旧安装保留的设备身份遭到拒绝；已确认按“提示旧配对失效 → 用户同意 → 备份旧设备配置、保留供给配置 → 重新网页配对 → 启动”处理。延续当前 Bee #20、文档 #1，不另建 PR。

## 技术与方案

沿用 POSIX sh 安装器、Python 3 伪终端回归、systemd、ShellCheck、现有 Go 验证及 Docusaurus。恢复分支使用 Linux util-linux 的 `flock -n` 配合 Bee 已有 `bee.json.lock`；这是新增的恢复分支工具要求，Ubuntu 通常已提供，缺失则明确停止并保留原配置。不添加语言运行时、JSON 解析器或新的 Bee 命令参数。

选择安装器兼容恢复：只识别当前 v0.0.6 和本 PR 共有的完整错误行 `bound device credential is invalid; silent pairing is not allowed`。与新增 Go 重配对参数相比，这个方案能立即作用于用户当前发布版；自动清除任意登录失败的配置会误处理网络、权限和未知错误，因此不采用。识别失败时保留原诊断及退出码，不猜测。

## 流程与边界

- 第 1/3 步验证已有配对前，将设备配置复制到安装器私有临时目录作为比较快照；不解析或输出凭证。
- login 标准输出实时显示，标准错误保留后原样输出；非零退出且包含上述完整错误行时，才提供恢复选项。
- 中英文提示旧配对被 Hive 拒绝；询问“是否备份旧设备配置并重新配对？[y/N]”。说明保留账号选择、停止本机服务，以及网页确认替换可能停用 Hive 上另一台 Bee。
- 拒绝、回车默认否、EOF：保留配置，不停止服务、不启动服务、不输出成功；明确重新运行安装器可以再次进入恢复确认。
- 同意后先询问 Hive 地址；地址输入 EOF 仍保持原配置。提供新的 Hive 地址时也继续使用已有供给选择，这是用户已确认的重新配对过程。
- 地址输入完成后检查 flock，停止系统服务，拒绝符号链接锁文件，获得与 Bee 共用的非阻塞排他锁。在锁内确认当前设备文件是常规文件、不是链接，并且字节与验证前快照一致。锁被占用或内容变化时停止。
- 在设备配置旁创建唯一的 0700 备份目录，将旧 bee.json 移到目录内；保留其文件权限。公布备份路径。释放锁后运行既有 login --hive，仍通过网页确认配对。
- 配对成功后继续第 2/3、3/3 步，沿用 egress.json。配对失败则保留备份及新生成的未完成配对配置，停止向导；下次可按现有逻辑继续，不自动回滚或覆盖新凭证。
- 网络、配置格式、权限、锁等其他登录错误不触发恢复。active 服务原有仅询问重启的行为不扩张。无终端/关闭向导仍不进行配对或移走配置。

## 验证矩阵

接受恢复（中文/英文）、原始设备配置完整备份/0700 目录/0600 文件、供给配置逐字保留、完整三步；拒绝/默认否/EOF；Hive 输入 EOF；未知登录失败原退出码；停止服务失败；flock 缺失、锁占用、符号链接锁；确认期间配置改变；备份移动失败；新配对失败保留可恢复现场。Linux CI 使用原生 flock，macOS 回归使用 Python fcntl 的同一系统锁语义。独立依据为用户 v0.0.6 实际错误以及 agent/cli.go 对已绑定身份和 HTTP 401 的明确分支。
