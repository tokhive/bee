# Bee 中英文安装与启动交互设计

## 批准依据与范围

用户要求安装向导支持中英文，增加清晰分割线、状态图标和更美观的文案；先讨论完整交互再实施。经过样例修订，用户已确认继续：下载和安装单独显示结果，配置成功流程始终完整显示 `[1/3]`、`[2/3]`、`[3/3]`，已有配置减少输入但不能省略启动和最终结果。

本次覆盖安装脚本及其调用的 `bee login`、`bee setup` 正常交互文案。沿用已有配对、供给授权和 systemd 行为；继续更新 Bee #20 和文档 #1。用户已批准样例并要求继续，按本设计和计划执行。

## 语言选择

- 交互安装且未显式指定语言时，开头展示 `1) 简体中文`、`2) English`，提示 `请选择 / Select [1-2]:`，输入 1 或 2 后继续。
- `BEE_LANG=zh|en` 指定本次安装语言并跳过菜单；非法非空值在安装前报错，包含实际值及允许值。
- 无交互终端或 `BEE_INSTALL_INTERACTIVE=0` 时不询问语言。未指定语言时，按首个非空的 `LC_ALL`、`LC_MESSAGES`、`LANG` 判断；以 `zh` 开头使用中文，其他使用英文。
- 菜单无效输入重新询问。菜单 EOF 沿用环境语言完成安装，并跳过后续交互；不能消费管道中的脚本内容。
- 所选 `BEE_LANG` 传给 login/setup。`BEE_INSTALL_UI=1` 仅标记安装器调用上下文，用于省去子命令中重复的“接下来运行 bee run”等引导；不写入 systemd 环境或修改账号配置。
- `bee login/setup` 独立调用也识别 `BEE_LANG`，未指定时使用同一环境语言规则；其他 Bee 命令和后台结构化日志的全面翻译不在本次范围。

## 显示规则

- 普通交互终端使用标题、40 字符横向分割线和少量状态 emoji；阶段标题为青色、成功绿色、提示黄色、失败红色。
- 非终端或 `TERM=dumb` 使用 ASCII 分割线与普通状态文字，不输出 ANSI 控制符或 emoji；非空 `NO_COLOR` 禁用颜色，仍保留支持终端的图标与分割线。
- 使用固定行长分割线，不以右侧边框对齐中文或 emoji。所有内容逐行保留，便于回看和复制日志。
- 参数、路径、URL、错误码和第三方命令原始诊断原样显示，不经 shell eval，不翻译或吞掉原始错误证据。
- 正常安装、确认、配对说明、账号发现及选择、步骤、成功结果和手动命令标签均提供中英文版本。已有 coded error 的底层诊断可保持原文，外层状态与说明使用所选语言。
- 首次设置/启动默认是 `[Y/n]`；运行中服务重启默认否 `[y/N]`。保留逐账号授权；账号提示无效回答必须重新询问，EOF 不得被当作同意。

## 分支与失败

后续经用户确认新增旧配对恢复分支，详见 [安装器恢复已失效设备配对](2026-10-26-install-repair-design.md)：仅在已知的已绑定凭证拒绝错误后询问是否重新配对，默认否；同意后备份设备配置并保留供给选择，再继续三步。下述一般失败停止规则仍适用于其他错误。

- 已有设备配置：第 1 步显示正在验证配对，调用 login；未完成配对继续网页确认。第 2 步已有供给配置则显示沿用；第 3 步仍启动并检查服务，完整显示结果。
- 活跃服务：显示更新完成和重启会中断当前工作的说明，仅询问重启；不展示配置三步。拒绝后显示当前进程继续运行及稍后重启命令；确认后检查 active 再显示结果。
- activating/reloading/deactivating：显示实际状态和状态/日志命令，不改动进程。
- 拒绝配置或输入 EOF：明确表示安装已保留、尚未由本次向导启动，打印配对、账号设置、启动、状态与日志命令。未开始的步骤不标完成。
- 任一步失败即停止；显示失败操作、相关路径/实际状态/退出码，保留原始输出和已生成配置。服务启动失败后提供 journalctl 命令；不得显示配置完成或正在后台运行。
- 只有 systemd 返回 active 才显示后台运行成功；连接和账号接单状态通过 `bee status` 检查，不由安装器推断。
- macOS 与 `BEE_INSTALL_SERVICE=0` 仅安装二进制，显示对应语言的 `bee start` 后续命令，不声称设置了开机自启。

## 兼容与发布

安装器仍下载官方发布的 Bee。完整中英文配对和账号交互需要包含本次 Go 修改的新二进制，与安装器配套发布。对旧 release 只传环境变量，不新增必须支持的 CLI 参数；旧二进制可继续运行，但自身文案保持旧语言。文档明确此边界，不能宣称仅更新远程脚本就能翻译旧程序。PR 阶段通过新 Go 二进制测试和真实伪终端安装测试验证，不擅自发布 release。

## 验证

- 保留全部安装身份、sudo 免密兼容、unit、配置及故障回归。
- 覆盖两种菜单选择、强制语言、locale 回退、非法语言、EOF、无终端、禁用交互、纯文本与 NO_COLOR。
- 两种语言均验证首次及已有配置完整显示三步；拒绝、重启默认否、失败不输出成功，且保留原始证据。
- Go 测试验证配对链接与代码、账号逐项选择、无效回答/EOF 不授权、语言传递和安装器调用不输出前台启动指令。
- 运行 `make test`、ShellCheck、文档构建；检查实际终端转录的顺序与样式，更新现有 PR 并检查 Linux CI。
