## 4. 诊断：C「问题优先」

### 4.1 页面结构与动作

页面标题使用公共壳。内容顶部为「检查结果／安全日志」页签；初次进入选中「检查结果」。检查页右侧为「运行诊断／重新运行诊断」主按钮和「导出脱敏报告」次按钮，运行时提供取消。日志页右侧只保留刷新日志操作。

诊断由用户主动触发；进入页面、切换页签、展开证据和浏览问题都不调用 `start()`。检查期间切到日志页不取消诊断，也不创建第二套轮询。桥、运行 ID 或网络修订变化继续按现有上下文隔离规则失效，旧结果不能覆盖新状态。

### 4.2 检查结果

上方显示检查时间、当前状态和各类数量。未运行、运行中、取消、完成分别呈现，只有已完成且所有已返回检查均通过时才可表达全部通过；空结果、部分完成、超时、未选来源、未知和取消均不能显示全部正常。

需要处理的 `fail`／`warning` 优先展示，按原报告的设备与连接、OpenAI、Claude 分组；只有存在问题的组才进入此区。摘要不把设备问题写成平台故障，不固定问题数量，不在 UI 重新判断授权、额度或接单条件。每组完整保留其问题检查、原始状态、原因和安全证据；同组出现多个不同原因时都可看到，不把同一平台的失败统一改写成一个硬编码原因。

每项处理入口使用报告已有 `next_action`；相同入口可以去重，不同入口均保留。跳转只导航，不自动修复、授权、开始贡献或恢复接单。

下方分别放「尚未完成的检查」「通过的检查」折叠区，显示真实数量。展开可查看每一项、观察时间和白名单证据。原报告内的检查必须完整且只出现一次：问题区 + 未完成区 + 通过区等于原报告，不丢检查、不把未检查改成通过。终态状态说明始终可见，不随折叠隐藏。

原型中的两个平台问题和 16 项检查只是视觉示例；正式支持报告实际返回的零到 16 项检查，包括设备／连接的问题。

### 4.3 安全日志与导出

日志页保留模块、平台、级别筛选、刷新、原生 cursor 分页和轮转截断说明。切换到日志页或改筛选不自动读取；明确刷新／加载更多才读。页面区分尚未读取、加载中、读取失败、已读取为空和有记录。筛选改变后清除旧范围，晚到结果继续受现有 request guard 约束。

日志用紧凑列表／表格，显示时间、级别、事件和可展开的安全证据，长证据换行。原有全部模块仍可筛选，不缩减为预览展示的四种。

导出范围弹窗保留「仅本次检查结果／本次检查结果与安全日志」、本机保存与 5 MiB 截断说明。确认后继续使用现有 `export()` 和 `downloadPayload()`，下载完成、失败、取消和结果未确认保持区别；不得用浏览器预览的 toast 替代真实下载回执。

## 5. 设置：B「分类页签」

设置页采用「通用／网络与代理／通知与启动／关于」四个页签。与所选预览一致，进入设置页默认展示网络与代理；内部切换不重建客户端、不重读整个系统状态、不丢代理草稿和测试结果。页签选择属于当前页面状态，不增加持久化配置。

| 页签 | 信息与操作 |
| --- | --- |
| 通用 | 语言（系统／中文／English）、外观（系统／浅色／深色）；更改后沿用现有保存及回读，失败保留此前已保存值和具体错误 |
| 网络与代理 | 代理编辑、保存、明确测试；已保存与当前生效配置；各流量实际路径；待重启状态和确认应用 |
| 通知与启动 | 希望接收通知与系统权限；自启期望与系统登记；失败证据、已有重试入口、重新检查系统状态；关窗找回说明 |
| 关于 | 桌面应用版本、Bee 版本、当前 Hive；没有版本观测时显示尚未读取，不用示例版本填补；不新增 S3 更新操作 |

### 5.1 网络布局与行为

正常窗口左侧为表单和待应用提示，右侧为已保存／当前生效配置及路径对照。左侧主要操作为「保存代理」，次要为「测试连接」；路径刷新使用弱化入口。当前 Hive／设备作用范围可见。未配对时仍可指定 Hive、保存代理草稿，用于已有官方只读查询能力，不要求 Hive 用户登录。

仅接受空值或核心已支持的无认证回环 HTTP 地址。沿用现有核心校验，不在页面另写代理解析规则。测试只检查代理连接与两个固定官方只读端点；HTTP 401 等结果按当前服务给出的可达性呈现，并说明不证明账号授权或额度。

保存与应用严格分离：保存成功不停止运行、不抹去旧生效配置。运行中显示「下次启动生效」；明确点击「停止并重新启动以应用」才展示可能中断任务的确认，确认后调用现有 `applySaved(true)`，继续保留平台暂停和待确认换号。取消确认不发应用命令。

路径对照完整保留：Bee 上游转发、OpenAI／Claude 官方查询与续期、Hive HTTP／WebSocket、官方客户端登录。环境变量优先级和 NO_PROXY 规则继续可见，只显示安全摘要。尚未读取或无法确认时按未知显示，不能伪造直连或已生效。

### 5.2 通知、自启与版本

通知开关代表应用期望，旁边独立显示允许、拒绝、尚未允许或尚未确认；只有现有明确开启／允许入口请求权限。查询状态、进页和切页签不申请权限；拒绝后保留系统设置文字指引及应用内提醒，不循环弹窗。

自启开关与系统已登记／未登记／尚未确认分开，仍以现有系统回读为准。保存失败、查询失败、通知送达失败和明确重试入口保持可见，不能用统一绿色成功状态掩盖。

不增加关闭窗口行为开关或等待任务退出。关于页的桌面版本读取现有构建清单，Bee 版本来自当前 bridge metadata；两个版本不互相冒充。

## 6. 响应式、语言和真实功能验收

最小窗口 860×600，正常对照尺寸 1440×1000。网络双栏在可用空间不足时纵向排列；页签、表单按钮、长路径和证据自然换行，页面可纵向滚动，不用横向宽表或隐藏关键操作维持比例。弹窗在窗口内可见、可滚动，Escape、焦点约束及关闭后返回触发入口继续有效。

中文与英文均覆盖新增及移动后的文案；用户数据、URL、错误证据原文不进入翻译替换。三种主题模式沿用真实偏好保存和系统变化。

验收至少包括：

1. 诊断手动触发、切页零业务写入、问题与其它检查完整覆盖、取消／未知／上下文失效、处理入口、日志按需读取及导出回执。
2. 设置四页签、草稿不丢失、偏好保存失败回退、通知查询不申请权限、自启系统回读、代理保存与应用确认分离、未配对草稿及路径未知。
3. 使用既有真实 NativeApp + IPC fixture 跑功能和明暗／中英／窄窗口检查；浏览器交互检查使用 ego-browser。纯间距、颜色调整不增加镜像式单元测试。
4. 原生窗口连接现有真实后端，验证主动诊断、手动日志、真实导出和代理只读测试可达；普通语言／主题验证保存。通知、自启不因本次视觉验收反复申请权限或修改登记；沿用已有原生证据，新增行为风险才补相应验证。
5. 公共壳同步后，用相同逻辑尺寸对照选定预览。当前 S2 壳与已批准公共壳的差异单列，未同步前不声称整个 App 已还原。
