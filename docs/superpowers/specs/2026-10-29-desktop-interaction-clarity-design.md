## 1. 目标与已确认范围

用户打开 Bee 后能理解当前能否接单、具体阻塞原因、可执行操作、操作结果和下一步，并通过实际可用的流程完成绑定、账号准备、开始贡献与恢复接单。覆盖正式 App 的概览、AI 账号、诊断、设置、更新与应用生命周期反馈。错误显示清楚但没有可走通的必要恢复路径，不算交付完成。

**整体完成原则：** 当前真实故障只是回归场景之一。以[全流程走查及76项场景矩阵](../reports/2026-11-01-desktop-full-scenario-review.md)作为范围与验收索引，覆盖每个正式入口的正常、空状态、加载、失败、结果未知、恢复、导航及重启；独立平台差异和共享故障分别验证。不能只修复当前 Hive 未连接或只让静态预览通过。

保留四页导航、银白／shadcn 视觉、现有真实业务能力；首次使用通过页面内提示和直接入口推进，不增加独立向导、必经欢迎页或一套持久化引导进度。概览以接单结论和下一步为主信息，进程与连接状态作为依据。

用户对方案 B 及原书面设计的批准见[相邻决策记录](2026-10-29-desktop-interaction-clarity-design-decision-trace.md)。采用视觉预览“方案 1：清晰分区”的状态层级与提示方式，页面布局和已有按钮位置优先沿用此前已批准的银白／shadcn 方案；预览中偏离原布局的位置不是实施依据。该编号不改变此前 B／C 的业务范围。本轮新增设计不追记为 10 月 29 日已经获批的决定。

## 2. 当前证据与设计约束

调查基线：Bee 桌面工作树提交 `021f800`。浏览器查看正式组件的模拟场景，不能据此声称真实账号授权、断网恢复和原生系统操作已通过。

11 月 1 日补充实际运行中的 Bee S1 Dev 证据，见[实况走查报告](/Users/dayong/myspace/mywork/tokenhive/design-previews/2026-11-01-bee-interaction/usability/REPORT.md)。18:22 的诊断返回 `GET /api/bee/identity → 401 / device_replaced`；运行快照为 `local=stopped, connection=disconnected`；OpenAI 的 `selected_source` 为 `source_missing`，Claude 为 `source_not_selected`。概览显示 `NETWORK_DEVICE_SCOPE`，账号页受启动错误阻挡，设置误显示“尚未配对”。启动错误与这次诊断是不同观测，不能断言来自同一次请求；不知道是谁、何时撤销了设备。

现有 `experience::initialize` 会将 `device_status` 的结果交给 `trusted_scope`，而业务失败可能在 `result.error` 中；必须先保留并透传该失败，不能将它替换为缺少身份字段的通用错误。`StartupGate` 还把管理进程可用与启动前置检查合并；这是恢复页被挡住的实现缺口。现有 `DesktopDevice::Begin` 明确禁止已绑定旧身份被拒绝后自动配对，新增恢复不能假称复用一个已经可用的按钮。

全流程补查进一步发现：初次读取一平台迟缓时已读出的设备／运行事实被整批等待挡住；诊断一次查询失败后停止轮询；设置草稿跨四页导航丢失；首次配对未完全遵守结果未知不重放；账号禁用动作缺少前置原因。现有预览套件的登录读取中、自动恢复过程两项连续失败。具体证据、边界和任务落点以走查报告 F02–F08 为准，不把已有部分测试通过写成整体可用。

| 现象 | 已核对依据 | 设计要求 |
| --- | --- | --- |
| 断线仍显示“贡献已启动” | `NativeRuntimeControls` 主标题仅使用本机运行状态；运行核心断线时保留进程、清除平台供给快照 | 综合新鲜运行与平台状态生成接单结论 |
| 侧栏反复显示“Hive 未连接” | `AppShell` 仅接收连接布尔值 | 区分停止、配对、连接、重连、拒绝、占用和未知 |
| 中文页面直接出现英文错误 | 设备、账号、设置、更新等页面直接渲染错误消息 | 在同一错误中提供本地化说明及完整安全证据 |
| 配对主动作弱化，错误设备卡贴住贡献区 | 配对链接使用 ghost 按钮；运行区底边与错误卡顶部没有区块间距 | 任务主动作突出，区块间距统一 |
| 读取中／失败时出现“0 个已接入” | 账号数由当前可读列表直接统计 | 未确认不能显示确定的零值 |
| “未配置账号或市场未开放”无法准确拆分 | Hive `platformSupply` 的不同分支共用 `not_configured`；缺少设备供给还可能涉及绑定或平台配置 | 由事实来源细分，禁止将缺少供给直接等同于用户未接入 |
| 旧客户端严格拒绝未知供给字段／原因 | Go 供给解码、Rust 桥及 TS 解码均校验契约 | 细分原因需要显式兼容方式，不能直接替换所有旧响应 |
| 设备凭据被撤销却只显示“结果未确认” | 真实诊断已有 `401 / device_replaced`，用户主提示缺少该码映射 | 直接说明凭据已撤销，提供受控恢复，不等待网络自动恢复 |
| 管理进程存在，但贡献已停止 | 真实进程列表与运行诊断分别确认 | 管理进程、贡献运行、Hive 身份检查各自命名，不能互相替代 |
| 本机身份“通过”、服务器却拒绝身份 | 诊断前者仅验证本地保存内容 | 分别标明“本机绑定信息完整”和“本次 Hive 身份核对失败” |

## 3. 一致的状态表达

### 3.1 三类事实与新鲜度

分别保留本机运行、Hive 连接、各平台接单三类事实。接单结论必须同时满足：当前绑定和运行实例一致、状态仍有效、本机正在运行且连接已确认、当前平台已接入、Hive 当前报告允许接单且未暂停。

“可接单”仅表示当前符合接收新任务条件。没有任务观测数据时，不显示“正在处理任务”或任务数。断线意味着暂不能正常接收新任务；已有请求可能中断，不能承诺继续完成。

无法读取不等于停止、断线、未接入或额度为零。已有记录可以保留为“上次确认”，附时间和过期标识；它不能继续支持可接单结论或相关写操作。手动停止和手动暂停使用中性状态，不作为故障报警。

### 3.2 概览主状态

先核对共享设备／运行实例事实的可靠性，再选择主状态。优先顺序为：共享依据不可用 → 已确认的核心失败、身份拒绝或连接占用 → 设备绑定阶段 → 正在开始／停止 → 确认没有已接入账号 → 本机已停止 → 连接阶段 → 平台接单结论。下表列出各条件的表达。单平台读取失败不属于共享依据失效，不抹去另一个平台已确认可接单的状态；旧实例的具体错误不能覆盖当前“待确认”。

| 条件 | 主状态与说明 | 主要处理位置 |
| --- | --- | --- |
| 初次读取，尚无有效事实 | 正在读取设备与账号状态… | 原位加载，无“0 个账号”或未绑定结论 |
| 共享依据读取失败／结果未知 | 无法确认当前接单状态；附最具体失败事实和实际核对进度 | 错误详情及匹配的处理入口 |
| 已确认核心启动失败／运行中断 | 贡献未能启动／贡献已中断，按实际失败阶段区别 | 显示具体失败及修复路径；核心不可用时指引从应用菜单退出并重新打开，不伪造一键重启能力 |
| 未绑定，且事实已确认 | 尚未绑定这台设备 | 设备绑定区 |
| 等待网页确认 | 请在 Hive 网页确认设备归属 | 打开 Hive 确认网页 |
| 已绑定且确认没有已接入账号 | 尚未接入 AI 账号 | 前往 AI 账号并定位可操作的平台 |
| 已有账号，本机已停止 | 贡献尚未启动／贡献已停止，按已知事实区别 | 开始贡献 |
| 正在启动或停止 | 正在启动贡献…／正在停止贡献… | 显示进度，防重复操作 |
| 正在首次连接 | 正在连接 Hive… | 展示连接状态；失败后显示实际原因 |
| 运行中断线 | 与 Hive 的连接已断开，暂不能接单 | 实际正在重连才显示重连进度 |
| 身份被拒绝／连接被占用 | 设备身份未通过 Hive 验证／设备连接被占用 | 查看具体原因，按已有能力处理 |
| 本次确认 `device_replaced` | 设备授权已失效，当前无法接单；附实际贡献状态 | 重新绑定此设备（§4.1）；不显示自动重连倒计时 |
| 已连接，所有已接入平台均暂停 | 已连接 Hive，尚未开启接单 | 定位平台行的恢复接单按钮 |
| 存在可接单平台 | 单平台显示“OpenAI 可接单”；多平台显示实际数量 | 各平台暂停／恢复和问题入口 |
| 已连接，但无平台可接单 | 已连接 Hive，暂不能接单 | 最优先问题及对应平台 |

运行中的“停止贡献”始终可发现，并沿用真实操作前置条件；它与“处理当前问题”分工明确。未知状态不能通过额外按钮绕过既有停止／恢复校验。若一个平台可接单、另一个异常，主状态同时给出“OpenAI 可接单；Claude 需要处理”的事实。所有平台暂停且另有阻塞时，同时指出其他原因，不能承诺点击恢复即可接单；可用性仍由真实条件控制。

侧栏复用同一状态来源，给出简短摘要和“查看连接详情”入口；正常停止不显示网络故障。展开入口导航至已有概览连接区域，不创建第二套连接控制。页面间的同一事实使用相同名称、严重程度和更新时间。

### 3.3 启动受阻时仍可处理问题（11 月 1 日补充）

分开管理进程／协议可用性、启动前置检查和业务运行状态。可信管理进程已可通信但设备／网络核对受阻时，四页内容仍可呈现；共享错误显示在相关区域，不能把概览和账号页全部替换成一条英文错误。二进制完整性失败、协议失败或管理进程不可用仍按原有硬性保护阻止原生操作，不能借此开放恢复命令。

| 操作 | 设备身份未通过时的行为 |
| --- | --- |
| 查看本机保存的 Hive／设备记录、贡献快照、诊断和报告 | 可信管理进程可用时可用；本机保存记录标为上次信息，不冒充服务器认可 |
| 自动读取本机登录、调整读取位置草稿 | 可用；只产生本机候选，不触发旧账号操作的自动重放或 Hive 注册 |
| 通过官方客户端登录 | 本机贡献已确认停止、无冲突操作且满足原有授权前置条件时可用；仍由用户确认 |
| 设置语言／外观、查看网络配置 | 可用；未知绑定不显示“尚未配对”；有身份范围的代理应用继续要求有效范围 |
| 打开 Hive 控制台 | 从核心校验过的已保存 origin 生成固定控制台地址；不依赖本次远端身份成功，不接受页面任意 URL |
| 接入／换号、恢复接单、开始贡献 | 继续要求有效身份及各自前置检查；禁用处显示具体原因和设备恢复入口 |
| 停止已有运行 | 以本机真实运行与所有权判断可用性，不因身份请求失败隐藏必要停止操作 |

提供“重新检查设备”来重跑失败的设备／启动前置核对，操作显示进度、最新结果及时间；它不重启进程、不开始贡献、不解除暂停。修复网络或完成绑定后可在同一 App 会话重新通过启动校验，不要求退出 App 才清除永久失败标志。保留既有启动时网络应用、更新核验、运行恢复顺序；新的恢复检查不得再次执行自动运行恢复。

已确认的当前 `device_replaced` 可以与同一绑定下的本机停止事实组合成明确阻塞；缺少无关账号数据不应覆盖该已知原因。事实携带绑定／实例与观测时间，已换绑定后的旧错误不得覆盖新状态。

### 3.4 分阶段读取与操作前置原因

共享设备／运行／来源默认配置已读取成功时及时发布；账号和供给按平台独立完成。一个平台慢请求、失败或等待官方权限，不能把另一平台与已经确认的共享事实一起隐藏。保持唯一协调器、现有请求期限和实例／revision屏障，不通过多个页面并发轮询解决。初次读取、后台有效刷新、过期等待读取、正在重试、停止重试分别表达；过期使旧报告不可操作，但未实际发起读取时不得写“正在核对”。

主要动作禁用时，邻近显示同一前置判断得出的具体原因与下一步，例如先停止贡献、先恢复设备、候选正在刷新、已有操作结果待核对。提交时条件变化使动作失效，要说明变化并引导重新确认，不能静默无反应。该说明不放宽核心权限或承诺未知条件下的操作。

## 4. 轻量首次使用与页面结构

已确认未绑定、配对进行中／过期，或已绑定且确认没有接入账号时，概览提供轻量准备提示：“绑定设备 → 接入账号 → 开始贡献 → 开启平台接单”，突出当前可执行的一步，并提供现有入口。该提示按当前缺失配置出现，也适用于用户主动取消全部本地选择后的重新配置；不宣称识别用户是否第一次使用。步骤仅解释依赖，不锁定访问顺序；例如未绑定时仍能查看账号、设置代理和运行允许的检查。

进度从真实设备、账号、运行和平台状态推导，不保存另一个“已完成第几步”。已绑定且至少接入一个账号后收起整条准备提示，主状态与平台行继续就地引导“开始贡献”和“恢复接单”。日常暂停、停止或临时断线不重现整条准备提示。状态未知时保留已知内容或读取反馈，不从读取失败推断配置缺失；无需新增持久字段追踪用户是否看过提示。

概览保留运行摘要、设备信息、紧凑账号列表。绑定未完成时突出设备操作；绑定后设备信息收回为三列摘要。概览不新增常驻副标题。账号暂停／恢复按钮继续位于额度下方；问题入口可导航到账号详情或设置目标，不移动既有运行操作的业务职责。

配对等待区使用高对比主按钮“打开 Hive 确认网页”，提供“复制配对码”和“复制确认网址”作为次操作，并反馈复制结果。显示剩余有效时间及明确到期时间；计时到期先核对，确认过期且无未决写入后主动作改为“重新生成配对码”。网页确认后由既有核对机制确认绑定；没有接入账号时显示“设备已绑定，可继续接入账号”，已有账号则指向其当前下一步。打开网页失败不撤销已有配对请求，保留网址及手动打开指引。

设备核对失败时保留最后已知信息并标记待确认，不把网络读取失败渲染成首次绑定表单。只有确认未绑定才提供首次绑定操作；已配置设备的凭据失效按 §4.1 人工恢复，身份冲突／连接占用不自动重新配对。设备名称和 Hive 输入在允许编辑的流程内保留。

### 4.1 设备凭据失效后的重新绑定（11 月 1 日新增设计）

选择在现有概览设备区提供有明确确认的恢复流程。仅显示错误和导出报告无法解决本次凭据撤销；自动清空配置重新配对会破坏用户控制与已有归属规则。新增流程复用 Hive 已有网页确认、替换前收尾、配对轮询和身份回读，不建立新服务或独立向导。

1. 本次针对当前保存凭据的身份查询明确返回 `401 / device_replaced` 或 `401 / invalid_device_credential`，且本地已有完整绑定记录时，显示“重新绑定此设备”。超时、503、无领域码的 401、403、连接占用和本地配置损坏均不能推导为这一条件；分别核对具体错误。
2. 确认弹窗列出当前 Hive、上次设备信息、旧凭据不可再用的证据，并说明：下一步要在 Hive 网页确认；若账户已有另一台有效 Bee，是否替换由网页明确确认；本机贡献保持停止，账号需重新确认接入。取消弹窗不发送请求。
3. 提交前核心重新检查同一绑定仍满足恢复条件、本机运行已停止、所有本机写入 worker 已退出且没有未核对的账号／设备写结果。运行中先提供“停止贡献”及影响确认；停止结果未知或旧操作未决时保留阻塞，不能清空记录绕过。
4. 核心在受保护的桌面目录中保存单个恢复记录和新配对凭据，再创建配对请求；旧配置保留至新身份核对通过。UI 只接收公开配对码、固定同源确认网址、阶段、时间和安全错误，不接收新旧凭据。双击、离开页面或重启继续同一恢复记录，不生成另一笔恢复事务。
5. 网页确认后自动核对原配对。每次已授权兑换尝试只提交一次；响应丢失后查询原配对及新凭据身份，不重放未知兑换，明确未提交的业务拒绝按 §4.2 处理。创建配对请求响应丢失且未取得配对 token 时，保留“创建结果未确认”，禁止另建请求；当前 Hive 协议没有查回该 token 的能力，显示导出检查信息与需 Hive 侧核对的明确说明，不伪造“重试即可恢复”。这是协议限制，不得记成恢复成功。
6. 新凭据身份经 Hive 回读确认后，校验它属于本次固定 Hive 和本次新凭据，再原子保存为当前桌面绑定。若网页确认了不同所有者，本机额外明确确认新归属后才采用；旧账号数据从不跨所有者自动使用。崩溃在远端成功／本地保存之间时继续核对并完成本地保存，不退回旧凭据、不再次兑换。
7. 新绑定使用新的账号作用域；旧本机记录留存，不直接迁移已接入状态、待确认操作、运行意图或自动恢复平台列表。重新读取本机登录，由用户确认接入，完成后仍暂停；之后由用户依次开始贡献和恢复平台接单。旧设备范围的代理设置不自动作为新设备已生效配置，需明确确认保存／应用。

关闭恢复面板不等于取消远端配对，不展示没有服务器保证的“取消成功”。配对确定过期且不存在兑换结果未知时，用户可重新生成；未决操作不因本地计时到期被删除。恢复记录损坏、磁盘写入失败或锁冲突时停止当前步骤并保留证据。正常应用重启只能继续核对已有事务，不能代替用户确认。

重新绑定处理的是设备访问资格，不能承诺恢复后马上接单；OpenAI 登录缺失、市场未开放、手动暂停等独立阻塞继续显示。首次配对、已有有效设备、设备替换的既有行为必须回归，不能为本次恢复绕过 Hive 的归属确认和收尾条件。

### 4.2 所有配对路径的结果与恢复

首次配对与凭据恢复均区分创建、等待网页、等待旧设备收尾、兑换、身份回读和本地保存。`draining` 说明实际等待条件，不能承诺完成时刻或提供强制接管；打开网页失败保留原请求。本地计时结束先核对，只有确认过期且无未决写入才允许用户重新生成。

创建和兑换都在提交前持久化本次尝试；传输失败或响应丢失后继续原操作查询，不能因再次打开页面、点击核对或重启再发 POST。轮询返回 approved 本身不证明上一笔兑换没有在途提交。只有明确业务拒绝并有未提交保证的情况，才按对应恢复条件继续；不能把一般超时或503当作该证明。创建未知但未取得token、旧数据缺少可证明的提交阶段时，保留具体阻塞和人工核对指引，不自动清空配置。复用桌面配对记录管理，不新建通用任务系统。

候选来源未找到、读取失败、过期、身份变化分别呈现。接入前确认说明影响：使用哪个账号、会暂停此 Hive 账号对应的平台、接入本身不开始贡献。换号展示当前与目标账号标识及完成后仍暂停；重新登录说明会调用官方客户端并可能改变其登录。不要将这些说明重复放在每行正常状态中。

账号只有指纹时标为“账号标识”，不伪造邮箱或用户名。尚未确认的套餐显示“套餐待确认”；尚未接入时省去无意义的“未知套餐”标签。计数仅在相关平台均已确认时显示确定总数；部分已知时显示“已确认接入 1 个，其余待确认”。

每个平台展示主要接单结论、主要原因和匹配入口；其他实际阻塞仍可展开查看。重复的同一故障合并展示，不能合并互斥原因或丢掉独立问题。额度未知、报告过期、已耗尽分别呈现；旧额度标出观察时间，不能以空条表达 0%。保留全部已有额度窗口、已用百分比、真实重置时间和超过 100% 的实际值。

来源读取方式继续保留在详情中，并沿用此前默认展开的决定。修改来源后自动读取；读取失败显示匹配的原因和恢复入口，不要求用户通过离开再进入页面来理解如何继续。权限授权等必要操作有直接入口，修改来源或完成授权后恢复自动读取，不重新引入日常“检测已有登录／检查账号”按钮。修复只恢复读取，接入、换号、恢复接单仍由用户触发。

官方登录完整覆盖未安装、不支持版本、启动失败、等待用户、超时、取消、取消结果未知、进程退出但来源未变化／身份不符、迟到完成。只有预期来源核验成功才显示登录完成，随后仍只是候选；退出码为零不等于完成，取消也不能撤销已经发生的官方登录。平台不支持的存储方式给出具体限制，不擅自切换到另一来源。

取消接入仅保留已确认的“取消尚未注册的本地选择”；不新增完整移除已注册账号功能。候选过期、正在刷新、写操作未决等条件要解释清楚；换号、暂停和账号注册的独立阻塞不能靠反复登录消除。

## 6. 原因与恢复动作

### 6.1 统一呈现规则

一个问题的可见输出包含：最具体的已确认失败事实、影响、实际可用下一步，以及同一提示内可展开的技术详情。详情保留失败操作、环节、错误码、时间、相关安全实际值、原始原因链和安全响应内容；不能只写到另一个日志文件。

示例：“Hive 返回服务暂不可用（HTTP 503），本次未能确认设备归属。”只有本次收到 503 才使用该句。DNS、TLS、连接拒绝、超时、401／403、409 等各按实际证据解释；不能将所有连接失败归为代理错误。

未知错误显示已知失败环节和实际原文，不推测具体原因。删除令牌、凭证、授权 URL 的秘密参数、敏感文件内容等；已有诊断脱敏边界继续有效。可见翻译不以吞掉原错误、只保留通用短句为代价。

### 6.2 恢复动作匹配

| 原因 | 提示重点与操作边界 |
| --- | --- |
| Hive 地址解析失败 | 显示实际目标和解析失败；检查对应网络／Hive 配置。已绑定地址不可随意修改时明确说明，不能出现无效编辑按钮 |
| Hive 连接超时／服务暂不可用 | 显示实际失败和核心当前重连状态；提供查看连接检查，不引导修改与 Hive 无关的上游代理 |
| 设备凭据明确被撤销／失效 | 显示实际 401 和领域原因，按 §4.1 提供明确确认的重新绑定；保持停止，不自动抢连或重绑 |
| 其他身份拒绝或身份不一致 | 显示本次拒绝证据，重新检查设备／打开 Hive 查看；不当作凭据撤销，不清空本地记录 |
| 设备连接被占用 | 说明当前连接归属未确认，提示检查另一处 Bee；不杀进程、不自动接管 |
| 未接入平台账号 | 前往对应平台接入；没有登录时提供官方登录入口 |
| Hive 未开放平台模型交易 | 明确需由 Hive 管理员处理；可查看详细原因，不提供反复登录或无效重试 |
| 授权同步未完成 | 按实际同步状态显示进度或具体失败；不直接认定需要重新登录 |
| 账号被拒绝／登录过期 | 对应平台重新登录；若必须先停止贡献，提供明确前置入口并说明影响 |
| 额度耗尽／上游限流 | 有可信重置／恢复时间才显示；无需用户修复时说明等待条件，不假造倒计时 |
| 套餐并发未配置／平台禁用 | 明确 Hive 管理员需处理；不引导用户更换本机账号来绕过 |
| 操作写入结果未知 | 显示原动作与核对结果，只重试查询；不重复写入 |

自动核对、核心重连和诊断是不同操作。正常后台读取不影响现有有效页面和按钮；过期／失败时按原有规则自动核对，并如实显示正在读取、等待重试和下一次重试时间。只在调度器确实有该时刻时显示倒计时；可恢复性与重试规则不由文案层重写。诊断仍由用户明确启动。

错误恢复后更新原区域：“连接已恢复，OpenAI 仍处于手动暂停”等结论必须依据当前平台状态。停止重试、不可恢复或需要用户处理时，不继续显示“正在自动核对”来掩盖阻塞。

所有平台原因均有单独验收落点，包括管理员禁用、设备收尾、离线、模型／授权／能力未知、套餐并发未配置、并发已满、限流、额度未知／耗尽及两平台来源／换号／授权拒绝。用户可处理、需管理员处理、等待系统条件恢复分别提供准确下一步；不只细分账号与市场两个原因。

### 6.3 必要的数据补充及兼容

连接观察从核心实际失败处携带：当前状态、失败类别及安全证据、发生时间、是否安排重试、实际重试时刻。所属运行实例／修订继续随快照传递；旧会话错误不能污染新连接。重连等待期间保留最近失败，连接确认恢复后撤销当前错误，历史留在既有日志。用户主动停止不残留“连接丢失”报警。不解析日志反推连接状态。

Hive 根据实际账号记录、平台供给配置与市场模型事实区分：账号尚未注册、平台未开放、平台供给配置受限、账号不具备可用模型、授权尚未同步等。`deviceSupply == nil` 本身不足以证明用户没有账号，必须保留可证明的具体条件。

面向用户的“尚未接入 {平台} 账号”以 Bee 当前已确认的本地选择为依据；本机已经接入但 Hive 尚未注册时显示“账号已接入，尚未完成 Hive 注册”，同时给出实际同步状态或阻塞原因。“Hive 尚未开放 {平台} 模型交易”必须由 Hive 对市场事实作出明确判断。没有细分证据时不显示这两个具体结论中的任意一个。

采用现有平台状态请求上的显式详细原因选项：新桌面的读取与暂停操作回读均请求细分原因，未请求的旧客户端继续接收原契约；不直接将新字段／新原因广播给所有旧客户端。Hive 的网页、CLI 和其他调用方继续保留现有语义。新桌面连接旧 Hive 时接受原有协议；仅在确实返回无法细分的 `not_configured` 时显示“此 Hive 尚未提供更具体的接单原因”，详情保留原码。可以另行显示已经独立确认的本地未接入事实，不能从该码反推市场状态。

该兼容方式仅覆盖此次原因细分，不建立通用协议协商系统。新原因的枚举、重复／未知原因校验、平台对应关系以及 `ready`／`paused` 不变量在 Go、Rust、TS 同步；扩展原因不能放松已存在的失败关闭校验。具体字段及请求选项在实施计划中一次定义。Hive 的 Bee 子模块引用需与协议提交对应，跨仓库联调后再判断交付完整性。

### 6.4 诊断与概览共享已确认事实（11 月 1 日补充）

诊断里的“设备身份已核对”改为实际范围：“本机绑定信息完整”；远端身份检查单独表达。`device_replaced`、`invalid_device_credential`、`source_missing` 等已知原因直接以中文／英文用户提示出现，不藏在详情中或统一写“此项结果未确认”。“检查已完成”只表示本次检查结束，不能表示恢复成功。

同一实例、绑定和网络版本的诊断新结果可以更新共享问题摘要及观测时间；不得仅凭 HTTP 可达就改变 WebSocket 连接状态、启动就绪状态或平台 ready。诊断旧绑定结果、较早结果和不同网络版本结果不进入当前主状态。检查失败保留上次确认并说明本次失败，不清成未绑定或零账号。实际设备恢复／启动重查成功后由新回读清除旧阻塞，并在概览显示剩余平台问题。

## 7. 设置、诊断、更新与应用操作

设置保留四个分类及默认网络页。代理说明改为条件式：“如需使用本机代理，请先启动代理工具。”保存结果明确区分已保存、已生效、下次启动生效；输入和错误保留在相关配置旁。代理测试说明实际测试目标，不能将官方端点可达当作 Hive 连接正常。

系统通知使用“接收系统通知”与实际系统权限并列；权限拒绝说明系统设置中的处理位置，保留应用内问题。自启使用“登录系统后启动 Bee”，说明会按此前运行选择恢复并保留手动暂停。系统偏好保存、权限授权与实际登记分别验证，不能统一报成功。系统通知本地化沿用用户语言和原有授权范围。

代理应用分别核对停止、配置生效和按原意图恢复；一项成功不掩盖另一项失败。响应未知时先读当前配置revision和运行状态，不自动重复“停止并重新启动”。通知偏好已保存不等于已获权限或已成功投递，自启期望不等于OS登记。跨四页导航和修复返回保留尚未保存的草稿，绑定变化时隔离旧草稿。

诊断继续问题优先，保留所有检查、未知状态、日志过滤和导出。将面向普通用户的“安全证据”展示名称改为“检查详情”，“核对诊断”改为“运行详情”；不改变证据脱敏或日志能力。处理按钮导航到实际存在的页面、页签、平台或区域，并聚焦目标；导航不自动发起诊断或修复。修正“去设置配对”“重新检测账号”等与当前入口不一致的旧指引。

跨页面处理问题时保留发起位置、对应平台、必要表单草稿及已提交操作的核对上下文，并提供返回入口。修复后回到原流程，继续只读核对；新的提交由用户明确触发。弹窗关闭或导航不丢失正在核对的操作，也不触发第二次提交。此能力使用现有页面和状态管理，不引入新的路由库或全局工作流服务。

诊断开始后的一次查询失败不能导致永久“进行中”。保留原报告ID，显示读取失败和真实重试状态，支持重新读取同一报告；查询恢复不再次启动诊断。未拿到开始回执时不能假造报告ID或重复开始，取消回执未知也只核对原报告。旧上下文失效、明确终态时停止查询；日志读取失败与导出结果未知保留各自恢复路径。

更新保留检查、下载、验证、确认退出安装与重启后核验。失败说明指出下载、签名验证、启动安装或安装后核验的具体环节；数字使用易读单位并在详情保留实际值。发布说明等上游内容标识来源，不能以未提供的翻译冒充本地化版本。

| 操作 | 固定含义 |
| --- | --- |
| 暂停接单 | 暂停该 Hive 账号对应平台的新任务，不终止已接请求 |
| 恢复接单 | 解除手动暂停；是否可接单仍取决于当前条件 |
| 开始贡献 | 启动本机运行、连接和同步；接单需按平台恢复 |
| 停止贡献 | 停止当前运行，可能中断任务；下次打开保持停止 |
| 关闭窗口 | 保持后台运行，可重新打开窗口 |
| 退出 Bee | 停止本 App 的运行并退出，可能中断任务；后续启动遵守既有运行意图核验 |
| 退出并安装 | 明确确认退出和安装；成功以更新流程真实回执及重启后核验为准 |

所有完成消息对应具体动作。关闭确认弹窗不撤销已提交操作；结果未知不显示成功。重要持续问题留在原区域，短暂成功反馈不抢焦点。

## 8. 国际化、布局与可访问性

**布局延续：** 以此前已批准的概览／账号布局和正式组件为对照，保留四页导航、运行摘要、独立设备摘要、平台账号列表的顺序及原有详情面板、设置页签。开始／停止贡献仍在运行摘要右侧；账号身份与状态在左、额度在右，暂停／恢复接单及账号动作仍在右侧额度区下方靠右，动作顺序沿用原设计。方案1预览中将暂停／恢复放到额度下方左侧的做法须纠正。窄窗口沿用既有响应式规则，额度和操作保持同组、操作仍靠右；不为单纯视觉变化另改位置。新提示与恢复入口放在对应问题附近，尽量不挤走已有主要操作；确因溢出、遮挡或操作不可发现而需要移动时，记录具体原因及前后对照。

正式 NativeApp 可达路径中的标题、按钮、禁用原因、空状态、异步过程、已知错误、确认弹窗、系统通知、托盘／菜单项及日期数字均纳入中英文覆盖。旧演示和已退出产品范围的资金页面不计入本次改造范围。

已知错误用稳定的原因及参数生成本地化说明，避免匹配完整英文句子。技术代码、品牌、URL、版本、账号标识及可展开的原始证据保留原文；日期和数字显式使用当前 App 语言，不取操作系统默认语言代替。切换语言后已有状态和错误说明同步更新，原始证据不变。测试分别允许必要原文，不能用“页面包含拉丁字母”判断翻译失败。

沿用现有主题与字号层级；关键状态、原因和操作说明至少 12px，正文采用现有 13px 层级，主状态保留 16px。紧凑视觉不通过 10px 关键说明实现。正文与重要说明对比度至少 4.5:1，颜色同时配合文字／图标表达。

主要区块之间使用统一 24px 留白；状态摘要与连续设备事实可保留既有细分隔结构，但设备表单／错误卡必须与运行区分开。关键操作沿用 32px 高度和清晰焦点，不使用小字号 ghost 作为唯一完成入口。图标按钮提供名称，焦点和可点区域不重叠。

860×600、常规尺寸、浅／深主题、中／英文都应能看到操作并纵向滚动；长地址、错误和账号标识自然换行，不撑出横向滚动。配对按钮有独立位置，不能被长 URL 挤出视口。弹窗与详情沿用焦点约束、Escape 和关闭返回；动态状态按需要使用 status／alert，避免轮询反复播报。尊重系统减少动态效果偏好，不增加与状态无关的动画。

**全场景布局复核（2026-11-02）：** [布局报告与截图索引](/Users/dayong/myspace/mywork/tokenhive/design-previews/2026-11-02-bee-layout-audit/README.md)及其76项映射作为T6–T10的补充输入。异常提示共用文字起点与右侧操作列，展开证据不移动操作列的顶部；长内容保持可滚动。860px原型中，账号行提前堆叠使首个暂停按钮落到首屏外，已以同尺寸对照恢复可容纳的两栏；正式实施以实际中英文内容检验断点，不机械沿用造成操作不可发现的旧断点。保留操作与额度同组靠右。原型中的占位设置、简化诊断及居中账号详情不作为正式页面完成依据；所有尚未渲染的状态须补实际内容后验收。

**可用性完成标准：** 在本地测试 Hive 和隔离桌面状态中，用真实协议制造上述故障组合，完成“诊断明确原因 → 用户确认重新绑定 → Hive 网页确认 → 新身份有效、贡献仍停止 → 修复登录来源 → 确认接入且暂停 → 开始贡献但仍暂停 → 用户恢复平台接单 → Hive 实际报告 ready”。记录每步真实回执和写入次数；没有真实官方账号条件时，将该段标为未完成并说明缺少的条件，不能用模拟候选宣称全链路通过。模拟正式组件用于布局和组合状态回归，原生壳用于权限、窗口和入口验收。当前用户设备的重新绑定、替换其他 Bee、开始贡献和恢复接单，均不能作为测试脚本的隐式副作用。

**功能完整性证据：** 将正式能力、入口和状态分支与场景、实施任务及最终证据双向对应；实施中新发现的分支必须补入矩阵。每项保留版本、环境、操作、预期／实际结果、脱敏证据及结论，模拟与真实验证分开登记。沿用既有[账号运行验收](../../desktop/account-runtime-validation.md)的受控请求要求：在专用验收环境、账号和明确请求范围内，两平台分别证明请求经 Hive、本 Bee、官方上游并实际返回，继续验证暂停后不再派发新请求、停止后不可继续接单；ready 只证明准入状态。必要真实路径待验、失败恢复无可行操作或证据缺失时，不声明整体完成；配对创建响应丢失且无token的人工处理路径也须证明可用。此条细化本轮验收，不表示已有实现通过或新增执行授权。
