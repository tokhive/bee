# Claude 官方登录修复与行内反馈

## 1. 已确认目标

修复 Bee 中点击「登录 Claude → 开始官方登录」后确认窗关闭、用户不知道是否启动或为何失败的问题。用户已确认[可点击预览](../../../../../design-previews/2026-11-03-claude-inline-login/prototype.html)的账号行内方案。本稿落实该界面和已有[账号运行规格第 6 节](2026-10-26-desktop-account-runtime-design.md#6-官方授权和授权维护)，不重新选择授权方式。

### 用户确认的界面

- 保留银白界面、账号列表及主按钮位置。登录前说明、启动、等待、核验、成功和恢复操作在 Claude 账号行下方展开。
- 登录进度由页面外的账号模型保存。切换页面或关闭账号详情不会取消登录，返回账号页可继续看到同一操作。
- 一次失败只展示一份。用户先看到具体原因和可执行的下一步，技术详情默认折叠。
- 官方登录成功只表示账号核验通过；接入仍由用户确认，接入后保持暂停，不自动开始贡献。
- 本轮不把接入、换号等其他确认对话框整体改版。共享组件修复不得损坏 OpenAI 登录和账号操作。

## 2. 已有证据与边界

| 证据 | 结论 |
| --- | --- |
| `agent/desktop_authorize.go` 在启动官方进程前读取旧来源，只允许 `source_missing` 继续 | 已成功读到但无法解析的旧记录会阻断重新登录，是当前已观察失败的原因 |
| `claudeStore.read()` 合并原始读取和解析，Claude 解析错误被包装成 `source_unavailable/read_keychain` | 必须区分读取失败与格式无效，不能把所有来源错误都忽略 |
| 当前解析信息合并了 accessToken 与 expiresAt 的校验 | 尚未证明本机具体哪个字段无效；预览中的缺少 expiresAt 是模拟例子，不能作为真实诊断 |
| 固定 Claude Code 2.1.153 的 `auth login --claudeai` 有浏览器回调及 readline 手动输入分支 | 官方登录必须有可见的官方交互；当前丢弃 stdout/stderr、stdin=/dev/null 的执行方式遗漏了该分支 |
| 原生界面另出现 `DESKTOP_STALE_RESULT actual=130 required>=131` | 时序尚未证明。不得降低修订门槛或按正常竞态吞错；先还原请求顺序与证据来源 |

不删除、重建或直接修改用户钥匙串。不读取或记录真实 token 来排查字段。登录全过程使用用户所选来源，不在 file 和 keychain 之间偷偷回退。

## 3. 技术栈

全部沿用已批准技术：Go 1.27.3 的账号来源与官方进程监督；Tauri 2.12 系列 / 现有 Rust 私有桥；React 19.2.8、TypeScript 7.0.2、Radix、Lucide 和既有 CSS；Node 24、Playwright 1.63.0、Go/Rust 测试。无新增数据库、HTTP 服务、OAuth 库或 UI 依赖。

官方客户端支持条件沿用 Codex 0.162.x/0.163.x、Claude Code 2.1.153 及以上的 2.1.x，并执行实际版本及命令能力探测。本轮必须验证用户所在 macOS 的 Claude 路径；其他平台不能以未验证的适配宣称已验收。

## 4. 来源基线与重新登录

启动前先解析并冻结所选命名空间，读取原始来源并取得仅限内存的修订摘要；摘要不进入前端或普通日志。原始数据及时清零。

- 来源不存在：允许官方登录创建记录。
- 来源可读但格式无效：允许官方登录修复，保留原始来源基线，直到官方客户端自己更新。
- 权限拒绝、非普通文件、不支持的来源或其他读取失败：停止启动，返回该次失败及对应恢复操作。
- 格式诊断分别检查结构、accessToken、expiresAt；仅返回字段名、校验条件及非敏感事实，不返回字段内容。

官方进程结束后在同一来源重新读取并解析：来源命名空间不符、仍无有效记录、原始内容未改变或核验中又发生变化都不能报告新登录成功。继续执行已有 token 修订、到期、套餐、scope、官方身份和最终读回校验。原始内容变化不能替代这些校验。

## 5. 官方交互与进程生命周期

沿用已批准的官方客户端方式：用户在官方页面及原生终端完成登录；Bee 不提供密码、验证码或 token 输入框。

macOS Terminal 仅承接本次官方命令的交互。Go 保留本次 owned supervisor、独立退出状态和取消归属；不能用 Terminal 的 busy、窗口关闭或命令已发送判断登录成功。不能结束已有 Claude/Terminal 进程或无关窗口。

采用原生终端内的固定 Bee 交互转接入口，连接本次私有端点；官方命令、参数和环境仍由 Go 固定白名单构造。macOS 使用 `open -a Terminal` 打开本次 0700 的 `.command` 启动脚本，脚本只含可信 Bee 路径与本次端点，不使用 AppleEvents，不等待整个 Terminal 退出。私有端点的目录 0700、访问权限 0600，每次操作独立，结束后关闭并清理。官方原文只显示于该原生终端，不进入 React、私有 JSON 协议、普通日志或磁盘文件；不把用户提供的目录文本拼入 Shell。

已对固定 Claude Code 2.1.153 的 authLogin 和手动回调实现静态检查：使用 readline 的 line 输入，不要求 isTTY 或 raw 模式。因此本次使用标准库管道转接，不新增 PTY 依赖。官方输入、合并输出与 supervisor 的退出码/生命周期管道分开，不能在官方原文中识别控制标记。正常退出、输入、Ctrl-C、终端关闭、取消、超时、应用退出及背压都须用合成程序和原生环境验证；任何不满足进程归属或官方交互的适配不得交付。

取消只在本次进程确认回收后成为终态。取消不能撤销官方客户端已保存的登录，因此提供「检查当前登录」，不自动接入。

## 6. 状态与协议

现有 `operation.state` 继续负责 pending/running/succeeded/failed/cancelled；authorize 操作增加可选的严格枚举 `phase`，其他操作不携带它：

| 状态 | 证据与界面 |
| --- | --- |
| 本地确认草稿 | 显示将调用官方客户端、可能改变客户端账号；继续登录 / 取消 |
| pending/running + starting | 来源、版本和能力检查，准备原生终端及官方进程；正在启动 |
| running + waiting_official | owned 官方进程已启动；请在官方页面完成登录，取消登录 |
| running + verifying | 官方进程已成功退出，正在核验来源和身份；正在确认登录结果 |
| succeeded | 全部已有核验通过；显示实际候选与套餐，保留既有接入/换号入口 |
| failed/cancelled | 显示真实失败环节，提供下表的有效恢复操作 |
| 结果未确认 | 保持原 operation ID，只查询原操作；不能再次提交登录 |

Go、Rust、TypeScript 的快照和授权回包同时接受该字段，拒绝未知枚举及非 authorize 的 phase。旧回包无 phase 时只显示有证据的粗粒度进度，不推测官方页面是否已打开。每次 phase 改变同时推进账号和 operation 修订。

确认草稿使用现有账号、来源和运行上下文戳；确认前条件变化时明确告知本次未提交，要求重新确认。进度不抢焦点；确认取消后焦点回到登录按钮；状态区使用语义化 status/alert，支持键盘、英文和减少动画。

## 7. 失败与恢复

| 本次已证实原因 | 直接操作 |
| --- | --- |
| 未安装或版本/命令能力不支持 | 官方安装或更新说明；安装完成后由用户重新登录 |
| 钥匙串/文件拒绝访问 | 说明失败来源与访问条件；允许访问后「重新读取」 |
| 现有记录格式无效 | 具体字段校验信息；「重新登录 Claude」可以真正启动 |
| 登录后身份核验网络失败 | 保留已保存登录，不声称账号已确认；「重新核验」调用现有 official 检测，不重复登录 |
| 取消或超时 | 说明客户端可能已保存登录；「检查当前登录」或由用户重新登录 |
| namespace/source revision 改变 | 保持未确认，重新读取并要求确认实际候选，不使用旧结果接入 |
| 提交或取消回包丢失 | 查询原 operation ID；在结果未知时禁止新提交和重复取消副作用 |
| 修订下降或证据完整性异常 | 保持 fail-closed，保留本次实际检查与 actual/required；不放宽门槛 |

错误内容优先使用本次最具体的底层事实。不能把「token 或到期字段无效」翻译为「已过期」，不能把 earlier runtime 的修订伪装成本次 account_snapshot 回包。相同失败在行内、详情和全局提示中不重复堆叠；详情可以提供定位回账号行的入口。

## 8. 验收

1. 合成的旧记录损坏/缺失/有效三种基线分别覆盖；损坏允许登录，权限错误仍阻止，未改变及核验中来源替换仍失败。
2. 官方合成程序实际通过受控输入输出完成问答，非零退出、Ctrl-C、关终端、取消、超时及退出只回收 owned group；秘密标记不进入桥、日志或临时文件。
3. 三层协议覆盖合法/非法 phase、操作身份与修订，旧快照和迟到结果不能覆盖新操作。
4. 浏览器覆盖确认→等待→核验→成功、网络失败→重新核验、无效记录→重新登录、取消→检查当前登录，以及切页返回、确认上下文变化和结果未知。
5. 原生 macOS 包验证行内布局、实际客户端可启动及终端承接；真实官方账号授权须由用户在官方页面完成。没有用户完成该步骤前，报告该环节未验收，不用模拟成功替代。
6. OpenAI、接入/换号/暂停行为保持既有约束。通过受影响 Go/Rust/TS 回归和前端构建；记录证据、更新账号使用及验收文档。

## 9. 本轮范围控制

不重建账号系统、贡献状态机或全局设计系统，不自动安装客户端，不新增 Bee OAuth，不操作 Hive 源码、数据库或真实贡献流量。130/131 问题按实际请求时间线定位；若涉及额外产品决策，再单独说明具体变更，不能为了让登录按钮可点而绕过保护。
