# Claude 登录小修复设计

问题：点击“开始官方登录”后弹窗关闭，用户无法清楚知道进度、失败原因和下一步。

采用用户已认可的账号行内预览：确认、等待、核验结果及恢复动作显示在 Claude 行下方；错误详情默认折叠。切换页面保留状态。成功后仍由用户主动接入，不自动开始贡献。

沿用现有 React、TypeScript、Tauri 与 Go，以及已有账号操作和检测接口，不新增依赖或协议。核验失败后的重新核验仅调用检测，不重复发起官方登录；结果未知时只查询原操作。保持现有来源、身份、版本和运行状态保护。

后端将成功读取但格式无效的旧凭据归类为 invalid_credentials，允许官方客户端替换；权限或其他读取失败仍阻止继续。完成登录后仍须通过现有核验。

用户指出减少任务不等于删掉必要功能，并要求接通授权码输入。本次在 macOS 使用系统 Terminal 承接官方 Claude Code 输入输出，不在 Bee 表单接收授权码，不改 OAuth 或桌面协议。Go 继续拥有和回收原官方进程，终端仅转接本次私有会话；关闭终端、取消和超时均终止该进程。完成后沿用原来源和身份核验。

沿用 Go 标准库 Unix socket、现有 x/sys/unix 与 macOS Terminal，不新增依赖。连接限私有临时目录、一次性随机会话认证，官方输出只流向终端，不写入 Bee 日志、协议或磁盘。测试用合成授权码验证输入、输出、关闭、取消与清理。原生人工输入与真实账号授权分别记录证据，不用合成测试代替真实授权成功。

此次不新增阶段协议，也不改独立的 revision 保护。终端适配只交付 macOS，其他平台沿用原执行方式，不宣称已有同等交互能力。
