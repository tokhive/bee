# Bee 桌面：设备在线与贡献控制分离

日期：2026-11-03。状态：方案 A 已实现；自动测试和 macOS 原生无账号在线验证完成。具体证据及未实测范围见[验证报告](../reports/2026-11-03-desktop-device-connection-verification.md)。

## 1. 已确认的目标

App 启动且设备已绑定，就与 Hive 保持 WebSocket 连接；是否贡献另行控制。

- Bee 管理子进程随 App 启动；进程可通信、设备在线、贡献已启动、平台可接单分别表达。
- 没有接入 AI 账号，也能连接 Hive 并显示设备在线。
- 自动连接不自动接入账号、不解除平台暂停，也不新增开始贡献的授权。
- 用户停止贡献后，App 仍运行，设备应继续保持在线。
- 未绑定时完成绑定，或设备重新绑定成功后，自动使用已核验的新身份连接。

本稿取代 2026-10-26 账号运行设计中“只有开始贡献才连接”和“停止贡献后保持断线”的约束。账号选择、平台暂停、官方登录、退出与更新的既有保护继续适用。

## 2. 源码事实

| 已核对的实现 | 对本次变更的约束 |
| --- | --- |
| `agent/client.go`：无 egress 使用 `/api/bee/connect`；有 egress 使用 `/api/bee/agent` | 已有只维持在线和承载隧道两种连接，不必为上线能力增加 Hive 接口 |
| Hive `hive/internal/service/connection.go`：同一设备只登记一个 live connection | 不能同时保留在线连接并另开贡献连接，必须统一拥有和串行交接 |
| Hive `hive/internal/service/bee_connection.go`：在线依据 live connection | 在线不要求账号选择或授权信封；HTTPS 身份核对不等于在线 |
| Hive `hive/internal/service/relay.go`：授权信封挂在连接及 lease 上 | 关闭旧贡献连接可使旧连接的授权退出可用集合；当前没有单独撤销整个连接贡献权限的接口 |
| `agent/desktop_runtime.go`：贡献 run 同时拥有 WebSocket、同步任务和停止流程 | 需要增加独立于贡献 run 的设备连接归属，不能只在启动时调用现有 Start |
| `agent/desktop_account_connection.go`：停止贡献时账号确认会临时建立隧道 | 自动在线连接必须与这条路径协调，不能导致自己与自己发生 409 |
| `desktop/src/features/lifecycle/NativeRuntimeControls.tsx`：local=stopped 时覆盖连接文案 | 前端必须按真实连接状态显示，允许“贡献未启动 / Hive 已连接” |

Hive 当前作为只读协议依据；工作区为 Bee 的 `.worktrees/bee-desktop-p0`，保留其现有未提交改动。

## 4. 两种实现方案

### A. 复用已有在线连接与贡献连接，串行切换（推荐）

未贡献时保持 `/api/bee/connect`；开始贡献时关闭并回收该连接，再建立 `/api/bee/agent`；停止贡献并回收旧隧道后，恢复 `/api/bee/connect`。

完整覆盖启动即在线、无账号在线、停止后继续在线和独立贡献控制。沿用现有 Hive 协议，不需要发布 Hive 更新；账号确认继续使用已验证的临时隧道路径。

代价：开始/停止贡献、停止状态下需要租约的账号确认会短暂重连。交接期间真实显示“正在连接 Hive”，Hive 也可能短暂观察到离线。不会用 UI 缓存伪装为连续在线。

### B. 始终保留同一条隧道连接，另设贡献准入

绑定后保持 `/api/bee/agent`，开始/停止贡献只改变贡献任务和准入状态，不主动断开 WebSocket。

完整覆盖同一条连接持续存在的更强要求，但必须同时解决 Hive 侧授权撤回与调度准入、本机正在执行的流取消、账号操作与空闲状态的区别。单纯停止本地同步或清空本地目标名单不足以撤销 Hive 已持有的授权；只暂停平台也不能把独立的贡献状态等同于平台暂停。

可靠的实现需要扩展 Hive/Bee 的会话内贡献控制契约：新桌面连接默认不贡献；变更绑定当前 lease 和单调序号；Hive 调度再次校验当前贡献状态；旧请求不得重开已停止的贡献；旧客户端保留既有行为。需增加兼容协商及 Hive 联调、发布步骤，范围明显大于 A。

比较：A 的规则、模块和部署成本较少，能够在现有 Hive 上安全实现启动后保持在线；B 的优势是启停不发生主动重连。不存在仅改前端或直接自动调用 runtime_start 的完整方案。

**用户已确认 A：接受短暂重连，复用现有协议。B 不进入本次实施。**

## 5. 方案 A 的连接归属

Go 管理子进程统一协调在线、贡献及临时账号连接。同一身份同一时刻最多拥有一个连接循环；旧循环退出前不启动下一循环。

连接与贡献保留独立状态：

| 场景 | 贡献状态 | 连接状态/用途 |
| --- | --- | --- |
| 未绑定 | 未启动 | 未连接；不持续尝试无凭证连接 |
| 已绑定、无账号 | 未启动 | 自动连接并保持在线 |
| 已绑定、有账号、尚未开始 | 未启动 | 保持在线；不自动同步贡献授权 |
| 用户开始贡献 | 启动中→运行中 | 在线连接交接给贡献隧道；保留既有账号核验及暂停规则 |
| 用户停止贡献 | 停止中→未启动 | 旧隧道及任务退出后恢复在线连接 |
| 停止时确认接入或换号 | 未启动 | 串行临时隧道；动作完成并回收后恢复在线连接 |
| 网络中断 | 保留既有贡献意图 | 按现有退避重连当前连接用途 |
| 明确退出或安装更新 | 回收中→停止 | 禁止自动再连；回收所有本 App 拥有的连接及任务 |

设备身份、连接代次和网络配置修订共同约束回调。旧连接的 connected、错误、重试和结束事件不得覆盖新连接或新设备。

首次连接的 409 继续表示归属未确认，不自动抢占。刚由本实例关闭的同身份连接可复用“已拥有会话”的有限冲突重试规则，等待 Hive 注销旧连接；凭据相同不构成拥有证据，持续冲突仍停下并报告。

## 6. 自动连接的触发与抑制

- 原生启动完成设备身份和生效网络配置核对后，授权 Go 连接协调器开始工作，避免启动配置未核验时抢先连接。沿用既有环境代理和各类网络请求的路径规则，不将专用出口代理误用于所有 Hive 请求。
- 未绑定的 App 保持可配对；绑定成功、身份核验通过且对应网络配置就绪后，自动连接，不要求用户再次点击开始贡献或重新核对。
- 自动在线不写入“贡献正在运行”的恢复意图，不占用贡献 run 的活动会话标记。
- 账号状态损坏或未决账号动作不能触发贡献恢复；单纯在线不借机修复或覆盖这些文件。身份或网络本身不可信时不连接。
- 用户开始贡献仍要求已有账号选择；现有干净会话及已保存运行意图的恢复规则继续适用。自动在线本身不生成恢复贡献的同意。
- 明确退出、更新、设备恢复和网络切换均须先设置抑制标记，再取消旧循环；不能由循环的 finally 路径自行拉起新连接。
- 网络配置切换后，仅用核验过的新修订重连；应用失败保留具体原因，不宣称新路径已生效。

## 7. 设备替换与账号动作

重新绑定进入既有恢复流程前，暂停在线自动重连并回收旧连接；继续保留既有账号未决操作和贡献 worker 的安全屏障。

恢复完成并保存、核验新身份后解除连接抑制，自动连接新设备。不得搬用旧设备的账号选择、连接代次或贡献恢复意图。取消恢复时只有仍可信的旧身份才能重新连接。

Hive 外部 replace 导致连接关闭后，旧凭证被拒绝则停止重连并显示设备身份问题；不自动创建配对、不反复重新绑定。

停止贡献时确认账号使用临时隧道，仍遵守暂停读回、同一未决操作核对和会话清理证明。在线协调器只交接传输，不重放账号写入。临时隧道结束或失败后，只有身份仍有效且没有退出/恢复抑制时才能恢复在线连接。

## 8. 停止与错误语义

停止贡献继续可能中断正在处理的请求，不新增等待 Hive 任务结算的能力。成功条件仍包括停止意图按既有规则保存、贡献 worker 退出和旧隧道回收；连接协调器可以独立处于连接中或重连中。

“贡献已停止，但 Hive 正在重连”是有效结果。重新连接失败不能伪造贡献停止失败；停止意图保存失败也不能伪造下次启动可安全恢复。

退出/更新与用户停止使用不同边界：前者回收所有连接并禁止再连，后者允许恢复在线连接。停止/退出失败的细节保留本次事实，不用通用错误覆盖具体原因。

## 9. 界面与协议

- 保留“贡献未启动／贡献已启动／贡献状态待确认”。
- “Hive 已连接”来自真实 WebSocket 事件，不再由贡献 local 状态覆盖。
- 连接错误、下一次重连时间、身份拒绝和连接被占用，在未贡献时也能查看。
- 未绑定与已绑定但尚未连接分别说明；说明文字表达“设备绑定后自动连接；开始贡献和平台恢复接单分别控制”。
- “开始贡献”仍要求账号前置条件；没有账号只限制贡献，不限制自动在线。
- 保持 Go、Rust、TS 的严格快照契约；诊断与页面消费同一事实，不从日志解析成功状态。
- Hive 在线字段继续使用现有连接注册表；推荐方案不修改 Hive 页面、接口或数据库。

## 10. 验收

1. 已绑定、没有账号，启动 App 后真实 WebSocket 已连接；Hive 显示在线；贡献保持未启动，未发出账号注册、续期或恢复接单请求。
2. 首次配对及重新绑定完成后自动连接；旧身份回调不能覆盖新身份。
3. 开始贡献时连接串行交接，无自撞 409、无双重连接；账号同步与暂停保护继续有效。
4. 停止贡献时旧隧道和 worker 退出，旧 lease 授权失效，随后恢复在线；重新打开仍遵守已保存的停止意图。
5. 停止状态下接入/换号可完成，结束后恢复在线；响应丢失只核对原操作，不重复写入。
6. 在线维持和贡献两种用途均覆盖断网重连、首次外部占用、受限的本机交接冲突、401/403、外部 replace。
7. 用户停止、退出、更新、代理切换和设备替换与连接建立并发时，不泄漏 worker、不错误再连、不覆盖新代次。
8. 前端覆盖“贡献未启动 / Hive 已连接”、未贡献时连接失败、重连、设备拒绝和占用；英文同步，最小窗口可用。

验证使用真实本地 WebSocket/HTTP 测试端点和竞态检查，结合既有 Rust/TS 契约与 Playwright 测试；原生 App 核验无账号自动在线。模拟测试不得冒充线上 Hive 运行证明。

## 11. 实施边界

按已确认的方案 A 实施。改动集中在 Bee 连接协调、贡献/账号/恢复的生命周期交接、原生启动与退出桥、页面状态及相关测试。不会自动提交或发布，不会为了验证而接入用户账号或开始真实贡献。
