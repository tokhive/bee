# S2 设置页三版设计预览

问题：相同的现有设置功能，单页、分类页签、总览与详情面板，哪种组织方式更清楚？

这是独立的临时 HTML/CSS/JavaScript 预览。沿用诊断页预览的公共壳与组件样式，复用正式 Bee 颜色变量；不增加依赖，不修改正式 UI，不接 Bridge，不读取用户数据，不申请系统权限、不操作运行进程。所有保存、测试、系统状态都是内存示例，刷新后复原。

从 S2 工作树根目录运行已有预览服务：

```sh
python3 -m http.server 1432 --bind 127.0.0.1
```

打开 `/docs/ui/2026-10-28-bee-s2-settings-prototype.html?variant=B`。

## 三种组织方式

- A 单页分组：通用、通知与启动、网络、关于依次排列，页首提供分组定位。
- B 分类页签：将简单偏好和复杂网络表单分开；默认展示网络页签。推荐此版，信息完整且主要只需一个滚动区。
- C 总览与详情：先看四组设置的摘要，点击配置按钮打开右侧详情面板；提供窄窗口适配。

三版都包含语言、主题、通知偏好与系统权限、自启期望与实际登记、保存与生效代理、明确的连通性测试、网络路径、重启应用确认、Hive 与版本信息。关于页不添加尚未接入的 S3 更新功能。

## 视觉与布局基线

保留已确认的银白精工 + shadcn/ui 风格，不再提出主题选型。沿用白色面板 #ffffff、银灰画布 #f7f8fa、文字 #242830、次要文字 #717680、细边框 #e8eaee、琥珀点缀 #ae7615。系统字体；页面标题 23px，分组标题 13px，表单与操作 12px，说明 11px；主按钮为高对比实心，次按钮描边，可能中断任务的动作保留危险语义。正文左对齐，178px 侧栏、57px 顶栏、32px 按钮与已确认诊断页保持一致。

本轮只比较组织方式；不增加关闭窗口行为开关、账号权限、Hive 用户登录、系统代理修改或退出策略。

## 演示入口与状态

地址参数：`variant=A|B|C`、`theme=light|dark`、`section=general|network|system|about`、`scene=pending|blocked|unpaired`、`detail=network`（C 的网络详情）。底部或方向键切换方案，表单、页签和弹窗内不拦截方向键。

- 默认：已保存 `http://127.0.0.1:7890`，运行仍使用 `http://127.0.0.1:7891`，显示下次启动生效。保存不自动重启；点击应用按钮才显示中断任务确认。
- 通知未允许：应用期望与系统权限分开显示。未申请时给明确入口；已拒绝时只给系统设置指引，不反复请求权限。
- 未配对：允许按 Hive 保存代理草稿，保留通知与普通偏好。未确认的运行路径按未知显示。
- 连通性测试只显示三个固定检查的合成结果，不验证账号授权或额度，不开始贡献。
- 中文／English 是偏好选项；本预览界面文案保持中文。明暗主题均可实际预览；跟随系统按浏览器系统偏好呈现。

正式功能依据：`docs/superpowers/specs/2026-10-26-desktop-diagnostics-experience-design.md` 第 6–8 节，以及 `desktop/src/features/settings/NativeSettingsPage.tsx`。用户选定本页布局后再同步完整中文 UI 规格与实施计划，原型模拟逻辑不进入正式 App。
